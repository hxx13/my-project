规格选择 — 桌面端 vs 移动端 差异化方案

一套组件，两种呈现：移动端 Bottom Sheet，桌面端居中 Dialog。根据视口宽度自动切换。

一、当前问题

🔴 Bottom Sheet 在桌面端的问题

  • 大屏幕上从底部滑出一个小面板 → 视觉重心失衡
  • 鼠标操作习惯是"点击 → 中间出现弹窗"，不是"点击 → 底部冒出"
  • 管理后台（快捷业务/scan）是重度操作场景，底部抽屉打断工作流
  • 桌面端用户的视线在屏幕中部，移到屏幕底部再移回来 → 不必要的眼动

🟢 业界桌面端怎么做

  • Figma/Notion/Linear：属性面板用右侧抽屉或居中 Dialog
  • 飞书/钉钉管理后台：表单类操作用居中 Modal
  • ERP/WMS 系统：物料规格选择用居中弹窗 + 确认按钮
  • 结论：桌面端 = 居中 Dialog，移动端 = Bottom Sheet

三、技术实现：一个 SpecSheet，两种渲染

视口 渲染模式 实现 关键差异
≥ 640px 居中 Dialog fixed inset-0 flex items-center justify-center
内容区 max-w-md w-full rounded-2xl		 取消+确认双按钮 / 右上角 X 关闭 / 键盘 Escape 关闭 / overlay 半透明遮罩
< 640px Bottom Sheet fixed inset-0 flex flex-col justify-end
内容区 rounded-t-2xl max-h-[85vh]		 拖拽手柄 / 底部安全区 / 单"完成"按钮 / 下滑关闭

💡 响应式断点依据

Tailwind sm: = 640px，恰好是平板竖屏/大手机横屏的分界线。
sm:flex sm:items-center sm:justify-center → Dialog 模式
默认（无前缀）→ Bottom Sheet 模式

四、与当前 SpecSheet 的改动量

改动内容
外层容器flex flex-col justify-end → sm:flex sm:items-center sm:justify-center（桌面居中，移动端底部）
内容面板移动端 rounded-t-2xl，桌面端 sm:rounded-2xl sm:max-w-md sm:max-h-[85vh]
拖拽手柄sm:hidden — 只在移动端显示
底部按钮区桌面端加"取消"按钮（与"确认"并列），移动端保持单"完成"按钮
动画桌面端 sm:animate-in sm:fade-in-0 sm:zoom-in-95，移动端 slide-in-from-bottom
