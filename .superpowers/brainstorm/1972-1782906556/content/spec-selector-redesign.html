规格选择交互 — 从「锚点弹窗」到「Bottom Sheet」

当前方案的问题不在 bug，在架构选型。锚点定位类弹窗天然脆弱——换一条路。

一、为什么锚点弹窗是死胡同

🔴 结构性缺陷（修不完）

  • Portal 脱离文档流 → 丢失滚动容器的 overflow 上下文
  • 手动算坐标 → 视口检测/ResizeObserver/scroll 监听三层补丁
  • 每增加一个使用场景（scan面板、H5、学生页）→ 多一套 variant 分支
  • 页面滚动/容器内滚动 → 弹窗不跟随，需要额外 scroll 监听
  • 卡片在 Grid 中 → overflow:visible 才能让弹窗不被裁切
  • 移动端 H5 → 弹出方向/安全区/键盘遮挡 全部失效

🟢 目标方案的特征

  • 零锚点计算 — 不需要知道按钮在哪里
  • 全端统一 — 桌面/平板/手机/H5 同一套代码
  • 视口固定 — 始终在屏幕底部，不受滚动/overflow 影响
  • 行业标准 — 京东/淘宝/美团/Apple Store 全部用这个

三、业界标准参考 — 全用 Bottom Sheet

产品 场景 交互模式
京东/淘宝 商品 SKU 选择 底部弹出面板：商品图+价格+已选规格+尺寸/颜色 chip + 数量步进器 + "加入购物车"按钮。从不做锚点弹窗。
美团/饿了么 菜品规格（辣度/大小/配料） 底部抽屉：菜品名+图片+规格选项 radio/chip + 数量 + 加入购物车。全端统一 Bottom Sheet。
Apple Store iPhone 选购（颜色/容量） 点击"选择"→ 从底部滑出面板，选颜色/容量/storage。桌面端同样底部弹出（非锚点）。
Shopify 商品 variants 默认用 variant picker block（内嵌在商品页），弹窗场景用 drawer/bottom sheet。
瑞幸/星巴克小程序 饮品规格（杯型/温度/甜度） 点击"规格"→ 底部半屏弹出，选完后点"完成"。H5 和小程序完全一致。

四、目标组件设计：<SpecSheet>

触发方式

  • 卡片中保留"选择规格"按钮（样式不变）
  • 点击 → setOpen(true)
  • 按钮上仍显示已选数量 badge

Sheet 布局

  • 顶部：拖拽手柄 + "选择规格" 标题 + 关闭按钮
  • 中上：物品缩略图 + 名称 + 副标题（确认在选哪件东西）
  • 中：规格维度 chips（颜色/尺寸等）
  • 中下：已选组合 + 步进器（每行一个 combo）
  • 底部：总数量 + "完成" 按钮

技术实现

  • 渲染方式：固定定位 position: fixed; bottom: 0; left: 0; right: 0
  • 零锚点计算：不需要知道按钮位置
  • 动画：translateY(100%) → translateY(0)，200ms ease-out
  • 遮罩：半透明黑色 overlay，click to dismiss
  • 安全区：padding-bottom: env(safe-area-inset-bottom)
  • 一个组件：替代 student/scanner/mobile 三套 variant 分支

与现有代码的关系

  • 新组件：frontend/src/components/material/SpecSheet.tsx
  • 废弃：MaterialSpecPickerSheet.tsx 中的 Popover 定位逻辑（保留工具函数）
  • 三个页面的"选择规格"按钮改为 onClick={() => setSpecSheetOpen(true)}
  • 数据流（cart/specSchema/selections）完全不变

五、全端统一 — 一个组件覆盖所有场景

使用场景 当前 目标 说明
/student/material Popover variant="student" SpecSheet 桌面学生中心，卡片 Grid 中触发
scan 快捷业务面板 Popover variant="scanner" SpecSheet 后台管理面板，可能有 overflow 容器
/m/home H5 Popover variant="mobile" SpecSheet 移动端 H5，底部 Sheet 天然符合手机交互习惯
