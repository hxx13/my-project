设计方案 · 数据库 & 后端 API

第一部分 — 确认后再进入前端设计

1. 数据库变更

personnel 表新增字段
字段 类型 说明
personal_pin VARCHAR(255) bcrypt 哈希，NULL 表示未设置
pin_updated_at DATETIME PIN 最后修改时间，可空

2. 后端 API 清单

POST /api/auth/special-channel/login

特殊通道登录 — 复用 loginWeb 返回格式

Request{ userId: string, pin: string }
Response{ token, role, userInfo } (同 loginWeb)
校验bcrypt.compare(pin, personal_pin) → 通过则签发 JWT
失败PIN 未设置 → 400 "请先设置个人密码"；PIN 错误 → 401
POST /api/auth/special-channel/set-pin

首次设置 PIN（仅在 personal_pin IS NULL 时允许）

Request{ userId: string, pin: string }
Response{ token, role, userInfo } — 设置成功后直接签发 token 进入
POST /api/auth/special-channel/check-pin-status

前端弹数字键盘前先查询：该 userid 是否已设置 PIN？决定展示设置 or 验证界面

RequestGET ?userId=xxx
Response{ hasPin: boolean }
POST /api/admin/personnel/batch-pre-create

批量预写入：扫描 personnel 表中所有 userid，为尚未有学生中心账号的创建预置数据

触发管理员手动触发（或定时任务）
Response{ created: number, skipped: number, total: number }
