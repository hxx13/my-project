三、扩展冗余策略总览

每个设计层面的扩展预留
层次 扩展点 机制
侧边栏 新增导航项（如"我的预约""课题组动态"） 扁平列表直接追加；超过 8 项时自然演进为分组折叠
仪表盘 新增统计卡片、快捷操作、房间卡片 卡片区用 flex-wrap 自动换行；快捷操作为可配置列表
出入记录 新增 Tab（异常记录、访客记录等） Tab 由配置数组驱动，新增只需加一项配置
房间管理 新增筛选维度、房间详情面板 卡片组件接受泛型 metadata，筛选器由配置生成
数据统计 新增统计指标、图表类型 指标面板可插拔注册，图表容器统一渲染
通知公告 新增来源类型（课题组、系统告警） type 字段 enum 可扩展，筛选 pills 由类型列表自动生成
帮助反馈 新增 FAQ 分类、留言类型 FAQ 分组由后端配置驱动；留言类型 enum 可扩展
API 端点 新增数据域 独立端点策略，新域 = 新端点，不影响现有契约

四、关键设计原则（回顾）

🔒 课题组不可见

组仅是代码级数据标签，用于后端过滤/权限。UI 中只在个人身份卡轻量提及，不设组横幅、组动态、组管理。

👤 纯个人视角

所有数据围绕"我"展开：我的记录、我的房间、我的统计、我的通知。不展示他人数据。

📊 事实优于评价

不制造虚的评分/等级/标签。展示可验证的统计数据，让学生自己得出结论。

🔌 独立端点

每个数据域独立 API 端点，TanStack Query 独立缓存。新功能 = 新端点，不破坏旧契约。
