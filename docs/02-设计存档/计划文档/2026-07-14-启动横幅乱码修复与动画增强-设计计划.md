## 背景

当前 Windows 终端（cmd / PowerShell）默认编码为 GBK，而项目全栈使用 UTF-8，导致控制台中文乱码。同时现有的赛博朋克启动动画虽架构完备（9 类协同），但在标题表现力、旋转器流畅度、进度条精细度上相比 Linux CLI 生态仍有差距。

## 目标

1. **乱码根除**：Windows / Linux 双平台终端中文正常显示
2. **大字标题**：内置极简 FIGlet 渲染器，零外部依赖，零许可证风险
3. **动画升级**：Spinner 多套方案（默认不变）+ ProgressBar 8 级平滑填充 + 分段着色

## 第 1 层：乱码修复

### 根因

`CyberColor` 终端检测读取 `sun.stdout.encoding` 判断是否 UTF-8。Windows CMD/PowerShell 默认 GBK → 检测为 false → box-drawing 回退 ASCII。同时日志字节本身是 UTF-8，GBK 终端误解字节序列 → 乱码。

### 方案

**JVM 参数**（Java 17+ 标准属性优先，HotSpot 私有属性兜底）：

```
-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8
```

`stdout.encoding` 是 Java 17+ 标准属性（JEP 400），适用于 HotSpot / OpenJ9 / GraalVM / Azul Zing 全系列。`sun.stdout.encoding` 作为 HotSpot 兜底。

**同时修改 `CyberColor` 终端检测**（对应 C4）：同时检查 `stdout.encoding`（Java 17 标准）和 `sun.stdout.encoding`（HotSpot），并日志输出实际检测到的编码值，便于运维验证。

### 启动脚本

新建 `startup.sh`（Linux/macOS）和 `startup.bat`（Windows），包含：

| 内容 | startup.sh | startup.bat |
|------|-----------|-------------|
| 编码 | `-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8` | 同 |
| 内存 | `-Xms256m -Xmx2g` | 同 |
| 工作目录 | `cd $(dirname $0)/..` | `cd /d %~dp0..` |
| 类路径 | `target/demo-*.jar` 或 `target/classes` | 同 |
| 编码声明 | 无需（JVM 参数覆盖） | `chcp 65001` 前置（cmd.exe OEM 代码页） |
| Docker 说明 | 注释注明 K8s/Docker 环境直接 `java -jar` 即可 | 同 |

### 验收

Windows Terminal + `startup.bat` 启动后不再出现乱码，中文正常渲染。

## 第 2 层：动画增强

### 2.1 内置 FIGlet 渲染器（替代 JFiglet 外部依赖）

**决策**：不引入 JFiglet。原因：
- JFiglet 最新版 0.0.9（2016 年），2.3.1 不存在（审计 C2）
- JFiglet 许可证为 GPL-2.0，商业/闭源项目存在 Copyleft 风险（审计 C5）
- 内置实现的复杂度可控（~200 行）

#### 新增文件：`com.example.demo.common.text.FigletRenderer`

包路径独立于 `logging.banner` ——文本渲染是通用能力，不属于日志层面（审计 H4）。

**实现策略**：
1. 将 FIGlet "big" 字体文件 `big.flf` 置于 `src/main/resources/fonts/big.flf`
2. FIGlet .flf 格式是公开标准，字体分发不受 GPL 约束
3. 解析 .flf 头（hardblank、height、baseline、comment lines），按行渲染字符字模
4. 横向拼接各字符的对应行，输出 `List<String>`（每行一个字符串）

```java
public final class FigletRenderer {
    /** 渲染文本为多行字符串列表（供调用方决定如何画框） */
    public static List<String> render(String text);
    
    /** 返回渲染后最大行宽（供外框宽度计算） */
    public static int widthOf(String text);
}
```

**关键实现细节**（审计 H1）：
- 字体从 classpath 加载：`FigletRenderer.class.getResourceAsStream("/fonts/big.flf")`
- Spring Boot fat JAR 嵌套资源兼容：`ClassLoader.getSystemResourceAsStream` 而非文件系统路径
- 字体加载失败 → `log.warn` + 回退到纯文本标题（审计 M1）
- 一次加载后缓存为 `static final`，避免重复解析

**修改：`StartupPhaseRunner.java`**（唯一的活跃渲染点）

`run()` 方法末尾，替换：

```java
// 旧 (第 147 行)
System.out.println(PhaseFrame.banner("🧬 TWIN SYSTEM v" + appVersion, "Neuro-Synced Infrastructure"));

// 新
List<String> figletLines = FigletRenderer.render("TWIN");
int maxWidth = Math.max(FigletRenderer.widthOf("TWIN"), 30);
String slogan = "v" + appVersion + " · Neuro-Synced Infrastructure";
// 包裹在 PhaseFrame 风格的 ╔═╗ 外框内
System.out.println(renderFigletBox(figletLines, slogan, maxWidth));
```

**emoji 保留**：🧬 保留在 `StartupPhaseRunner` 中（审计 M4），仅 `PhaseFrame.banner()` 的文本标题替换为 FIGlet 渲染。

#### 死代码清理

`StartupBanner.java` 经确认零外部调用方（审计 C3）。本计划不动它——作为独立清理 PR 处理。唯一的活跃横幅渲染路径是 `StartupPhaseRunner.run()`。

### 2.2 Spinner 升级 + 并发修复

#### 修改：`Spinner.java`

**并发修复（审计 C7）**：`volatile int index` 在 `tick()` 中的读取-修改-写入操作不是原子的。`LoadingSpinner.GLOBAL_SPINNER` 被所有实例共享 → 并发调用时帧会跳过/重复。

```java
// 旧
private volatile int index = 0;
public String tick() {
    String frame = frames[index];
    index = (index + 1) % frames.length;
    return frame;
}

// 新
private final AtomicInteger index = new AtomicInteger(0);
public String tick() {
    return frames[index.getAndUpdate(i -> (i + 1) % frames.length)];
}
```

**帧方案枚举**：

```java
public enum SpinnerStyle {
    CLASSIC(new String[]{"⠋","⠙","⠹","⠸","⠼","⠴","⠦","⠧","⠇","⠏"}),  // 现有默认，保持不变
    DOTS  (new String[]{"⣾","⣽","⣻","⢿","⡿","⣟","⣯","⣷"}),           // Claude Code 风格
    ARC   (new String[]{"◜","◝","◞","◟"});                             // 简洁弧形

    final String[] frames;  // static final — 审计 M8
    SpinnerStyle(String[] frames) { this.frames = frames; }
}
```

**默认值保持不变**（审计 C6）：无参构造 `new Spinner()` → `CLASSIC`（Braille `⠋-⠏`）。不改变现有行为。想用 DOTS 的调用方显式传 `new Spinner(SpinnerStyle.DOTS)`。

受影响的调用点：
| 调用方 | 行号 | 默认值变更？ |
|--------|------|-------------|
| `LoadingSpinner.GLOBAL_SPINNER` | LoadingSpinner:36 | 否（CLASSIC） |
| `StickyFooter` 内部 spinner | StickyFooter:27 | 否（CLASSIC） |
| `StartupBanner` 内部 spinner | StartupBanner:88 | 否（CLASSIC，死代码） |

**StartupPhaseRunner 的 StickyFooter** 可以显式用 DOTS：

```java
// StickyFooter 增加可选构造参数
StickyFooter footer = StickyFooter.install(System.out, SpinnerStyle.DOTS);
```

### 2.3 ProgressBar 数学修正 + 8 级平滑填充

#### 修改：`ProgressBar.java`

**数学修正（审计 C1）**：原伪代码 `filled / 8` 在 20 格宽度下最多产生 2 个满格方块。正确的缩放因子是 `BAR_WIDTH × 8 = 160`。

```java
// 正确实现
private static final int BAR_WIDTH = 20;
private static final int SUB_LEVELS = 8; // 每格 8 级细分
private static final int TOTAL_UNITS = BAR_WIDTH * SUB_LEVELS; // = 160
private static final char[] SUB_BLOCKS = {' ', '▏','▎','▍','▌','▋','▊','▉','█'};

public static String render(int current, int total, String label) {
    if (!CyberColor.isTty()) {
        // 非 TTY: 纯文本百分比
        String pct = total > 0 ? (current * 100 / total) + "%" : "?%";
        return pct + (label != null ? " " + label : "");
    }

    long numerator = (long) current * TOTAL_UNITS;
    int filled8 = total > 0 ? (int) (numerator / total) : 0;
    int fullBlocks = filled8 / SUB_LEVELS;   // 0..20 ✓
    int remainder  = filled8 % SUB_LEVELS;    // 0..7  ✓

    double ratio = total > 0 ? (double) current / total : 0;

    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < BAR_WIDTH; i++) {
        if (i < fullBlocks) {
            sb.append(colorForRatio(ratio)).append('█');
        } else if (i == fullBlocks && remainder > 0) {
            sb.append(colorForRatio(ratio)).append(SUB_BLOCKS[remainder]);
        } else {
            sb.append(CyberColor.GRAY).append('░');
        }
    }
    sb.append(CyberColor.RESET);
    sb.append(String.format(" %3d%%", (int)(ratio * 100)));
    if (label != null) sb.append("  ").append(label);
    return sb.toString();
}

/** 分段着色 */
private static String colorForRatio(double ratio) {
    if (ratio < 0.5) return CyberColor.GREEN;
    if (ratio < 0.8) return CyberColor.AMBER;
    return CyberColor.CYAN;
}
```

**不使用渐变**：分段着色（绿→琥珀→青）已足够，`gradientChar()` 从计划中移除（审计 H5）。

### 2.4 CyberColor 职责拆分

**类拆分（审计 H2）**：当前 `CyberColor` 混合了 4 种职责 → 拆为 3 个类：

| 新类 | 职责 | 来源 |
|------|------|------|
| `CyberColor` | 颜色常量 + 修饰方法（不改） | 保留现有 |
| `TerminalCapability` | TTY / ANSI / Unicode 检测 | 从 CyberColor 提取检测方法 |
| *移除* | ~~blend() / gradientChar()~~ | 删除（不再需要，见 §2.3） |

```java
// TerminalCapability.java — 仅检测，不涉颜色
public final class TerminalCapability {
    public static boolean isTty()     { ... }
    public static boolean hasAnsi()   { ... }
    public static boolean hasUnicode(){ ... }
    public static String  detectedCharset() { ... } // 新增：运维可见的编码信息
}
```

`CyberColor` 内部委托 `TerminalCapability`，现有调用方完全无感知。

**blend() 移除（审计 H3）**：不再需要。进度条分段着色已够用。
