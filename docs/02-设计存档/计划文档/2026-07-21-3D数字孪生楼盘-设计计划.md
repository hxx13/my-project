# 3D 数字孪生楼盘查看器 — 设计计划

## 概述

在当前主项目 `frontend/src/features/digital-twin-3d/` 内构建轻量级 3D 楼盘查看器。Canvas 满屏渲染 8 层 GLB 建筑模型，支持 Tier 1 + Tier 2 共 8 项交互功能。模型从 Blender 导出 ~300KB/层，总模型数据 < 3MB。


## 前端改动

### ① SceneCanvas — 3D 场景壳

**文件：** `frontend/src/features/digital-twin-3d/scene/SceneCanvas.tsx`

- `<Canvas>` 固定屏幕 `fixed inset-0 z-0`，不参与 DOM 流
- 包含：`<Lights />` + `<CameraController />` + `<Sky />` + `<ContactShadows />` + `<BuildingModel />`
- 加载进度浮层：`useProgress` 显示百分比，加载完自动消失
- `dpr={[1, 2]}` — 普通屏幕 1× 像素比，Retina 2×，避免移动端浪费显存

### ② BuildingModel — 建筑模型加载与楼层变换

**文件：** `frontend/src/features/digital-twin-3d/scene/BuildingModel.tsx`

当前 3 层（2F/3F/4F 占位，后续替换为 8 层）：

```
每层: <Suspense fallback={<FloorGhost />}>
        <FloorLayer name={name} y={i * FLOOR_SPACING} />
      </Suspense>
```

楼层变换系统（纯 Zustand 状态驱动，不在 useFrame 中逐帧遍历）：

```typescript
// 三种模式互斥，由 store 管理：
// - mode === 'stacked'   → 正常堆叠，每层 y = i * 3.2
// - mode === 'exploded'  → 垂直拉开，每层 y = i * (3.2 + gapV)
// - mode === 'staircase' → Z 字形，每层 y += gapV, z -= gapH
// - focusedFloor !== null → 聚焦单层，其他层 opacity → 0.1 / y 偏移
```

**关键性能点**：楼层位置通过 `<primitive>` 的 `position` prop 直接设置，由 R3F 在 reconciler 阶段 diff，不经过 useFrame。任何形变动画使用 GSAP 操作 Three.js Object3D 引用，不触发 React 重渲染。

### ③ CameraController — 轨道控制 + 运镜系统

**文件：** `frontend/src/features/digital-twin-3d/scene/CameraController.tsx`

基于 `@react-three/drei` 的 `OrbitControls`（自带 damping，无需手写 useFrame 平滑）：

| 功能 | 实现 |
|------|------|
| 手动旋转/缩放 | `OrbitControls` 默认行为，`enableDamping dampingFactor=0.08` |
| 视角预设 | `gsap.to(camera.position, ...)` + `gsap.to(controls.target, ...)` 同步动画 |
| 全局复位 | 读取 `BuildingModel` 所有楼层的包围球，计算全局最佳视点 |
| 楼层聚焦 | 根据 `store.floorCenters[floorName]` 的包围球计算摄像机距离和角度 |
| 自动巡航 | 异步 `async` 函数，GSAP 依次执行多段运镜，`store.isTouring` 防重入 |

**运镜预设表**：

| 预设 | 摄像机位置 | 目标点 |
|------|-----------|--------|
| 全局俯瞰 | 30° 俯角，包围球 1.5× 距离 | 全局中心 |
| 正立面 | 正面 Z 轴 3× 距离 | 全局中心 |
| 顶视图 | 正上方 3.5× 距离 | 全局中心 |
| 楼层聚焦 | 35° 俯角，楼层包围球 1.2× 距离 | 楼层中心 |

### ④ ModelPicking — 点击选中模型部件

**文件：** `frontend/src/features/digital-twin-3d/scene/ModelPicking.tsx`

- R3F 原生支持 `onClick` / `onPointerOver` / `onPointerOut` 事件
- 仅对名称以 `Room_` / `Door_` / `Device_` 开头的 mesh 绑定事件
- 选中状态：`mesh.emissive = '#3b82f6'` + `emissiveIntensity = 0.3`
- 悬停状态：`mesh.emissive = '#bae6fd'` + `emissiveIntensity = 0.15`
- `Wall_` 前缀的 mesh 绑定 `onClick={e => e.stopPropagation()}` 阻止穿透选中
- Store: `selectedNode: { name, position, type } | null`

### ⑤ SceneOverlay — 选中部件 HTML 标签

**文件：** `frontend/src/features/digital-twin-3d/scene/SceneOverlay.tsx`

- 使用 `@react-three/drei` 的 `<Html>` 在部件上方渲染 React DOM
- 内容：部件名称 + 类型标签 + 基础信息占位
- 定位：读取 mesh 包围盒中心 → worldToScreen 换算
- 关闭按钮 → `store.setSelectedNode(null)`

### ⑥ UI 控制面板

三个独立面板，绝对定位浮于 Canvas 上方，`z-10`，`pointer-events-none` 包裹层 + 内部 `pointer-events-auto`。

**ViewControls.tsx**（右侧悬浮）：
- 4 个图标按钮垂直排列：俯瞰 / 正面 / 顶视 / 复位
- 激活态高亮指示

**FloorControls.tsx**（左下角水平条）：
- 8 个楼层按钮（1F-8F），点击 → `store.focusFloorCamera(name)`
- "还原"按钮取消聚焦
- 展开/阶梯模式切换按钮（互斥）

**TourControls.tsx**（右下角）：
- 巡航风格选择（环绕 / 推近）
- 启动/停止按钮

## 🔍 三方审查反馈汇总

以下来自稳定性、性能、先进性三路 Agent 的交叉审查，共 30 项发现，已去重并纳入修订。

### 致命缺陷（CRITICAL × 6）

| # | 来源 | 缺陷 | 修正 |
|---|------|------|------|
| C1 | 稳定性 | Canvas 无 Error Boundary → Three.js 异常直接白屏 | 加 `react-error-boundary`，fallback 含手动重载按钮 |
| C2 | 稳定性+性能 | 8 个 GLB 并发加载 → CPU 解码风暴 + GPU 上传合并卡顿 | 错峰加载队列，最大并发 2，优先加载中间层(4F→上下展开) |
| C3 | 稳定性 | GLB 加载失败只有 console.error，用户不可感知 | Timeout Promise(15s) + 按错误类型(网络/解析/解码)分类 + 200ms退避重试1次 + 手动重试按钮 |
| C4 | 性能 | 射线检测无 BVH 加速 → 每帧 O(n) 三角形遍历 5-10ms | `three-mesh-bvh` + 非交互 mesh 设 `raycast={() => null}` |
| C5 | 先进性 | 无 `useGLTF.preload()` → 用户点楼层才加载，pop-in 体验差 | 页面挂载时分批预加载（每批 ≤2 并发），Suspense 只负责挂载渲染 |
| C6 | 先进性 | Zustand v5 未用 `useShallow` → 对象型 selector 每次返回新引用 | `selectedNode`/`floors`/`floorNames`/`cameraTarget` 等所有引用型字段加 `useShallow` |

### 高危缺陷（HIGH × 6）

| # | 来源 | 缺陷 | 修正 |
|---|------|------|------|
| H1 | 稳定性 | GSAP timeline 无 React 生命周期集成 → 卸载后动画继续跑 | CameraController + BuildingModel 均用 `@gsap/react` 的 `useGSAP` hook |
| H2 | 稳定性 | OrbitControls 外层有残留手动事件监听（wheel/pointer，非 drei 内置）| 当前已用 drei `<OrbitControls>`，不额外 addEventListener。清理项仅指 drei 组件的 useEffect cleanup 确保 dispose |
| H3 | 稳定性 | Store `floorCenters` 与 `floorNames` 解耦 → 空指针 TypeError | 合并为 `floors: Record<string, FloorData>`（Zustand 推荐 plain object），`focusFloorCamera` 内 null guard |
| H4 | 性能 | 模式切换通过 Zustand → 8 个 `<primitive position>` reconciler diff | 明确分离：GSAP 直接操作 Object3D ref（动画中），动画结束后同步 Zustand（最终态） |
| H5 | 性能 | 无移动端降级策略 → GPU 内存 OOM | 三档设备检测(`hardwareConcurrency`<4→low, ≥4且<7→medium, ≥7→high)；Low档：无阴影/dpr[0.75,1]/30fps，GPU内存靠KTX2控制 |
| H6 | 性能 | 无性能监测手段 → 优化无基线 | `stats.js` + `renderer.info.render` 日志(draw calls/triangles) + 性能预算表 |

### 中危缺陷（MEDIUM × 8）

| # | 来源 | 缺陷 | 修正 |
|---|------|------|------|
| M1 | 性能 | OrbitControls 缺约束 → 可缩放穿墙、翻到地下 | minDist=6, maxDist=80, polarAngle 0.15~1.35rad, zoomSpeed=0.8, rotateSpeed=0.5 |
| M2 | 性能 | ContactShadows `frames={1}` 在 explode/staircase 错位 | 模式切换时通过 `key={floorMode}` 强制卸载/重新挂载（drei ContactShadows 不支持 needsUpdate 重烘焙） |
| M3 | 稳定性 | 后台 tab 切回时 GSAP 追进度 → 动画跳变 | `visibilitychange` 暂停/恢复 `gsap.globalTimeline` |
| M4 | 稳定性 | SceneOverlay `<Html>` 缺 key → 快速切换短暂双标签 | 加 `key={selectedNode.name}` 强制卸载 |
| M5 | 稳定性 | WebGL context lost 无恢复 → GPU 驱动异常崩溃 | `webglcontextlost`→preventDefault+展示恢复层；`webglcontextrestored`→`renderer.resetState()`+重新上传纹理；30s超时降级 |
| M6 | 先进性 | 光照基础（环境光+方向光）→ 建筑材质表现力弱 | 加 `<Environment preset="city">` HDR 环境贴图 + `toneMapping=ACESFilmicToneMapping` |
| M7 | 先进性 | 无 KTX2/Basis 纹理压缩 → GPU 内存膨胀 | Phase 1 纳入：Blender 导出 KTX2；Three.js `KTX2Loader`（`three/addons`）；不依赖"简化GLB" |
| M8 | 性能 | GLB 卸载无 dispose → 页面切换 GPU 内存泄漏 | 楼层卸载时显式 `scene.traverse(child => child.geometry?.dispose(); child.material?.dispose())`；`useGLTF.clear(url)` 清理缓存 |

## 修订后性能保障

| 策略 | 具体措施 |
|------|---------|
| **模型压缩** | Blender 导出 GLB 时 **Meshopt 几何压缩** + **KTX2/Basis 纹理压缩**，目标 ≤300KB/层（Meshopt 与 Draco 二选一，选 Meshopt 解码速度更快） |
| **分批预加载** | `useGLTF.preload()` 分 2 批、每批 ≤2 并发，优先中间层(4F→5F→3F→6F→2F→7F→1F→8F)；Suspense 仅负责挂载渲染 |
| **形变动画** | GSAP 直接操作 Object3D ref，动画结束后才同步 Zustand（不触发 React reconciler diff） |
| **BVH 加速** | `three-mesh-bvh` 所有几何体，非交互 mesh `raycast={() => null}` |
| **阴影** | ContactShadows `frames={1}` 单帧烘焙；模式切换时 `key={floorMode}` 强制重挂载 |
| **OrbitControls 约束** | dampingFactor=0.08、minDist=6、maxDist=80、polarAngle 0.15~1.35rad、zoomSpeed=0.8、rotateSpeed=0.5 |
| **dpr 分档** | High [1,2]、Medium [1,1.5]、Low [0.75,1]（三档阈值见 Step 0.9） |
| **移动端降级** | Low 档：无 ContactShadows、dpr[0.75,1]、GPU内存靠KTX2控制在80MB内；不维护"简化GLB"版本 |
| **材质共享** | 跨楼层按名称匹配共享材质，加载完成后遍历 scene → 去重替换为单例 → dispose 重复实例 |
| **内存管理** | 楼层卸载时 `dispose()` geometry/material；`useGLTF.clear(url)` 清纹理缓存 |
| **性能监测** | `stats.js` + `renderer.info.render`(draw calls/triangles) + 性能预算表 |

## 实施步骤

### Step 0 — 稳定性基础设施（先于一切功能）

**0.1** 安装新依赖：`npm i three-mesh-bvh react-error-boundary`
**0.2** SceneCanvas 双层 Error Boundary：外层 `<ErrorBoundary>` 兜 React DOM 异常；`Canvas.onCreated` 监听 `gl` 异常桥接到外层
**0.3** 设备检测顶层 Provider（`useDeviceTier`）→ 在所有 preload/Canvas 之前确定 tier，避免竞态
**0.4** `Canvas.onCreated` 中 WebGL context lost/restored 监听 → lost 展示恢复层 → restored 调 `renderer.resetState()` + 纹理重上传 → 30s 超时降级
**0.5** `document.addEventListener('visibilitychange')` → GSAP `globalTimeline.pause()/resume()`

### Step 0.5 — 性能基线

**0.6** 分批预加载：`useGLTF.preload()` 分 2 批、每批 ≤2 并发；顺序 4F→3F→2F（当前3层）；扩展8层后 4F→5F→3F→6F→2F→7F→1F→8F
**0.7** BVH + 非交互 mesh：每个 FloorLayer 加载后 `traverse` → `geometry.computeBoundsTree()`；`Wall_` 前缀 mesh 设 `raycast={() => null}`
**0.8** 材质共享：加载后按 `material.name` 匹配 → 跨楼层去重替换为单例 → `dispose()` 重复实例
**0.9** DevOps：`<Stats>` 挂入 Canvas（仅 `import.meta.env.DEV`）

### Step 1 — Store 搭建

**1.1** `useStore.ts`：Store interface 完整定义
```typescript

cameraTarget: [number,number,number]
```

**1.2** 所有消费引用型字段的 selector 均用 `useShallow`：`floors`、`floorNames`、`cameraTarget`、`selectedNode`

### Step 2 — CameraController + SceneCanvas 整合

**2.1** drei `<OrbitControls>` 替换手写控制器：dampingFactor=0.08、minDist=6、maxDist=80、polarAngle 0.15~1.35rad、zoomSpeed=0.8、rotateSpeed=0.5
**2.2** `<Environment preset="city">` HDR 环境贴图 + Canvas `onCreated` 中设置 `gl.toneMapping = THREE.ACESFilmicToneMapping`
**2.3** ContactShadows `<ContactShadows key={floorMode} ... />` 模式切换强制重挂载
**2.4** CameraController + BuildingModel 均使用 `useGSAP` hook（`@gsap/react`）管理运镜动画生命周期
**2.5** 视角预设：`focusFloorCamera(name)` 先 `.kill()` → 新 GSAP timeline；全局复位/俯瞰/正面/顶视

### Step 3 — BuildingModel 增强

**3.1** 加载链路：`useGLTF.preload()` 分批预加载（Step 0.6）→ 每个 FloorLayer 用 Timeout Promise(15s) 包装 + 200ms 退避重试 1 次 + per-floor 错误 UI
**3.2** 错误分类：`instanceof TypeError`(网络)→重试有意义；`GLTFLoader error`(解析/解码)→不重试，直接展示手动重试按钮
**3.3** 楼层变换：GSAP 操作 Object3D ref → 动画结束后同步 Zustand `floorMode`
**3.4** 卸载清理：`useEffect` cleanup → `scene.traverse(child => child.geometry?.dispose(); child.material?.dispose())` + `useGLTF.clear(url)`

### Step 4 — ModelPicking + SceneOverlay

**4.1** BVH 加速拾取（Step 0.7 已统一处理）
**4.2** 选中：`emissive='#3b82f6' emissiveIntensity=0.3` / 悬停 `emissive='#bae6fd' 0.15`

### Step 5 — UI 面板

**5.1** ViewControls（右侧垂直按钮组）/ FloorControls（左下水平条）/ TourControls（右下）
