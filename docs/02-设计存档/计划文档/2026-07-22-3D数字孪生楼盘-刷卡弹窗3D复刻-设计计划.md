## 一、架构全景

### 1.1 两个位置的关系

```
┌─ /#/console/digital-twin-3d（配置中心）────────────────────┐
│                                                           │
│  Canvas: 主 BuildingModel（读写 useStore）                  │
│  全功能集合：                                              │
│    ✅ 楼层切换  ✅ 爆炸/阶梯  ✅ 手动旋转缩放                  │
│    ✅ 模型点击  ✅ 巡航     ✅ 镜头预设配置（6值）             │
│    ✅ 路线预设配置  ✅ 弹窗模拟测试                           │
│                                                           │
│  职责：开发 → 调参 → 配置 → 导出                            │
│  不在弹窗视图中，独立存在                                    │
└───────────────────────────────────────────────────────────┘

┌─ /#/console/dashboard → UiverseProfilePopup（刷卡弹窗）────┐
│                                                           │
│  Canvas: PopupBuildingModel（不写 useStore，内部 useRef）    │
│  功能子集（从配置中心下放的配置驱动）：                         │
│    ✅ 自动巡航  ✅ 路线引导  ✅ 房间高亮                       │
│    ❌ 手动旋转  ❌ 楼层切换  ❌ 爆炸/阶梯                      │
│    ❌ 模型点击  ❌ 巡航风格                                   │
│                                                           │
│  2D/3D 切换：右键菜单 [🏗 切换3D视图]，超管可见              │
│  职责：按人员权限展示，纯自动                                │
└───────────────────────────────────────────────────────────┘
```

**关键事实**：两个位置在不同路由下 → Canvas 永远不同时存在 → 无 GPU 双倍压力 → 无 store 同时写入冲突。

### 1.2 代码关系

| | 主 BuildingModel | PopupBuildingModel |
|---|---|---|
| **行数** | ~500 行 | ~200 行（精简版） |
| **数据源** | `useStore`（Zustand 全局） | 内部 `useRef`（不污染全局） |
| **unmount 清理** | `useGLTF.clear()` | 不调 `clear()`（GLTF 缓存留给下次） |
| **支持模式** | stacked / exploded / staircase / focusedFloor | 仅 stacked + focusedFloor |
| **用户交互** | 点击选中 / 悬停高亮 | 无（纯展示） |
| **BVH/raycast** | 有 | 无 |
| **材质共享** | 有（materialCache） | 无 |
| **使用位置** | digital-twin-3d 配置中心 | Dashboard 弹窗 3D 模式 |
| **运镜** | OrbitControls + GSAP flyTo | 纯 GSAP 直接操作 camera.position/lookAt |

## 二、弹窗 3D 模式设计

### 2.1 入口：右键菜单切换（全局模式）

- 在 `UiverseProfilePopup` 内，**右键点击弹窗内容区域**弹出上下文菜单
- 菜单项 `[🏗 切换3D视图]` 仅对超级管理员可见
- **全局开关**：一次切换影响**所有人的弹窗**。所有刷卡弹窗共用同一个模式（2D 或 3D）
- 状态持久化到 `localStorage['dt3d-popup-3d-mode']`（`'2d' | '3d'`）
- 切换时弹窗内容区做 AnimatePresence 过渡

**为什么是全局而非每人独立**：
- 3D 模式是系统级功能升级，不是用户偏好
- 每个人单独开关意味着需要 per-user localStorage，不可维护
- 调试期超管决定启用/关闭，面向所有弹窗生效

### 2.4 路线系统

#### 2.4.1 路线预设数据格式

```typescript
type RoutePoint = [number, number, number]; // [x, y, z] 世界坐标

type RoomRoute = {
  id: string;
  name: string;           // 显示名称："入口 → 101 实验室"
  fromRoom: string;       // 起点房间名（或 'entrance' 表示建筑入口）
  toRoom: string;         // 终点房间名
  points: RoutePoint[];   // 途经点坐标数组
};

// 双向查找表
const routeByRoom: Record<string, RoomRoute> = {
  'Room_101': { id: 'entrance→Room_101', name: '入口 → 101', ... },
  'Room_203': { id: 'entrance→Room_203', name: '入口 → 203', ... },
};
```

#### 2.4.2 路线录制功能（Q2 决策）

在 digital-twin-3d 页面的配置面板中，用户通过**点击房间序列**来录制路线：

```
录制流程：
  1. 点击 [🎬 开始录制]
  2. 依次点击模型中的房间（或从房间列表选择）
     Room_Entrance → Corridor_A → Room_101
  3. 系统自动计算途经点坐标（各房间的 worldPosition）
  4. 点击 [⏹ 停止录制] → 保存为 RoomRoute 配置
  5. 可编辑途经点坐标（拖拽控制点微调）
  6. 导出到 routePresets.ts
```

**途经点自动计算**：选中房间后，取其 GLB mesh 的 `getWorldPosition()` 作为途经点。用户可在配置面板中微调每个点的 X/Y/Z。

#### 2.4.3 渲染：连续实线（Q2 决策）

**不做虚线流动**。改为**连续实线 + 发光**：

```typescript
// CatmullRomCurve3 平滑曲线 → TubeGeometry 管道
const curve = new THREE.CatmullRomCurve3(points);
const geometry = new THREE.TubeGeometry(curve, 64, 0.12, 8, false);

// MeshBasicMaterial — 不受光照影响，纯色管线
const material = new THREE.MeshBasicMaterial({
  color: new THREE.Color('#ef4444'),  // 红色
  transparent: true,
  opacity: 0.85,
});

// 可选：外层 glow 管道（稍粗，低 opacity）增强视觉效果
const glowGeometry = new THREE.TubeGeometry(curve, 64, 0.25, 8, false);
const glowMaterial = new THREE.MeshBasicMaterial({
  color: new THREE.Color('#ef4444'),
  transparent: true,
  opacity: 0.2,
});
```

**无动画**：路线是一次性渲染的静态管道。视觉引导通过相机沿路线飞行来实现（ROUTE_FLY 步骤中 camera 沿 curve 移动）。

### 2.5 Canvas 生命周期

**Q1 决策**：切换为 3D 模式时才 mount Canvas，切回 2D 模式直接销毁。无需预热常驻。

```
弹窗打开（2D 模式）
  → Canvas 不 mount（零 GPU 开销）

用户切换 [🏗 3D视图]
  → Canvas mount → GLB 加载（命中 HTTP 缓存 ~500ms）→ 开始巡航

用户切回 [📋 列表视图]
  → Canvas unmount → GPU 释放 → 回到 2D 模式

再次切换 [🏗 3D视图]
  → Canvas 重新 mount → GLB 从 HTTP 缓存加载（~300ms）→ 开始巡航
```

**切换空白期处理**：Canvas mount 期间显示加载骨架屏（Canvas 占位区 + 脉冲动画），加载完成后骨架屏淡出、模型淡入。

### 2.6 过场动画：全部可配置

所有运镜时长由 `PopupFlowConfig.animation` 控制，不在代码中硬编码。前端配置面板可调节。

```typescript
type AnimationConfig = {
  overviewDuration: number;      // 全楼俯瞰飞行时长（秒），默认 2.0
  floorFocusDuration: number;    // 楼层聚焦飞行时长（秒），默认 1.5
  routeSegmentDuration: number;  // 路线每段飞行时长（秒），默认 1.5
  highlightFadeIn: number;       // 高亮 + 卡片淡入时长（秒），默认 0.3
  ease: string;                  // GSAP ease，默认 'power2.inOut'
};
```

**默认值不是 1.0s**。保守起步为 1.5-2.0s，后续在配置面板中根据实际体感调优。

### 2.7 流程可配置（Q4 决策）

弹窗**不硬编码**巡航流程。所有步骤由 digital-twin-3d 页面预先配置，导出为 JSON 配置文件，弹窗读取执行。

```typescript
// 配置结构（digital-twin-3d 页面编辑，导出给弹窗使用）
type PopupFlowConfig = {
  // 初始展示：摄像头从哪个位置开始
  overview: { camOffset: [number,number,number]; targetOffset: [number,number,number] };
  
  // 楼层聚焦策略：单层 → focusedFloor，多层 → explodedFloors
  floorStrategy: {
    singleFloor: 'focused' | 'zoomed';     // 单层：聚焦 or 拉近
    multiFloor: 'exploded' | 'sequential'; // 多层：同时展开 or 逐个飞
    noPermissionFloors: 'dim' | 'hide';    // 无权限楼层：dim(opacity=0.1) or hide
  };
  
  // 房间选择后的行为
  roomAction: {
    autoFly: boolean;           // 是否自动飞向房间
    showRoute: boolean;         // 是否显示路线
    highlightRoom: boolean;     // 是否高亮
    showInfoCard: boolean;      // 是否弹出信息卡片
  };
  
  // 视觉
  visual: {
    routeColor: string;           // 路线颜色，默认 '#ef4444'
    routeGlowOpacity: number;     // 路线发光透明度，默认 0.2
  };
  
  // 动画速度（全部可配，不硬编码）
  animation: AnimationConfig;
};
```

**digital-twin-3d 页面的配置面板**：新增 `FlowConfigPanel.tsx`，可视化编辑上述参数，实时预览效果。配置保存到 localStorage 并支持导出 JSON 文件。

## 三、PopupBuildingModel 设计

### 3.1 与主 BuildingModel 的差异

`PopupBuildingModel` 只做弹窗需要的最小功能集：

```
PopupBuildingModel（~200 行）
  │
  ├── useGLTF 加载 4 层 GLB（复用主页面缓存）
  ├── 内部 useRef Map 管理楼层 Group 引用
  ├── 不写 useStore（不调 registerFloor/recomputeGlobalBounds）
  ├── 不调 useGLTF.clear()（unmount 时不清理缓存）
  ├── 不支持 exploded/staircase（仅 stacked + focusedFloor）
  ├── 不支持用户交互（无 onClick/onPointerOver/BVH）
  ├── 不支持材质共享
  │
  ├── floorVisibility: 通过 opacity 控制楼层显隐
  │     focusedFloor='1F' → 1F opacity=1, others opacity=0.1
  │
  ├── highlightRoom(name): 遍历 refMap 找 mesh，设 emissive
  └── clearHighlight(): 清除所有 emissive
```

### 3.2 相机运镜

弹窗不需要 OrbitControls。直接用 GSAP 操作 R3F camera：

```typescript
// 弹窗内独立的 flyTo（不依赖主 useStore 的 _cameraActions）
const flyTo = (pos: THREE.Vector3, target: THREE.Vector3, duration = 1.5) => {
  gsap.to(camera.position, {
    x: pos.x, y: pos.y, z: pos.z,
    duration, ease: 'power2.inOut',
    onUpdate: () => camera.lookAt(target),
  });
};
```

**为什么不需要 OrbitControls**：
- 弹窗纯展示，无用户手动操作
- `camera.position` 由 GSAP 直接控制
- `camera.lookAt(target)` 替代 `controls.target`

### 3.3 Canvas 配置

```tsx
<Canvas
  camera={{ position: [0, 30, 60], fov: 42, near: 0.5, far: 500 }}
  gl={{ antialias: true, powerPreference: 'high-performance' }}
  style={{ width: '100%', height: '100%' }}
>
  {/* 光照 */}
  <ambientLight intensity={0.6} />
  <directionalLight position={[80, 60, 40]} intensity={0.8} />

  {/* 地基平面（Q6：保留，几乎零开销的 plane mesh） */}
  <mesh rotation={[-Math.PI / 2, 0, 0]} position={[0, -0.1, 0]} raycast={() => {}}>
    <planeGeometry args={[600, 600]} />
    <meshStandardMaterial color="#e8e4df" transparent opacity={0.6} depthWrite={false} />
  </mesh>

  {/* 无 ContactShadows（Q5） */}

  <PopupBuildingModel
    floorNames={['1F','2F','3F','4F']}
    focusedFloor={focusedFloor}
    highlightedRoom={highlightedRoom}
  />
  <Scan3DRouteLines route={activeRoute} />
</Canvas>
```

### 3.4 错误降级（Q8 决策）

```typescript
// PopupBuildingModel 外层包裹 ErrorBoundary
<ErrorBoundary
  fallback={null}  // 静默降级
  onError={(err) => {
    console.error('[Scan3D] Canvas init failed, falling back to 2D:', err);
    setContentMode('2d');  // 切回 2D 模式
  }}
>
  <PopupBuildingModel ... />
</ErrorBoundary>
```

WebGL context lost → 不弹 toast，静默记录日志。GLB 加载失败 → `FloorGhost` 线框占位（复用 BuildingModel 已有的 Suspense fallback）。

## 四、3D 模式数据流

### 4.1 运行时数据流

```
刷卡/WebSocket 事件
  → person 数据 { name, group, rooms: [{ id, name, floorName }] }
    → popup 打开
      → 如果 localStorage['dt3d-popup-3d-mode'] === '3d'
        → Canvas mount → GLB 加载 → 开始巡航
          → OVERVIEW → FLOOR_FOCUS → ROOM_SELECT

用户点击房间按钮
  → selectRoom(roomName)
    → 查找 routeByRoom[roomName]
      → 有路线 → ROUTE_FLY → HIGHLIGHT
      → 无路线 → 直接 HIGHLIGHT（仅高亮，无路线）

弹窗关闭 / 切回 2D
  → Canvas unmount → GPU 资源释放
  → GLTF 缓存保留（PopupBuildingModel 不调 clear()）
  → 下次打开秒加载
```

## 七、关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| Canvas 策略 | **两个独立 Canvas，不同时存在** | 不同路由，互斥。不需要解决双 Canvas GPU 问题 |
| 弹窗 BuildingModel | **PopupBuildingModel（~200行精简版）** | 不写 useStore，不调 clear()，内部 useRef 自管理 |
| Canvas 生命周期（Q1） | **切换 3D 时 mount，切回 2D 时销毁** | 节省 GPU 资源，无需预热 |
| 运镜方式 | **纯 GSAP 直接操作 camera** | 不需要 OrbitControls，弹窗纯展示 |
| 切换入口 | **右键菜单，超管可见，全局生效** | 一次切换影响所有弹窗，非 per-user |
| 切换动画 | **加载骨架屏 + 淡入** | Canvas mount 期间骨架屏占位，无空白帧 |
| 路线渲染（Q2） | **连续实线 + 发光管道，无虚线** | MeshBasicMaterial + TubeGeometry，简洁可靠 |
| 路线录制（Q2） | **digital-twin-3d 页面点击房间序列录制** | 自动计算途经点，可微调，可导出 |
| 动画速度 | **全部可配置，不硬编码** | AnimationConfig 六个参数，配置面板调节 |
| 巡航流程（Q4） | **全部可配置，不硬编码** | digital-twin-3d 页面 FlowConfigPanel 编辑，导出 JSON |
| 阴影（Q5） | **无 ContactShadows** | 弹窗不需要，节省 GPU |
| 地面参考平面（Q6） | **保留** | 零开销 plane mesh，帮助感知空间 |
| 数据策略（Q7） | **开发期 mock → 接入期映射桥接** | roomNameMapping 配置文件，后续迁移后端 |
| 错误降级（Q8） | **静默切回 2D + console.error** | 不弹 toast，不打断用户 |
| GLTF 缓存 | **PopupBuildingModel 不清理** | 缓存留给下次或 digital-twin-3d 页面 |
