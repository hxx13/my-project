## 用户反馈 6 项 — 根因详解

### U1: 缩小有上限（min/maxDistance 均不对）

`CameraController.tsx` 中 `<OrbitControls minDistance={6} maxDistance={80}>`：

- **minDistance=6 太松**：允许镜头进入建筑内部（包围球半径 ~10 单位）
- **maxDistance=80 太远**：建筑在视口中仅占 ~15%
- **target 未设置**：OrbitControls 默认围绕 `[0,0,0]` 旋转，建筑中心在 y≈3.2

### U2: 没有平移拖动

drei OrbitControls 默认 `enablePan=true` + 右键/中键拖拽平移。但零 UI 提示、零 tooltip、零键盘快捷键。用户不知道右键可平移。

### U3: 相机中心算法硬编码

- ViewControls 4 个预设全部 hardcode `target=[0,8,0]`
- TourControls waypoints 全部用 `TARGET=[0,8,0]`
- `registerFloor` 存的是 `box.getCenter()` **本地坐标**（~[0, 1.4, 0]），未加楼层 Y 偏移
- `__dt3d_resetCamera` 算出的 `globalCenter ≈ [0, 0, 0]` 而非真正的 `[0, 3.2, 0]`

### U4: 爆炸/阶梯模式错位堆叠

**核心根因**：`useGSAP` 依赖 `[floorMode, focusedFloor, explodeGapV, explodeGapH, floorNames]`，缺少楼层加载状态。当楼层在非堆叠模式激活**之后**才加载完成时，`useGSAP` 不重新触发，该楼层永久停留在 `<primitive position={[0, i*3.2, 0]}>` 堆叠位置。

**次要根因**：GSAP position tween 未 kill → 模式快速切换时旧 tween 与新 tween 叠加抖动。

### U5: 点击地板选中整层模型（三层叠加）

1. **名称遍历**：丢弃 `e.object` 精确引用 → 按名匹配 traverse → 同名 mesh 全亮
2. **共享材质污染**：GLB 中多 mesh 共享 Material + `materialCache` 跨层共享 → 设 emissive 污染所有共享 mesh
3. **hover 复位冲突**：`onPointerOut` 按名比较而非引用比较 → 可能清掉选中高亮

### U6: 选中弹窗卡片定位偏移

- `obj.getWorldPosition()` 返回 mesh 几何中心（房间正中），不是用户点击位置
- `e.point` 已有精确命中点但被丢弃
- `distanceFactor={30}` 缩放过大 + 缺 Y 轴偏移使卡片盖在模型表面

#### P0.2 实现细节：方案 B — Store 存 `_cameraActions`

核心矛盾：`camera` 和 `controlsRef` 仅在 R3F Canvas 内部的 `useThree()` 中可用，Zustand store actions 在模块顶层定义无法访问 React hooks。

**选择方案 B**：CameraController 挂载时把函数写入 store 的 `_cameraActions` 字段。

```typescript
// useStore.ts 新增
type CameraActions = {
  flyTo: ((pos: [number,number,number], target: [number,number,number], duration?: number) => void) | null;
  resetCamera: (() => void) | null;
  focusFloor: ((name: string) => void) | null;
};

type Store = {
  // ... existing fields ...
  _cameraActions: CameraActions;
};

// 初始值全 null
_cameraActions: { flyTo: null, resetCamera: null, focusFloor: null },
```

```typescript
// CameraController.tsx — useGSAP 中注册
useGSAP(() => {
  useStore.setState({
    _cameraActions: { flyTo, resetCamera: () => { /* global reset logic */ }, focusFloor: (name) => { /* focus logic */ } }
  });
  return () => {
    useStore.setState({ _cameraActions: { flyTo: null, resetCamera: null, focusFloor: null } });
  };
}, []);
```

```typescript
// 面板中调用（替代 window.__dt3d_*）
const { flyTo, resetCamera, focusFloor } = useStore((s) => s._cameraActions);
// 调用前 null check
flyTo?.(pos, target);
```

Phase 0 只完成 store 侧接口定义 + CameraController 注册。面板接入放在 Step 2.5/3/4。

#### P0.5 实现细节：正确的 WebGL 恢复

`needsUpdate` 是 `THREE.Texture` 的属性，不是 Material 的。且 `onCreated` 需解构 `scene` 用于遍历。

```typescript
// SceneCanvas.tsx onCreated — 正确写法
onCreated={({ gl, scene }) => {
  gl.domElement.addEventListener('webglcontextrestored', () => {
    // 遍历所有纹理设 needsUpdate
    scene.traverse((obj: any) => {
      if (obj.material) {
        const mats = Array.isArray(obj.material) ? obj.material : [obj.material];
        mats.forEach((mat: any) => {
          for (const val of Object.values(mat)) {
            if (val instanceof THREE.Texture) val.needsUpdate = true;
          }
        });
      }
    });
    // Three.js 内部已自动恢复 shader/buffer，这里仅处理纹理重上传
  });
}}
```

#### P0.6 实现细节：Hover 不 clone 材质

用户快速划过 20 个 mesh → 20 次 `material.clone()` 不可接受。策略调整：

- **Hover**: 仅改 `document.body.style.cursor` + 可选渲染一个独立的半透明 outline ring（`<Ring>` / `<Edges>` 组件，不碰原材质）
- **Click 选中**: 保留 `isSharedMaterial()` + `clone()` 逻辑（低频操作，性能可接受）

这意味 P0.6 的核心变更是**删除** onPointerOver/onPointerOut 中所有 emissive 操作，改为纯 cursor 反馈。Step 6 统一实现此策略。
