## 问题总览

5 个用户反馈缺陷，按严重程度排列：

| # | 缺陷 | 严重度 | 根因类别 |
|---|------|--------|---------|
| 1 | 缩小有上限，无法看清全貌 | HIGH | minDistance=6 太松可穿入建筑；maxDistance=80 太远建筑缩成点 |
| 2 | 没有平移拖动 | HIGH | Pan 默认开启但右键平移不可发现，无 UI 提示 |
| 3 | 相机中心算法硬编码，导致穿墙 | CRITICAL | ① 所有预设 target=[0,8,0] ② registerFloor 存本地坐标未加 Y 偏移 |
| 4 | 爆炸/阶梯模式错位堆叠 | CRITICAL | 包围盒中心异步写入 + 初始 position 与 GSAP 冲突 |
| 5 | 点击地板选中整层模型 | HIGH | scene.traverse 按名匹配 + 共享材质污染 |
| 6 | 选中弹窗卡片定位偏移 | MEDIUM | 用 mesh 几何中心而非点击交点；缺 Y 轴偏移 |

## 缺陷 1: 缩小有上限（min/maxDistance 均不对）

### 根因（子 Agent 纠正）

`CameraController.tsx` 中 `<OrbitControls minDistance={6} maxDistance={80}>`：

**minDistance=6 太松**（不是太紧！）：Three.js OrbitControls 中 `minDistance` 是**缩近**限制。建筑包围球半径约 10 单位，minDistance=6 意味着镜头可以**进入建筑内部**。FOV=42° 下可见垂直范围仅 4.6 单位 → 用户缩近后只能看到一层楼的一部分，完全丢失空间感。

**maxDistance=80 太远**：建筑高约 9.2 单位，在 maxDistance=80 处建筑在视口中仅占 ~15%。用户缩远后建筑缩成一个小点。

**更致命的是**：OrbitControls 的 `target` 未显式设置，默认为 `[0,0,0]`。建筑实际中心在 y≈3.2。target 不在建筑中心 → 用户旋转时绕世界原点转 → 建筑飞到屏幕外。

### 修复方案

**改为动态计算 minDistance/maxDistance**，基于实际加载的楼层包围球：

```typescript
// 在 CameraController 中，从 store.floors 计算全局包围球
// minDistance = 全局包围球半径 × 0.5（允许贴近观察）
// maxDistance = 全局包围球半径 × 3.0（允许远观全貌）
// 无楼层数据时的 fallback: minDistance=2, maxDistance=120
```

同时降低 `minPolarAngle` 下限（当前 0.15 rad ≈ 8.6°，允许更俯视的角度）。

### 涉及文件

- `scene/CameraController.tsx` — 动态距离约束
- `store/useStore.ts` — 可能需要暴露 `globalBounds` 派生状态

## 缺陷 2: 没有平移拖动

### 根因

查看 `CameraController.tsx` 中 OrbitControls 配置：

```tsx
<OrbitControls
  ref={controlsRef}
  makeDefault
  enableDamping dampingFactor={0.08}
  minDistance={6} maxDistance={80}
  minPolarAngle={0.15} maxPolarAngle={1.35}
  zoomSpeed={0.8} rotateSpeed={0.5}
/>
```

未显式设置 `enablePan`，drei OrbitControls 默认为 `true`。但用户反馈无法平移。可能原因：

1. 中键/右键平移在用户设备上不可用（笔记本触控板无中键）
2. `enablePan` 实际未生效（需要确认 drei 版本默认值）
3. 缺少 UI 层面的平移模式切换按钮

### 修复方案

1. **显式启用** `enablePan={true}` + `panSpeed={0.8}`
2. **添加右键平移**：`mouseButtons={{ LEFT: ROTATE, MIDDLE: PAN, RIGHT: PAN }}` 使右键也能平移
3. **ViewControls 增加平移模式按钮**：点击后切换 OrbitControls 的 `touches` 和 `mouseButtons` 配置

### 涉及文件

- `scene/CameraController.tsx` — Pan 配置 + 全局 API
- `panels/ViewControls.tsx` — 添加平移模式按钮

## 缺陷 3: 相机中心算法硬编码 —— 核心缺陷

### 根因

**所有视角预设都硬编码了 `target=[0,8,0]` 和固定 camera position**，完全无视建筑模型的实际包围盒：

```typescript
// ViewControls.tsx — 当前代码
const presets = [
  { label: '俯瞰', action: () => FLY()?.([0, 45, 1], [0, 8, 0]) },
  { label: '正面', action: () => FLY()?.([0, 10, 45], [0, 8, 0]) },
  { label: '顶视', action: () => FLY()?.([0, 40, 0.1], [0, 8, 0]) },
  { label: '复位', action: () => RESET()?.() },
];
```

问题链条：
- 建筑实际中心约在 y ≈ 3.2（3 层 × 3.2 间距 / 2），而非 y=8
- 所有预设 target 指向 y=8（建筑上空 4.8 单位），camera 围绕空中的点旋转
- 用户操作 OrbitControls 时旋转轴心在建筑上方 → 旋转时必然"穿墙"
- `__dt3d_focusFloor` 虽然有动态计算，但 ViewControls 完全不使用它
- `__dt3d_resetCamera` 计算了全局包围球，但被"复位"按钮调用时才触发

### 修复方案

**重构为完全自适应**：所有相机运动（预设/聚焦/复位/巡航）均基于 `BuildingModel` 加载后计算出的 **全局包围球 (global bounding sphere)**：

#### 3.1 Store 新增派生数据

```typescript
// useStore.ts 新增
globalCenter: [number, number, number];  // 所有已加载楼层的包围球中心
globalRadius: number;                    // 包围球半径
recomputeGlobalBounds: () => void;       // 任一楼层的包围盒更新后调用
```

每次 `registerFloor` 被调用时，自动触发 `recomputeGlobalBounds()`，聚合所有 `floors[].center` 和 `floors[].radius` 计算全局包围球。

#### 3.2 ViewControls 预设改为闭包函数

```typescript
// 不再硬编码 target，而是在点击时实时从 store 读取 globalCenter
const presets = [
  { 
    label: '俯瞰', 
    action: () => {
      const { globalCenter, globalRadius } = useStore.getState();
      const dist = globalRadius * 2.5;
      const phi = Math.PI / 5;  // 18° 俯角
      const pos: [number,number,number] = [
        globalCenter[0],
        globalCenter[1] + dist * Math.sin(phi),
        globalCenter[2] + dist * Math.cos(phi) * 0.1,
      ];
      FLY()?.(pos, globalCenter);
    }
  },
  // ... 正面/顶视/复位 同理
];
```

#### 3.3 巡航路径改用包围球

```typescript
// 4 向环绕：摄影机在 globalCenter 周围，距离 = globalRadius * 2.0
// hero 推近：从远到近 3 段，每段距离递减
```

#### 3.4 `__dt3d_focusFloor` 修复

当前实现已经动态计算单层包围球，但 `fov` 闭包不更新（CameraController 中 `const { fov }` 只在挂在时取一次）。改为每次调用时从 store 读取最新 fov。

### 涉及文件

- `store/useStore.ts` — 新增 globalCenter / globalRadius / recomputeGlobalBounds
- `scene/CameraController.tsx` — 闭包修复，删除硬编码 fallback
- `panels/ViewControls.tsx` — 全部预设改为动态计算
- `panels/TourControls.tsx` — 巡航路径改为基于包围球
- `panels/FloorControls.tsx` — 聚焦调用确保 fov 实时

## 缺陷 4: 爆炸/阶梯模式错位堆叠

### 根因

楼层变换有**三个相互独立的坐标设置机制，彼此冲突**：

#### 4.1 初始位置 vs GSAP 动画目标

```tsx
// FloorLayer 渲染时
<primitive ref={ref} object={scene} position={[0, y, 0]} />  // y = i * 3.2

// useGSAP 触发时
gsap.to(ref.position, { 
  x: -centerOff.x,
  y: targetY - centerOff.y, 
  z: targetZ - centerOff.z,
  duration: 0.8 
});
```

- React 渲染 `<primitive position={[0, y, 0]}>` → Group 的本地 position 起始为 `[0, y, 0]`
- useGSAP 触发时 `gsap.to(ref.position, target)` → 从当前位置动画到目标
- 但 `floorCenters.current` 是异步写入的（在 FloorLayer 的 useEffect 中计算），useGSAP 首次触发时可能尚未填充

#### 4.2 包围盒中心未就绪

`floorCenters.current.get(name)` 在 useGSAP 首次触发时可能返回 `undefined`，fallback 到 `new THREE.Vector3(0,0,0)` → 此时 `targetY - 0 = targetY`，楼层位置不正确。等 `onCenter` 回调写入后又不会自动重新触发 useGSAP（因为它不依赖 `floorCenters` ref）。

#### 4.3 聚焦模式硬编码偏移

```typescript
if (focusedFloor) {
  if (name === focusedFloor) { targetY = 0; }      // 聚焦层放到 y=0
  else if (i > fi) { targetY = 25; }                // 上方层硬编码飞到 y=25
  else { targetY = -10; }                            // 下方层硬编码飞到 y=-10
}
```

聚焦模式下完全不考虑 `centerOff`，导致聚焦层也未居中补偿。

### 修复方案

#### 4.1 统一坐标系统

**删除 `<primitive position={[0, y, 0]}>` 的初始 position，改为全由 ref 驱动**：

```tsx
// FloorLayer: 不设 position（或设为 [0,0,0]）
<primitive ref={ref} object={scene} />

// useGSAP: 首次运行时检测 ref.position 是否已设置
// 若未设置（初始态），直接 set 而非动画
```

或更好的方案：**将 position 管理完全交给 BuildingModel 的 useGSAP**，FloorLayer 完全不设置初始 position。

#### 4.2 确保包围盒就绪后再动画

```typescript
useGSAP(() => {
  floorNames.forEach((name, i) => {
    const ref = refMap.current.get(name);
    const centerOff = floorCenters.current.get(name);
    if (!ref || !centerOff) return; // 包围盒未就绪时跳过，避免错位
    
    // ... 计算 target 并动画
  });
}, [floorMode, focusedFloor, explodeGapV, explodeGapH, floorNames]);
```

同时，当 `floorCenters` 更新后需要**主动触发一次 useGSAP 重新计算**。最简单的方式：在 `registerCenter` 回调中递增一个 `boundsVersion` state 作为 useGSAP 的额外依赖。

#### 4.3 聚焦模式保留 centerOff 补偿

```typescript
// 聚焦模式下也应用 centerOff
if (name === focusedFloor) { 
  targetY = -centerOff.y;      // 居中到 y=0
  targetZ = -centerOff.z;
}
```

#### 4.4 硬件位置设置（动画完成后）

GSAP 动画完成后通过 `onComplete` 同步写入 Zustand 最终态（遵循设计计划 H4 要求的"动画结束后同步 Zustand"）。

### 涉及文件

- `scene/BuildingModel.tsx` — 重构坐标管理 + boundsVersion
- `store/useStore.ts` — 可选的 boundsVersion 递增

## 缺陷 5: 点击地板选中整层模型

### 根因（三层叠加）

子 Agent 排查确认，bug 由三层缺陷叠加触发：

#### 第 1 层：`scene.traverse` 按名匹配 —— 丢弃了 `e.object` 精确引用

```typescript
// 当前：onClick 拿到 e.object（精确引用），但只存 name
setSelectedNode({ name: 'Room_XXX', ... })

// 然后 subscribe 回调中按 name 重新遍历整个 scene
scene.traverse((child: any) => {
  if (child.isMesh && child.name === node.name) {
    child.material.emissive.set('#3b82f6')  // 所有同名 mesh 全亮！
  }
})
```

如果 GLB 中有 N 个名为 `Room_Floor` 的 tile mesh，N 个 tile 全部高亮。更糟的是，若整层地板被命名为 `Room_MainFloor`，它本身就是一个大 mesh → 视觉上"整层亮了"。

#### 第 2 层：共享 `THREE.Material` 实例污染 —— **核心原因**

GLB 导出时多个 mesh 常共享同一个 Material（减少 draw calls）。`materialCache` 系统甚至**主动跨楼层共享材质**。

当代码执行 `child.material.emissive.set('#3b82f6')` 时，修改的是 material 对象本身的属性。如果这个 material 被 **50 个 mesh**（墙、天花板、楼梯...）共享，**50 个 mesh 全部发光**。这就是用户看到"整个模型都亮了"的真正原因。

```typescript
// 验证方法：在浏览器 DevTools 中
meshA.material === meshB.material  // → true（共享！）
```

#### 第 3 层：hover 复位与选中高亮冲突

`onPointerOut` 直接写 `e.object.material.emissive.set('#000000')`。若该 material 被共享，hover 退出会错误清除所有共享 mesh 的 emissive。且未检查当前 mesh 是否就是已选中的 mesh → hover 退出可能清掉选中高亮。

### 修复方案

核心原则：**不按名称重新查找。直接持有 mesh 引用。克隆共享材质。**

```
旧: e.object → name → scene.traverse → material mutation（污染共享材质）
新: e.object → 存到 ref → clone material（如共享）→ 直接操作该 mesh 的独立 material
```

#### 5.1 删除 `useStore.subscribe` + `scene.traverse`

不再在 subscribe 回调中按名遍历整个 scene。高亮逻辑完全内联到 onClick/onPointerOver/onPointerOut 中。

#### 5.2 onClick 中直接持有 mesh 引用 + 解除共享材质

```typescript
onClick={(e: any) => {
  e.stopPropagation();
  const obj = e.object;
  if (!obj?.isMesh) { /* 忽略 Group */ return; }
  
  // 恢复上一个选中 mesh 的 emissive
  if (selectedMeshRef.current && selectedMeshRef.current !== obj) {
    selectedMeshRef.current.material.emissive?.set?.('#000000');
    selectedMeshRef.current.material.emissiveIntensity = 0;
  }

  // 如果该 material 被其他 mesh 共享，clone 一份独立实例
  if (isSharedMaterial(obj)) {
    obj.material = (obj.material as THREE.Material).clone();
  }
  
  // 直接设高亮（不再遍历 scene）
  obj.material.emissive?.set?.('#3b82f6');
  obj.material.emissiveIntensity = 0.3;
  selectedMeshRef.current = obj;
  
  const wp = new THREE.Vector3(); obj.getWorldPosition(wp);
  useStore.getState().setSelectedNode({ name: obj.name, type, worldPos: [wp.x, wp.y, wp.z] });
}}
```

#### 5.3 修复 hover 复位

`onPointerOut` 中先检查 `e.object !== selectedMeshRef.current`，避免清掉选中高亮。对比改为**引用比较**而非名称比较。

#### 5.4 防御：扩展非交互 mesh 的 raycast 禁用

除了 `Wall_` 前缀，对 `Slab_`、`Ceiling_`、`Structure_` 等前缀也设置 `raycast = () => {}`。或反向限制：只对 `Room_`/`Door_`/`Device_` 保留 raycast。

### 涉及文件

- `scene/BuildingModel.tsx` — FloorLayer onClick/hover 重构：删除 subscribe+traverse，改用直接引用+材质克隆
- 新增 `isSharedMaterial()` 工具函数

## 缺陷 6: 选中弹窗卡片定位偏移

### 根因

SceneOverlay 使用的 `worldPos` 来源于 `obj.getWorldPosition()`，存在两个问题：

#### 6.1 用的是 mesh 几何中心，不是点击位置

```typescript
// BuildingModel.tsx onClick — 当前代码
const wp = new THREE.Vector3(); obj.getWorldPosition(wp);
useStore.getState().setSelectedNode({ ..., worldPos: [wp.x, wp.y, wp.z] });
```

`getWorldPosition()` 返回的是被点击 mesh 的**几何中心**（世界坐标）。对于覆盖整层的大地板 mesh，几何中心在房间正中。用户点击地板边缘时，卡片出现在房间中央——完全对不上点击位置。

R3F 的 `e.point` 已经提供了射线命中点的精确世界坐标，但当前代码没使用。

#### 6.2 缺少 Y 轴偏移

```tsx
// SceneOverlay.tsx
<Html position={node.worldPos} center distanceFactor={30}>
```

`center` 使卡片居中于 3D 位置点——卡片直接盖在 mesh 表面。应该向上偏移让卡片浮在模型上方。

#### 6.3 `distanceFactor={30}` 缩放过大

drei 的 `Html` 用 `distanceFactor` 做透视缩放：实际像素大小 = CSS 像素 / (camera_distance / distanceFactor)。distanceFactor=30 意味着在距离 30 单位处卡片为原始 CSS 大小，更近则放大，更远则缩小。结合建筑包围球半径 ~10 单位，镜头通常在 15-40 单位范围，distanceFactor=30 会导致卡片大幅缩放，不协调。

### 修复方案

```typescript
// onClick — 改用 e.point（命中点）+ 向上偏移
onClick={(e: any) => {
  // ...
  const hitPoint = e.point.clone();  // world-space intersection point
  hitPoint.y += 0.5;                  // 向上偏移 0.5 单位，浮在模型上方
  useStore.getState().setSelectedNode({ 
    name: obj.name, type, 
    worldPos: [hitPoint.x, hitPoint.y, hitPoint.z] 
  });
}}
```

```tsx
// SceneOverlay — 降低 distanceFactor
<Html key={node.name} position={node.worldPos} center distanceFactor={15}>
```

### 涉及文件

- `scene/BuildingModel.tsx` — onClick 中 worldPos 改用 `e.point` + Y 偏移
- `scene/SceneOverlay.tsx` — distanceFactor 调整
