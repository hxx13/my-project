## 一、背景

用户报告 4 个 cage-shelves 相关问题：

1. **Bug**：event-log 页面"已存在天数"（两基准间的日期差）计算不正确
2. **Bug**：cage-shelves 主页面配置自动对比/手动对比后，笼位格子上的告警感叹号不显示
3. **Feature**：event-log 需要快照删除管理功能；快照数据源需确认是对比用的快照
4. **Feature**：将 event-log 合并入 special-status 页面，以顶部 tab 分区作为子路由

---

## 二、根因分析（两个子 agent 交叉验证）

### Bug 1 & 2 的共同根因：`currentBatchId` 未被传递到后端

**数据流缺陷**：

```
前端 AdminCageEventLogPage
  ├─ currentBatchId = localStorage("cageCompareCurrent")  ← 用户手动选择的"当前批次"
  ├─ fetchPersistedAlerts(baselineBatchId, mode)            ← 只传了 baseline，没传 current！
  │
后端 CageAlertService.getPersistedAlerts()
  └─ currentBatchId = selectLatestBatchInfo()               ← 始终取最新批次，忽略用户选择
```

**影响**：
- 手动模式：用户选了 current 批次，但后端忽略 → `spanDays` 计算的是 baseline vs latest，非 baseline vs selected → "已存在天数"显示错误
- 自动模式：当 baseline=latest（只有1个批次时 fallback），spanDays=0 → `spanDays < thresholdDays` → 所有告警被过滤 → 感叹号不显示
- 主页面 `AdminCageShelfPage.tsx:377` 同样调 `fetchPersistedAlerts(alertBaselineId, configMode)` → 同受影响

### Bug 2 的次因：告警阈值过滤逻辑

后端 `CageAlertService.java:118`：
```java
if (spanDays < thresholdDays) continue;
```
当 spanDays=0 时，任何 threshold≥1 的告警都会被过滤。这在新数据场景下会导致感叹号完全不显示。

### Feature 1 快照数据源确认

经核实，`snapshot-batches` 端点查询 `cage_special_status_snapshot` 表（`CageSpecialStatusSnapshotMapper.xml:138-148`），与 `CageAlertService.getPersistedAlerts()` 使用的表完全相同。**快照数据源已是对比用的快照，无需切换。** 但缺少删除功能。

### Feature 2 alertMap 键格式一致性

前端 agent 验证了键匹配路径：

- 存：`alertMap.set(${a.shelveId}:${a.position})` — a.position 来自后端 `snap.getPositionLabel()`
- 取：`alertMap.get(${sid}:${c.position})` — c.position 来自后端 `positionLabel || ${String.fromCharCode(64+x)}-${y}`

两者都使用 `positionLabel` 字段，格式一致。合并不会引入新问题。

## 四、边缘情况与风险

| 风险 | 缓解措施 |
|------|---------|
| `currentBatchId` 不存在的批次 | `selectAllByBatchId` 返空列表 → spanDays=0 → 返回空告警（不崩溃） |
| 删除唯一快照 | 返回空 batchList → 所有 tab 显示空态引导 |
| 删除正在使用的对比批次 | 前端检测 → toast 提示"无法删除当前对比使用的批次" |
| DELETE 部分失败（快照删了但事件日志未删） | `@Transactional` 保证原子性 |
| 4 个 tab 同时加载过多请求 | `enabled` 门控只加载当前 tab；batchList/alertData 父级共享避免重复请求 |
| Tab 状态刷新丢失 | URL search param `?tab=xxx` 持久化 |
