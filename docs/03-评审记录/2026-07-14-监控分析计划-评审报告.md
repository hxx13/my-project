## 🔴 CRITICAL（共 5 项 — 实施会产生错误结果）

### C1. `getSnapshot()` 将错误的 Map 传入 Snapshot 字段

**位置**: Task 1 Step 1, `getSnapshot()` 方法 (L121-131)

```java
new Snapshot(
    totalRequests.sum(),
    uniqueVisitorCount(),
    copyStatusDistribution(),
    copyResponseTimeBuckets(),
    topN(statusCounts, 10),   // ← 传给 topUrls，但这是状态码 Map！
    topN(urlCounts, 10),      // ← 传给 top404Urls，但无 404 过滤！
    topN(uaCounts, 5)
);
```

- **`topUrls`** 收到的是 `{"200": 4891, "404": 312}` — 状态码当作 URL 路径
- **`top404Urls`** 收到的是全部 URL 排行，未过滤 status==404
- **根因**: 交换了数据源（`statusCounts` ↔ `urlCounts`），且 404 URL 根本没有独立追踪

**三审一致**: 本人 ✓ | Agent#1 ✓ | Agent#2 ✓

---

### C2. `topN()` 通用方法 key 名永远为 `"ua"`

**位置**: Task 1 Step 1, `topN()` 方法 (L186)

```java
m.put(e instanceof Map.Entry ? "ua" : "path", String.valueOf(e.getKey()));
```

`ConcurrentHashMap.entrySet().stream()` 每个元素都是 `Map.Entry`，条件永真 → 所有条目 key 都是 `"ua"`。

- URL 排行本应是 `{"path": "/api/...", "count": N}`，实际输出 `{"ua": "/api/...", "count": N}`
- 前端 `RankingCard` 用 `keyField="path"` 查找 → `item["path"]` = `undefined` → 渲染空白

计划 TODO 承认此问题但标注为 "implementation-level fix"，未在交付代码中修复。

**三审一致**: 本人 ✓ | Agent#1 ✓ | Agent#2 ✓

---

### C3. 404 URL 排行功能无数据采集机制

**位置**: Task 1, `afterCompletion()` (L74-119)

Spec 要求 `top404Urls`，前端 `AnalyticsSnapshot` 定义了该字段，计划 `Snapshot` record 声明了该字段 — 但拦截器 `afterCompletion()` 中**从未按 status==404 条件单独记录 URL**。

需要新增:
```java
ConcurrentHashMap<String, LongAdder> url404Counts = new ConcurrentHashMap<>();
// 在 afterCompletion() 中:
if (status == 404) {
    url404Counts.computeIfAbsent(normalized, k -> new LongAdder()).increment();
}
```

当前实现完全无法产生 404 URL 排行数据。

**三审一致**: 本人 ✓ | Agent#1 ✓ | Agent#2 ✓

### C4. 后续轮询无过期数据指示器

**位置**: Task 7 Step 1, `MonitorAnalyticsCards` 状态守卫 (L583)

```typescript
if (loading && !analytics) { return <MonitorAnalyticsSkeleton />; }
```

首次加载后 `analytics` 非 null。后续 5 分钟轮询时 `analyticsLoading=true` 但组件**静默显示过期数据**，无任何加载中指示。对比现有 `ClientVersionCard` 显示 "加载中..."。

**三审一致**: 本人 ✓ | Agent#1 — | Agent#2 ✓

### C5. 错误态在有过期数据时静默吞错

**位置**: Task 7 Step 1 (L588)

```typescript
if (error && !analytics) { return <ErrorCard />; }
```

首次成功 → 第二次失败 → `analytics` 非 null → 显示过期数据，**错误被完全隐藏**。用户不知道数据可能过期、不知道出了问题。应有非阻塞错误提示（banner/toast）。

**三审一致**: 本人 ✓ | Agent#1 — | Agent#2 ✓

## 🟠 HIGH（共 7 项 — 明显缺陷/违规）

### H1. `refreshAll()` 未包含 `fetchAnalytics` — 手动刷新跳过分析数据

**位置**: Task 8 Step 3 + [MonitorDashboardPage.tsx:101](frontend/src/features/admin/monitor/MonitorDashboardPage.tsx#L101)

```typescript
const refreshAll = () => { fetchAll(); fetchTimers(); fetchTimerHistory(); fetchSessions(); };
// fetchAnalytics() 缺失！
```

点击"手动刷新"按钮 → 健康/资源/任务/计时器/会话全部刷新 → **唯独分析数据不刷新**。用户只能等最多 5 分钟。

**建议**: `refreshAll` 中加入 `fetchAnalytics()`。

**三审一致**: 本人 ✓ | Agent#1 ✓ | Agent#2 ✓

---

### H2. `--app-radius-sm` 设计令牌不存在

**位置**: Task 7 Step 3-4, L689 & L732

```css
rounded-[var(--app-radius-sm)]  /* 该变量未定义 → 圆角解析为 0 */
```

`semantic.css` 仅定义了 `--app-radius-container` / `--app-radius-element` / `--app-radius-pill`。`--app-radius-sm` 不存在，CSS 回退到 initial value `0` → 条形图渲染为**尖角**。

**建议**: 改用 `--app-radius-element`（8px）或 `--app-radius-pill`。

**发现方**: Agent#2

---

### H3. `role="progressbar"` 语义错误

**位置**: Task 7 Step 3, `StatusBar` 组件 (L725-731)

`progressbar` 表示有可测量完成度的进行中任务（如文件上传），状态码分布图是**静态快照**。屏幕阅读器会读成"X percent complete"造成困惑。

**建议**: 改为 `role="img"` + `aria-label`，与上方直方图一致。

**发现方**: Agent#2

---

### H4. Plan 与 Spec 布局位置矛盾

- **Plan Task 8 Step 2**: 插入在 `<ClientVersionCard />` 和 `<MonitorResourceGauges />` **之间**
- **Spec §3.4**: "在 `<MonitorResourceGauges />` **下方**加入"

**建议**: 以 Spec 为准——放在 ResourceGauges 下方、ActiveSessionsSection 上方。

**发现方**: Agent#2

---

### H5. `copyResponseTimeBuckets()` 每次快照分配 8 个废弃 LongAdder

**位置**: Task 1 Step 1, L167-178

```java
m.put("0-10", responseTimeBuckets.getOrDefault("0-10", new LongAdder()).sum());
```

缺失 bucket 时创建一次性 `LongAdder` 对象仅为了调用 `.sum()` 返回 0。虽开销小但模式错误。

**建议**: null 检查后返回 0L。

**发现方**: 本人 + Agent#1

---

### H6. `parseInt(String(statusDist["200"] ?? 0), 10)` 无意义双重转换

**位置**: Task 7 Step 2, L622

`statusDist` 类型为 `Record<string, number>`，值已是 number。`String()` + `parseInt()` 是无效往返。

**建议**: 直接用 `Number(statusDist["200"] ?? 0)` 或 `statusDist["200"] ?? 0`。

**发现方**: Agent#1 + Agent#2

---

### H7. 分析区块缺少标题

**位置**: Task 7 + Task 8

OverviewTab 中每个 section 都有标题（`<h3>系统健康</h3>` / `<h3>活跃连接</h3>`），分析区块没有。用户扫描页面时缺少上下文标签。

**建议**: 添加 `<h3>访问分析</h3>`。

**发现方**: Agent#2
