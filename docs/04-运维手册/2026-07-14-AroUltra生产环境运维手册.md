> **版本**: v3.0（三轮 agent 复审修正） | **日期**: 2026-07-14 | **服务器**: 10.127.139.31 | **域名**: aroultra.shsmu.edu.cn

## ⚠️ 关键警告（必读）

| 警告 | 后果 |
|------|------|
| **启动 JAR 必须加 `--spring.profiles.active=prod`** | 不加则 logback 无 appender，JAR 秒退（踩坑记录 #1） |
| **当前用 `nohup`，不是 systemd** | JAR 崩溃后**不会自动重启**，需要人工发现并手动重启 |
| **密码在命令行上明文传递** | `ps aux` 可见 `--spring.datasource.password=...`。后续改为环境变量 `DB_PASSWORD` |
| **以下命令交替使用 `sudo`** | 服务管理命令以 root 执行为准；nginx 操作需要 sudo |
| **SELinux 可能阻止 nginx 连接后端** | 首次部署后若 502，执行 `setsebool -P httpd_can_network_connect on` |

### 2.2 完整配置（逐项注释）

```nginx
# ═══════════════════════════════════════════════════════════════
# WebSocket 升级映射：仅在客户端请求升级时才发送 Upgrade 头
# 解决 Socket.IO 长轮询降级兼容性问题
# ═══════════════════════════════════════════════════════════════
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

# ═══════════════════════════════════════════════════════════════
# HTTP → HTTPS 强制跳转
# ═══════════════════════════════════════════════════════════════
server {
    listen 80;
    # 仅匹配域名。IP 访问会落到 nginx 默认 server，统一返回 444
    server_name aroultra.shsmu.edu.cn;
    return 301 https://aroultra.shsmu.edu.cn$request_uri;
}

# ═══════════════════════════════════════════════════════════════
# HTTPS 主站点
# ═══════════════════════════════════════════════════════════════
server {
    listen 443 ssl;                               # nginx ≥1.25.1 后改用 http2 on;
    server_name aroultra.shsmu.edu.cn;

    # ── SSL 证书 ──
    ssl_certificate     /usr/local/nginx/certs/2026/shsmu.edu.cn_with_chain.crt;
    ssl_certificate_key /usr/local/nginx/certs/2026/shsmu.edu.cn.key;

    # ── SSL 安全策略 ──
    ssl_protocols TLSv1.2 TLSv1.3;                # 禁用 TLS 1.0/1.1
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:1m;              # 1MB ≈ 4000 会话
    ssl_session_timeout 1h;                       # 从原 5m 改为 1h，提升缓存命中率

    # ── 上传限制 ──
    client_max_body_size 100m;

    # ── Gzip 压缩 ──
    gzip on;
    gzip_comp_level 5;
    gzip_min_length 256;
    gzip_types application/javascript application/json text/css text/plain image/svg+xml;
    gzip_vary on;

    # ── 安全响应头（server 级别，子 location 会继承） ──
    add_header X-Frame-Options "SAMEORIGIN" always;         # 防点击劫持
    add_header X-Content-Type-Options "nosniff" always;     # 防 MIME 嗅探
    # 注意：不使用 X-XSS-Protection（已废弃，Chrome/Firefox 均移除）。
    #       现代替代方案是 Content-Security-Policy（未来补充）。

    # ── 主应用代理 ──
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;            # $host 而非 $http_host（避免大小写/注入）
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_connect_timeout 60s;
        proxy_send_timeout 300s;
        # proxy_buffering 默认 on——对大文件和慢客户端友好。
        # SSE/流式端点由后端设置 X-Accel-Buffering: no 按需关闭。
    }

    # ── 静态资源缓存 ──
    # /assets/ 下的 JS/CSS 文件名带内容 hash，可长期缓存。
    # 注意：子 location 的 add_header 会覆盖父级 add_header，此处显式合并。
    location /assets/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        # 不使用 expires 指令（会生成重复 Cache-Control）
        add_header Cache-Control "public, max-age=604800, immutable";
        # 重新声明安全头（子 location 覆盖父级 add_header）
        add_header X-Frame-Options "SAMEORIGIN" always;
        add_header X-Content-Type-Options "nosniff" always;
    }

    # ── 登录接口限流 ──
    # 每 IP 每秒最多 5 次，突发允许 3 次排队。必须放 server 块内部。
    location /api/auth/ {
        limit_req zone=auth burst=3 nodelay;
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    # ── Socket.IO WebSocket 代理 ──
    # 使用 map 变量兼容：真正的 WebSocket 握手发 Upgrade，长轮询发 close
    location /socket.io/ {
        proxy_pass http://127.0.0.1:9092;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;   # map 变量
        proxy_read_timeout 86400s;
    }

    # ── 扩展点位（按需取消注释） ──
    # 宝塔面板：  location /bt/  { proxy_pass https://127.0.0.1:15701/; }
    # CosyVoice： location /tts/ { proxy_pass http://127.0.0.1:50000/;  }
    # 静态资源独立目录： root /opt/twin/static; try_files $uri $uri/ /index.html;
}
```

### 2.3 限流定义文件

```nginx
# /etc/nginx/conf.d/aroultra-limit.conf
# 被 nginx.conf 的 include 指令加载

limit_req_zone $binary_remote_addr zone=auth:10m rate=5r/s;   # 登录：5 次/秒
limit_req_zone $binary_remote_addr zone=api:10m rate=30r/s;   # API：30 次/秒
```

部署命令：

```bash
sudo tee /etc/nginx/conf.d/aroultra-limit.conf << 'EOF'
limit_req_zone $binary_remote_addr zone=auth:10m rate=5r/s;
limit_req_zone $binary_remote_addr zone=api:10m rate=30r/s;
EOF
sudo nginx -t && sudo nginx -s reload
```

**注意**：以上配置中的 `location /api/auth/` 块已直接写在 §2.2 的 server 块内部，无需用 `tee -a` 追加。

## 三、日志管理

### 3.1 nginx 日志路径配置

默认路径（由 nginx 包管理）：

| 日志 | 路径 | 内容 |
|------|------|------|
| access | `/var/log/nginx/access.log` | 所有请求 |
| error | `/var/log/nginx/error.log` | 错误 + 告警 |

如需按站点分离，在 server 块内加：

```nginx
access_log /var/log/nginx/aroultra_access.log;
error_log  /var/log/nginx/aroultra_error.log warn;
```

### 3.2 logrotate

```bash
sudo tee /etc/logrotate.d/aroultra << 'EOF'
/var/log/nginx/*.log {
    daily
    rotate 30
    missingok
    notifempty
    compress
    delaycompress
    sharedscripts
    postrotate
        /usr/bin/kill -USR1 $(cat /run/nginx.pid 2>/dev/null) 2>/dev/null || true
    endscript
}
EOF
```

> **以下命令以 root 身份执行。** JAR 进程属主为 root。

### 6.1 JAR 生命周期

```bash
# 启动
nohup java -jar /opt/twin/app/demo-*.jar --server.port=8080 --spring.profiles.active=prod --spring.datasource.password=SuperAdmin@2026 > /tmp/jar.log 2>&1 &

# 优雅重启（SIGTERM，等待 20 秒）
pkill -15 -f 'demo-.*\.jar' && sleep 20 && nohup java -jar /opt/twin/app/demo-*.jar --server.port=8080 --spring.profiles.active=prod --spring.datasource.password=SuperAdmin@2026 > /tmp/jar.log 2>&1 &

# 强制杀

# 检查运行状态
ps aux | grep 'demo-.*\.jar' | grep -v grep
ss -tlnp | grep 8080
```

### 6.2 完整部署流程

```bash
# 步骤 1：上传新 JAR（通过堡垒机 SFTP → /home/aroadmin/）
# 步骤 2：备份旧 JAR
sudo cp /opt/twin/app/demo-*.jar /opt/twin/app/demo-previous.jar.bak

# 步骤 3：替换 JAR
sudo rm -f /opt/twin/app/demo-*.jar
sudo mv /home/aroadmin/demo-*.jar /opt/twin/app/

# 步骤 4：重启
sudo pkill -15 -f 'demo-.*\.jar'
sleep 20
sudo nohup java -jar /opt/twin/app/demo-*.jar --server.port=8080 --spring.profiles.active=prod --spring.datasource.password=SuperAdmin@2026 > /tmp/jar.log 2>&1 &

# 步骤 5：验证
sleep 30
curl -sk -o /dev/null -w "%{http_code}" https://localhost -H "Host: aroultra.shsmu.edu.cn"
# 应返回 200

# 步骤 6：如失败，回滚
sudo pkill -9 -f 'demo-.*\.jar'
sudo mv /opt/twin/app/demo-*.jar /tmp/demo-failed.jar
sudo mv /opt/twin/app/demo-previous.jar.bak /opt/twin/app/demo-$(date +%Y%m%d-%H%M%S).jar
# 然后重新启动旧 JAR

# 步骤 7：确认旧前端缓存不冲突
# JAR 构建版本由 build-meta.json 管理，WebSocket 连接时自动比对，
# 版本不匹配会触发客户端自动刷新
```

### 7.2 崩溃检测（cron 脚本骨架）

```bash
#!/bin/bash
# /opt/twin/scripts/health-check.sh — 每分钟 cron 执行

FAILS=0
for port in 80 443 8080 3306; do
    ss -tlnp | grep -q ":$port " || { echo "[$(date)] PORT $port DOWN" >> /var/log/twin/health.log; ((FAILS++)); }
done

# 连续 3 次失败才告警（避免误报）
if [ $FAILS -gt 0 ]; then
    RECENT=$(tail -3 /var/log/twin/health.log | grep -c "$(date +%Y-%m-%d)")
    [ $RECENT -ge 3 ] && echo "ALERT: $FAILS ports down at $(date)"
fi
```

## 九、踩坑记录

| # | 现象 | 根因 | 解法 |
|---|------|------|------|
| 1 | JAR 秒退，仅一行 Logback WARN | 未指定 `spring.profiles.active`，logback 所有 appender 都在 springProfile 内 | 加 `--spring.profiles.active=prod` |
| 2 | `Unknown time zone: 'Asia/Shanghai'` | MariaDB 缺少时区数据 | `mysql_tzinfo_to_sql /usr/share/zoneinfo \| mysql mysql` |
| 3 | 多个 bean `Table 'twin_system.sys_system_config_def' doesn't exist` | DDL 执行时机晚于 @PostConstruct | `schema.sql` 提前建表 + 6 个 bean 加 try-catch |
| 4 | 登录 `Invalid CORS request` 403 | CORS 未放行生产域名 | `WebMvcConfig.java` 加 `https://aroultra.shsmu.edu.cn` |
| 5 | 数据导入 `utf8mb4_0900_ai_ci` 报错 | MariaDB 不支持 MySQL 8.0 排序规则 | `sed` 替换为 `utf8mb4_unicode_ci` |
| 6 | 外键约束阻止建表 | dump 中建表顺序与依赖不匹配 | `mysql --force` + `--no-create-info` |
| 7 | Docker 镜像拉取超时 | 校园网屏蔽 Docker Hub | 裸机 MariaDB 替代 Docker MySQL |
| 8 | SSH 直连/浏览器直访 `10.127.139.31` 超时 | VLAN 隔离 | 仅通过堡垒机访问 |

## 十、备份

```bash
#!/bin/bash
# /opt/twin/scripts/backup.sh — 每日凌晨 3 点 cron
BACKUP_ROOT=/opt/twin/backups
DATE=$(date +%Y%m%d)
mkdir -p $BACKUP_ROOT/$DATE

# 数据库全量
mysqldump -u root -p'SuperAdmin@2026' --single-transaction --routines --triggers --all-databases | gzip > $BACKUP_ROOT/$DATE/mysql-all.sql.gz

# 上传文件增量
rsync -av --delete /opt/twin/data/ $BACKUP_ROOT/$DATE/data/ 2>/dev/null

# 保留 30 天
find $BACKUP_ROOT -maxdepth 1 -type d -mtime +30 -exec rm -rf {} \;
echo "[$(date)] Backup done" >> /var/log/twin/backup.log
```

恢复：`zcat mysql-all.sql.gz | mysql -u root -p'SuperAdmin@2026'`
