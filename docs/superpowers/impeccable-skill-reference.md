## 1. 概述与技能架构

Impeccable 是一个前端设计品质系统，确保 AI 生成的 UI 代码达到生产级标准。它与 Bento 设计系统配合使用，分工明确：

- **Bento** 管"用什么令牌"（设计令牌/组件库）
- **Impeccable** 管"做的够不够好"（品质规则/对比度/排版/布局/动效/反模式）

## 2. 会话初始化（Setup）

每次会话开始时必须执行以下步骤：

### 步骤 1：运行 context.mjs

```bash
node .claude/skills/impeccable/scripts/context.mjs --target frontend/src/
```

- 输出 `NO_PRODUCT_MD` → 按 `reference/init.md` 流程初始化
- 输出 `UPDATE_AVAILABLE` → 询问用户是否更新

### 步骤 2：加载子命令参考

如果用户调用了特定子命令（`craft`, `shape`, `audit`, `polish` 等），必须先读取对应的 `reference/<command>.md`。

### 步骤 3：熟悉现有设计系统

读取至少一个项目文件（CSS / tokens / theme / 代表性组件）。

### 步骤 4：读取匹配的注册表

- **产品 UI**（后台/仪表盘/工具/设置面板）→ `reference/product.md`
- **品牌 UI**（营销/落地页/作品集/长文内容）→ `reference/brand.md`

### 步骤 5：运行 palette.mjs（仅新项目）

```bash
node .claude/skills/impeccable/scripts/palette.mjs
```

仅在项目没有已提交的品牌颜色时运行。使用 OKLCH 色彩空间。

### 完成后确认语

> "已读取 UI 设计规范 + Bento 设计系统 + Impeccable 设计品质 v3.9。当前配色：[项目配色]。所有颜色通过语义令牌引用。Impeccable 品质规则（对比度 ≥4.5:1、行宽 65-75ch、语义 z-index、prefers-reduced-motion）将在本次会话中自动执行。"

## 3. 通用设计规则

### 色彩

- **验证对比度。** 正文 vs 背景 ≥ 4.5:1；大号文字（≥18px 或 bold ≥14px）≥ 3:1
- placeholder 文字同样需要 4.5:1，不能用默认灰色
- 灰色文字放有色背景上会显脏 → 用背景色相更深色阶的值，或文字色的透明度

### 排版

- 正文行宽上限 **65–75ch**
- 非衬线 + 非衬线配对必须选对比轴（几何 vs 人文/怪诞）
- Hero/展示标题 `clamp()` max ≤ **6rem**；letter-spacing ≥ **-0.04em**
- h1–h3 用 `text-wrap: balance`；长文用 `text-wrap: pretty`

### 布局

- 间距要有节奏变化，不均匀等距
- 卡片不是默认方案。能用列表/分组/分割区域就不用卡片。嵌套卡片永远错误
- Flexbox 用于 1D，Grid 用于 2D。不要默认 Grid 当 `flex-wrap` 更简单的时候
- 无断点响应式 Grid：`repeat(auto-fit, minmax(280px, 1fr))`
- 构建语义 z-index 阶梯：dropdown → sticky → modal-backdrop → modal → toast → tooltip。永远不要 999/9999

### 动效

- 动效必须有意图，不是事后点缀
- 不动画 CSS 布局属性（width/height/top/left）除非确有必要
- 缓出用指数曲线（ease-out-quart/quint/expo）。不用 bounce/elastic
- **`prefers-reduced-motion: reduce` 不可跳过**
- 列表交错动画是合法的；禁止的是"每个 section 用完全相同的入场动画"
- 入场动画不能成为内容可见性的门控
- 产品 UI 过渡 150-250ms，动效传达状态变化，非装饰

### 交互

- `position: absolute` 的下拉菜单在 `overflow: hidden/auto` 容器内会被裁剪。使用原生 `<dialog>` / popover API、`position: fixed` 或 portal 来逃脱层叠上下文

## 4. 绝对禁令（Absolute Bans）

以下任何一项出现 → 直接判定不合格 → 重写：

| 反模式 | 说明 |
|--------|------|
| **侧边竖线装饰** | `border-left/right > 1px` 作为卡片/列表的彩色强调线 |
| **渐变文字** | `background-clip: text` + 渐变背景 |
| **玻璃态默认** | 毛玻璃/blur 卡片做默认装饰 |
| **hero-metric 模板** | 大数字 + 小标签 + 辅助数据 + 渐变强调（SaaS 陈词滥调） |
| **千篇一律卡片网格** | 相同尺寸卡片（图标 + 标题 + 文字）无限重复 |
| **每段都加眉标** | 小字号全大写 tracking-wide "ABOUT / PROCESS / PRICING" 挂在每个标题上方 |
| **01/02/03 编号段** | 每个 section 前面都标序号——只有真正有序流程/步骤才配序号 |
| **文字溢出容器** | 长标题 + 大 clamp + 窄 Grid = 平板/手机溢出。每个断点都要测 |

### 新项目特有限制

- **奶油色/沙色/米色背景体** 是 2026 年饱和的 AI 默认值。暖中性色带（OKLCH L 0.84-0.97, C < 0.06, hue 40-100）都是变体
- 带色中性色：向品牌色相添加 0.005–0.015 chroma，不要默认向暖或向冷
- 选择主题前写一句物理场景句：谁用、在哪、什么环境光、什么心情

## 5. AI Slop 检测

### 一阶检测

仅凭"这是什么品类"就能猜到配色/主题？→ 重做场景句和色彩策略

### 二阶检测

品类 + "不是XX风格"就能猜到审美家族？→ 第一层避开了，第二层没避开，重做到两层都不显然

**检测通过标准**：用户看到这个界面时，无法毫不犹豫地说"这是 AI 做的"。

## 6. 色彩系统

### 色彩空间：使用 OKLCH

停止使用 HSL。OKLCH 是感知均匀的，等步长的亮度看起来是等步长的。

```
oklch(lightness chroma hue)
```

- lightness: 0-100%
- chroma: 约 0-0.4
- hue: 0-360

构建主色及其变体：保持 chroma+hue 大致不变，变化 lightness，但在接近白色或黑色时减少 chroma。

### 色彩策略（四个承诺等级）

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| **Restrained（克制）** | 带色中性 + 一个强调色 ≤10% | 产品默认；品牌极简 |
| **Committed（承诺）** | 一个饱和色承载 30–60% 表面 | 品牌默认 |
| **Full palette（全调色板）** | 3–4 个命名色彩角色 | 品牌营销；产品数据可视化 |
| **Drenched（沉浸）** | 表面就是色彩 | 品牌英雄页；营销页面 |

### 带色中性色

纯灰已死。向所有中性色添加 0.005–0.015 chroma，色相朝向品牌色。

### 60-30-10 规则（正确用法）

关于**视觉权重**，不是像素数：
- **60%**：中性背景、留白、基础表面
- **30%**：次要色彩：文字、边框、非活跃状态
- **10%**：强调色：CTA、高亮、焦点状态

### WCAG 对比度要求

| 内容类型 | AA 最低 | AAA 目标 |
|----------|---------|----------|
| 正文 | 4.5:1 | 7:1 |
| 大文字（18px+ 或 14px bold） | 3:1 | 4.5:1 |
| UI 组件、图标 | 3:1 | 4.5:1 |

### 暗色模式

暗色模式不是反转亮色模式。关键差异：

| 亮色模式 | 暗色模式 |
|----------|----------|
| 阴影表示深度 | 更亮的表面表示深度（无阴影） |
| 深色文字浅色背景 | 浅色文字深色背景（减少字重） |
| 鲜艳强调色 | 稍微去饱和强调色 |
| 白色背景 | 纯黑或品牌色深色（oklch 12-18%） |

## 7. 排版系统

### 产品 UI 排版

- **一个字体族通常就够了。** 产品 UI 不需要 display/body 配对
- **固定 rem 阶梯，非流体。** clamp 大小的标题不适合产品 UI
- **更紧凑的比例。** 步进比 1.125–1.2
- **行宽仍然适用：** 正文 65–75ch；数据/表格可放宽至 120ch

### 品牌 UI 排版

#### 字体选择流程（每次必做）

1. 写出三个具体的品牌声音词。不要"modern"或"elegant"，要"温暖且机械且固执"或"冷静且临床且细致"
2. 列出你会直觉选用的三个字体。如果出现在 Reflex-reject 列表中，拒绝它们
3. 浏览真实字体目录，找到品牌的*物理对象*：博物馆说明牌、1970年代终端手册、布料标签、廉价新闻纸童书、音乐会海报、中世纪餐厅收据
4. 交叉检查。"优雅"不一定是衬线。"技术"不一定是无衬线。"温暖"不是 Fraunces

#### Reflex-reject 字体列表

训练数据默认值。禁止列表：

Fraunces · Newsreader · Lora · Crimson · Crimson Pro · Crimson Text · Playfair Display · Cormorant · Cormorant Garamond · Syne · IBM Plex Mono · IBM Plex Sans · IBM Plex Serif · Space Mono · Space Grotesk · Inter · DM Sans · DM Serif Display · DM Serif Text · Outfit · Plus Jakarta Sans · Instrument Sans · Instrument Serif

#### Reflex-reject 审美路线

- **编辑排版（Editorial-typographic）**：展示衬线（常为斜体）+ 小号等宽标签 + 规则分隔线 + 单色克制。到 2026 年，每个 Stripe 和 Notion 相邻品牌都落在这里。

## 8. 布局系统

### 间距系统

- 使用一致的间距刻度（推荐 4pt 基数：4, 8, 12, 16, 24, 32, 48, 64, 96px）
- 语义化命名：`--space-xs` 到 `--space-xl`
- 使用 `gap` 代替 margin 处理兄弟元素间距
- 使用 `clamp()` 实现流体间距

### 视觉节奏

- **紧凑分组**：相关元素间距 8-12px
- **宽松分隔**：不同区块间距 48-96px
- **变化间距**：区块内不均匀等距

### 选择合适的布局工具

- **Flexbox**：1D 布局（导航栏、按钮组、卡片内容）
- **Grid**：2D 布局（页面结构、仪表盘、数据密集界面）
- **容器查询**：组件用 container queries，页面布局用 viewport queries

### 打破卡片网格单调

- 不要默认把所有东西放进卡片网格
- 只在内容真正独立且可操作时使用卡片
- 变化卡片大小、跨列、或混合卡片与非卡片内容
- 永远不要嵌套卡片

### 视觉层级强化

| 工具 | 强层级 | 弱层级 |
|------|--------|--------|
| **大小** | 3:1 比例或更高 | <2:1 比例 |
| **字重** | Bold vs Regular | Medium vs Regular |
| **色彩** | 高对比度 | 相似色调 |
| **位置** | 顶部/左侧（主要） | 底部/右侧 |
| **空间** | 被留白包围 | 拥挤 |

### 光学调整

- 图标视觉不正中但几何居中时，微调
- 文本 `margin-left: 0` 因字母空白看起来略微缩进 → `-0.05em`
- 触摸目标最小 44×44px

## 9. 动效系统

### 时长：100/300/500 规则

| 时长 | 用例 | 示例 |
|------|------|------|
| **100–150ms** | 即时反馈 | 按钮按下、开关、色彩变化 |
| **200–300ms** | 状态变化 | 菜单打开、tooltip、hover 状态 |
| **300–500ms** | 布局变化 | 手风琴、模态框、抽屉 |
| **500–800ms** | 入场动画 | 页面加载、hero 揭示 |

退出动画比入场快 ~25%（约 75% 入场时长）。

### 缓动曲线（使用这些，不用 CSS 默认值）

```css
--ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);    /* 平滑 */
--ease-out-quint: cubic-bezier(0.22, 1, 0.36, 1);   /* 稍干脆 */
--ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);     /* 自信、果断 */

/* 避免：感觉过时和俗气 */
/* bounce: cubic-bezier(0.34, 1.56, 0.64, 1); */
/* elastic: cubic-bezier(0.68, -0.6, 0.32, 1.6); */
```

### 动效素材

- **Transform / opacity**：移动、按压反馈、简单揭示、列表编排
- **Blur / filter / backdrop-filter**：焦点拉近、深度、玻璃/镜头效果
- **Clip-path / masks**：擦拭、揭示、编辑裁剪
- **Shadow / glow / color filters**：能量、可供性、焦点、温暖
- **Grid-template-rows 或 FLIP 风格变换**：扩展和重排布局而不直接动画 `height`

### 感知性能

- **抢先开始**：立即开始过渡（iOS 应用缩放、骨架屏 UI）
- **提前完成**：渐进式显示内容（渐进图像、流式 HTML、骨架淡入）
- **乐观 UI**：立即更新界面，优雅处理失败
- **缓动影响感知时长**：缓入使任务感觉更短（峰终效应权重最终时刻）

### 无障碍

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 10. 交互设计

### 下拉菜单

使用 `position: absolute` 的下拉菜单在 `overflow: hidden` 或 `overflow: auto` 容器内会被裁剪。使用原生 `<dialog>` / popover API、`position: fixed` 或 portal 来逃脱层叠上下文。

### 组件状态

每个交互组件必须有完整七态：

1. **default** — 静止态
2. **hover** — 微妙反馈
3. **focus** — 键盘焦点指示器
4. **active** — 点击/触摸反馈
5. **disabled** — 明确不可交互
6. **loading** — 骨架屏（非居中 spinner）
7. **error** — 验证或错误状态

### 空状态

空状态要教用户怎么用，不是"暂无数据"。

### 一致性

同一产品内保持一致 affordance：同样的按钮形态、同样的表单控件词汇、同样的图标风格。不要为了"风格"重造标准控件。

## 11. 产品注册表（Product Register）

当设计**服务**产品：应用 UI、后台仪表盘、设置面板、数据表格、工具、认证后界面。

### 产品 Slop 测试

不是"有人会说 AI 做的吗"。熟悉感在这里通常是特性。测试是：一个熟悉该品类最佳工具的用户坐下来会信任这个界面吗，还是在每个微妙不合的组件上停顿？

### 排版

- 一个字体族通常够了
- 固定 rem 刻度，非流体
- 步进比 1.125–1.2
- 正文行宽 65–75ch；表格可放宽至 120ch

### 色彩

产品默认为 Restrained（克制）。建立状态丰富的语义词汇：
hover, focus, active, disabled, selected, loading, error, warning, success, info。

### 组件

- 骨架屏用于加载态，不是居中 spinner
- 空状态教用户怎么用
- 一致的可供性

### 动效

- 150–250ms 过渡
- 动效传达状态，非装饰
- 禁止编排页面加载序列

### 产品禁令

- 不传达状态的装饰性动效
- 屏幕间不一致的组件词汇
- UI 标签/按钮/数据中使用展示字体
- 为风格重造标准可供性
- 非活跃状态上使用重色或全饱和强调色
- 模态框作为第一反应（模态框通常是懒惰；先穷尽内联/渐进式替代方案）

## 12. 品牌注册表（Brand Register）

当设计**就是**产品：品牌网站、落地页、营销页面、营销活动页、作品集、长文内容、关于页面。

### 品牌 Slop 测试

如果有人看到后毫不犹豫地说"AI 做的"，就失败了。标准是独特性；访客应该问"这是怎么做的？"而不是"哪个 AI 做的？"

### 排版

- **字体选择流程**（见 §7 排版系统）
- 两个字体族是最低要求*仅当*声音需要时
- 模块化刻度，流体 `clamp()`，步进 ≥1.25

### 色彩

品牌界面有权使用 Committed、Full palette 和 Drenched 策略。

- 在选择策略之前命名一个真实的参考
- 调色板就是声音
- 当策略是 Committed 或 Drenched 时，不要用中性色在边缘对冲
- 不要在项目之间趋同

### 图像

品牌界面依赖图像。一个没有图像的餐厅/酒店/杂志/产品落地页读起来是不完整的。

- 使用 Unsplash：`https://images.unsplash.com/photo-{id}?auto=format&fit=crop&w=1600&q=80`
- **在使用前验证 URL**
- 搜索品牌的物理对象，不是通用类别
- 一张果断的照片胜过五张平庸的

### 品牌禁令

- 等宽字体作为"技术/开发者"的懒惰缩写
- 每个标题上方的大圆角图标
- 全大写正文
- 胆小的调色板和平均的布局
- 零图像（当简报暗示需要图像时）
- 默认编辑杂志美学

### craft — 构建功能

完整构建流程：shape 设计 → 确定视觉方向 → 编写生产代码 → 浏览器中检查和改进。

#### 流程门控

1. **Shape 简报确认** → 方向问题回答 → 调色板确认 → 一个设计方向批准或委托
2. Shape 确认**不等于**编码绿灯。压缩门控是 craft 流程最主要的失败模式

#### 生产标准

- **真实内容** — 无占位符文案、占位符图像、死链接
- **语义优先** — 真实标题、地标、标签、表单关联、无障碍名称
- **刻意间距和对齐** — 无默认间距或任意边距
- **有意图的排版** — 清晰的层级、可读的度量、稳定的换行
- **现实状态覆盖** — default, hover, focus-visible, active, disabled, loading, error, success, empty, overflow
- **完成的交互品质** — 键盘路径、触摸目标、反馈时机、滚动行为、状态过渡
- **优质动效** — 模糊、滤镜、遮罩、阴影、揭示；避免休闲布局属性动画
- **可维护** — 可复用本地模式、清晰组件边界、项目约定

### shape — 设计规划

编码前塑造 UX 和 UI。产出**设计简报**。

#### Phase 1：发现访谈（必须）

以对话方式提问，适应回答。分轮次：

**第 1 轮**：目的与受众、内容与数据、设计方向、范围、约束、反目标

- 断言后确认，不是菜单后转义
- 当 PRODUCT.md 和用户提示使一个选项明显时，命名它并请用户确认或覆盖

#### Phase 1.5：视觉方向探测

仅当全部满足时：工作是净新增、期望保真度是中/高/生产级、当前环境有原生图像生成。

生成 **2 到 4** 个不同的方向探测，差异应在主要视觉方向（层级、拓扑、密度、排版声音或色彩策略）。

#### Phase 2：设计简报

**紧凑形式**（3-5 要点）：发现清晰时
**完整结构化形式**：真正模糊或多屏幕时

简报包含：功能摘要、主要用户行动、设计方向、范围、布局策略、关键状态、交互模型、内容需求、推荐参考、开放问题。

### init — 项目初始化

- **DESIGN.md**（视觉）：视觉主题、调色板、排版、组件、布局
- **`.impeccable/live/config.json`**：预配置实时模式

#### 流程

1. **加载当前状态** — 检查已存在的内容
2. **探索代码库** — README、package.json、现有组件、品牌资产、设计令牌
3. **询问战略问题** — 访谈模式，非确认模式
4. **编写 PRODUCT.md** — 仅用户确认后
5. **决定 DESIGN.md** — 提供 `/impeccable document`
6. **配置实时模式** — 当代码存在时
7. **推荐起点** — 2-4 个最相关的后续命令

### document — 生成 DESIGN.md

生成捕获当前视觉设计系统的 `DESIGN.md` 文件。

#### 两种模式

- **Scan mode（默认）**：项目有设计令牌、组件或渲染输出。提取后确认描述语言
- **Seed mode**：项目是预实现（全新初始化，什么都没构建）。访谈五个高层答案，写入最小 DESIGN.md

#### DESIGN.md 结构（六部分，固定顺序）

1. `## 1. Overview` — 创意北极星、哲学、关键特征
2. `## 2. Colors` — 主色/次色/第三色/中性色 + 命名规则
3. `## 3. Typography` — 展示字体/正文字体，层级，命名规则
4. `## 4. Elevation` — 阴影词汇或平面策略
5. `## 5. Components` — 按钮、卡片、输入、导航等
6. `## 6. Do's and Don'ts` — 具体、有力的护栏

#### YAML 前言格式

```yaml
---
name: <project title>
description: <one-line tagline>
colors:
  primary: "#b8422e"
  neutral-bg: "#faf7f2"
typography:
  display:
    fontFamily: "Cormorant Garamond, Georgia, serif"
    fontSize: "clamp(2.5rem, 7vw, 4.5rem)"
    fontWeight: 300
    lineHeight: 1
components:
  button-primary:
    backgroundColor: "{colors.primary}"
    textColor: "{colors.neutral-bg}"
    rounded: "{rounded.sm}"
    padding: "16px 48px"
---
```

### critique — 设计评审

运行两个独立评估，综合为一个设计评审，持久化快照。

#### 硬性不变量

- 评估 A（设计评审）和评估 B（检测器/浏览器证据）都是必需的
- 必须作为两个隔离的子代理运行
- 降级运行必须在报告第一行标注 `⚠️ DEGRADED`

#### 评估 A：设计评审

以设计总监思维评估：AI slop、整体设计、认知负荷、情感旅程、Nielsen 启发式（评分 0-4）

#### 评估 B：检测器 + 浏览器证据

```bash
node .claude/skills/impeccable/scripts/detect.mjs --json [target]
```

浏览器可视化检查（当可用时）。

#### 综合报告结构

- **报告头来源**：声明评估如何运行
- **设计健康分数**：10 项启发式表格（总分 /40）
- **反模式判定**：LLM 评估 + 确定性扫描 + 视觉叠加层
- **整体印象**：直觉反应
- **什么做得好**：2-3 项具体
- **优先问题**：3-5 项，每项 P0-P3 标记
- **用户画像红旗**：2-3 个相关画像的具体问题
- **次要观察**：较小问题
- **考虑问题**：引发更好解决方案的挑衅性问题

#### 评分范围

| 分数范围 | 评级 | 含义 |
|----------|------|------|
| 36–40 | 优秀 | 只需小打磨；发布 |
| 28–35 | 好 | 解决薄弱领域，坚实基础上 |
| 20–27 | 可接受 | 用户满意前需要显著改进 |
| 12–19 | 差 | 需要重大 UX 改造 |
| 0–11 | 严重 | 需要重新设计；当前状态不可用 |

### audit — 技术质量审计

运行系统化**技术**质量检查。不修复问题；为其他命令记录问题。

#### 五个维度

1. **无障碍（A11y）**：对比度问题、缺失 ARIA、键盘导航、语义 HTML、alt 文本、表单问题
2. **性能**：布局抖动、昂贵动画、缺失优化、包大小、渲染性能
3. **主题化**：硬编码颜色、暗色模式缺陷、不一致令牌
4. **响应式设计**：固定宽度、触摸目标、水平滚动、文本缩放、缺失断点
5. **反模式**：对照所有绝对禁令和 AI slop 检查

#### 评分范围

| 分数范围 | 评级 |
|----------|------|
| 18–20 | 优秀 |
| 14–17 | 好 |
| 10–13 | 可接受 |
| 6–9 | 差 |
| 0–5 | 严重 |

### polish — 发布前打磨

执行精雕细琢的最终通过，捕获所有区分好工作和伟大工作的小细节。

#### 设计系统发现（非可选）

在打磨前必须对齐设计系统：
1. 找到设计系统文档
2. 注意约定：共享组件如何导入、使用的间距刻度、令牌颜色
3. 识别偏离并命名根本原因：缺失令牌 / 一次性实现 / 概念不对齐

#### 打磨维度

- 视觉对齐与间距
- 信息架构与流程
- 排版打磨
- 色彩与对比度
- 交互状态（七态完整）
- 微交互与过渡
- 内容与文案
- 图标与图像
- 表单与输入
- 边缘情况与错误状态
- 响应式
- 性能
- 代码质量

#### 抛光检查清单（21 项）

对齐设计系统 → 信息架构匹配 → 所有断点视觉对齐完美 → 间距一致使用令牌 → 排版层级一致 → 所有交互状态已实现 → 所有过渡平滑 → 文案一致打磨 → 图标一致 → 所有表单标签和验证正确 → 错误状态有用 → 加载状态清晰 → 空状态欢迎 → 触摸目标 ≥44px → 对比度符合 WCAG AA → 键盘导航工作 → 焦点指示器可见 → 无控制台错误 → 无布局抖动 → 所有浏览器兼容 → 尊重 reduced motion → 代码干净

### animate — 添加动效

#### 动画策略

- **英雄时刻**：一个标志性动画
- **反馈层**：哪些交互需要确认
- **过渡层**：哪些状态变化需要平滑
- **愉悦层**：在哪里惊喜和愉悦

#### 实施类别

- **入场动画**：Hero 部分、模态/抽屉进入、列表节奏（交错上限 500ms）
- **微交互**：按钮反馈、表单交互、开关、复选框
- **状态过渡**：显示/隐藏、展开/折叠、加载状态、成功/错误
- **导航与流程**：页面过渡、标签切换、轮播、滚动效果
- **反馈与引导**：hover 提示、拖放、复制/粘贴、焦点流程
- **愉悦时刻**：空状态动画、完成动效、彩蛋

#### 绝对禁止

- 使用 bounce 或 elastic 缓动曲线
- 休闲动画布局属性（width, height, top, left, margins）
- 反馈使用超过 500ms 的时长
- 无目的动画
- 忽略 `prefers-reduced-motion`
- 动画一切

### colorize — 色彩策略

#### 色彩引入维度

- **语义色彩**：状态指示器（成功/错误/警告/信息）
- **强调色应用**：主要操作、链接、图标、标题、hover 状态
- **背景与表面**：带色背景、色彩区块、渐变背景、卡片色彩
- **数据可视化**：图表、热力图、比较
- **边框与强调**：全边框（非侧边条纹）、下划线、分隔线、焦点环
- **排版色彩**：彩色标题、高亮文本、标签
- **装饰元素**：插图、几何形状、渐变、有机形状

#### 平衡与打磨

- **主色**（60%）：主要品牌色或最常用强调色
- **次色**（30%）：支持色提供变化
- **强调色**（10%）：高对比度关键时刻
- **中性色**（其余）：灰/黑/白用于结构

### layout — 布局修复

#### 间距系统

- 一致的间距刻度（推荐 4pt 基数）
- 语义化令牌命名
- `gap` 代替 margin
- `clamp()` 实现流体间距

#### 选择正确的布局工具

- **Flexbox**：1D 布局
- **Grid**：2D 布局
- **容器查询**：组件
- **视口查询**：页面布局

使用 `grid-template-areas` 实现复杂页面布局。

#### 布局绝不要

- 使用刻度外的任意间距值
- 使所有间距相等
- 把所有东西包在卡片里
- 嵌套卡片
- 使用千篇一律的卡片网格
- 默认 hero metric 布局模板

### live — 浏览器实时变体

在浏览器中选择元素，选取设计操作，获取 AI 生成的 HTML+CSS 变体，通过 HMR 热替换。

#### 前提条件

运行中的带 HMR 的 dev server。

#### 合约（按顺序执行）

1. `live.mjs`：启动
2. 打开应用 URL
3. 轮询循环（默认长超时 600000ms）
4. 收到 `generate` → 读取截图 → 加载操作参考 → 规划三个方向 → 一次编辑写入所有变体 → `--reply done`
5. 收到 `steer` → 读取消息 → 做工作 → `--reply steer_done`
6. 收到 `accept`/`discard` → 处理 → 轮询
7. 如果中断 → `live-status.mjs` / `live-resume.mjs`
8. 收到 `exit` → 清理

#### 变体规划（四阶段）

**Phase A：提取身份（不可跳过）**
从 DESIGN.md、CSS 自定义属性、计算样式、兄弟组件中提取"这个界面实际上是什么"。

**Phase B：选择模式**
- **Default 模式**（~90% 会话）：保留现有身份，在身份内变化
- **Departure 模式**：当 PRODUCT.md 反参考明确指向当前界面或用户提示明确要求时

**Phase C：规划三个变体**
- Default 模式：每个变体承诺不同的**主要差异轴**（层级/布局拓扑/排版系统/色彩策略/密度/结构分解）
- Departure 模式：每个变体锚定不同的**审美方向**，从品牌的物理/空间/材料体验中推导

**Phase D：斜视测试**
- Default：检查身份是否保持
- Departure：家族通过（标签不同）+ 句子通过（描述不押韵）

#### 参数（每个变体 0–4 个）

| 元素权重 | 参数预算 |
|----------|---------|
| 叶子/微小（按钮、图标） | 0 |
| 小型组合（标签输入、简单卡片） | 0–1 |
| 中等组合（区块组件、导航集群） | 目标 2 |
| 大型组合（hero、整页区域） | 目标 2–3，最多 4 |

三种参数：`range`（滑块）、`steps`（分段）、`toggle`（开关）

## 14. Hooks 管理

### `/impeccable hooks <action>`

管理当前项目的**设计检测器 Hook**。

Hook 在对设计相关文件（`.tsx`, `.jsx`, `.html`, `.vue`, `.svelte`, `.astro`, `.css`, `.scss`, `.ts`, `.js`）的直接编辑后运行 impeccable 设计检测器。

#### 操作

| 操作 | 功能 |
|------|------|
| `status` | 打印当前状态 |
| `on` | 启用 Hook |
| `off` | 禁用 Hook |
| `ignore-rule <id>` | 抑制整个规则 |
| `ignore-file <glob>` | 抑制匹配文件 |
| `ignore-value <id> <value>` | 抑制特定值（共享或本地） |

#### 偏好最窄的例外

1. 精确 `ignore-value` 命令 → 写入共享 `.impeccable/config.json`

4. 内联注释 `impeccable-disable-line` / `impeccable-disable-next-line` 用于必须随文件离开仓库的豁免

## 16. 认知负荷评估

### 三种认知负荷

1. **内在负荷：任务本身** — 用户要做的固有复杂性。通过结构化、脚手架、渐进式披露管理
2. **外在负荷：糟糕的设计** — 由糟糕设计选择引起的心理负担。**无情消灭。**
3. **相关负荷：学习努力** — 用于建立理解的努力。这是*好的*认知负荷。

### 认知负荷检查清单

- [ ] **单一焦点**：用户能否完成主要任务而不被竞争元素分心？
- [ ] **分块**：信息以可消化组呈现（≤4 项/组）？
- [ ] **分组**：相关项视觉上分组？
- [ ] **视觉层级**：屏幕上最重要的立即清楚？
- [ ] **一次一件事**：用户能在进入下一个之前专注于一个决定？
- [ ] **最少选择**：决定简化（≤4 个可见选项在任何决策点）？
- [ ] **工作记忆**：用户需要记住上一屏的信息来操作当前屏？
- [ ] **渐进式披露**：复杂性仅在用户需要时揭示？

**评分**：0-1 失败 = 低负荷（好）。2-3 = 中等（尽快解决）。4+ = 高负荷（急需修复）。

### 工作记忆规则

人类一次只能在工作记忆中持有 **≤4 项**。在任何决策点，计算用户必须同时考虑的不同选项/操作/信息数量：
- ≤4：可管理
- 5–7：接近边界
- 8+：过载

## 19. 色彩与对比度深度参考

### 构建功能性调色板

完整系统需要：

| 角色 | 目的 | 示例 |
|------|------|------|
| **Primary** | 品牌、CTA、关键操作 | 1 个颜色，3-5 个色阶 |
| **Neutral** | 文字、背景、边框 | 9-11 个色阶 |
| **Semantic** | 成功、错误、警告、信息 | 4 个颜色，2-3 个色阶 |
| **Surface** | 卡片、模态框、叠加层 | 2-3 个高度级别 |

### 危险的色彩组合

- 浅灰文字白色背景（#1 无障碍失败）
- 红文字绿背景（反之）：8% 男性无法区分
- 蓝文字红背景（视觉振动）
- 黄文字白背景（几乎总是失败）
- 薄浅文字图像上（不可预测对比度）

### 令牌层级

使用两层：原始令牌（`--blue-500`）和语义令牌（`--color-primary: var(--blue-500)`）。暗色模式只重定义语义层。

### Alpha 是设计异味

大量使用透明度通常意味着不完整的调色板。为每个上下文定义显式叠加颜色。例外：焦点环和交互状态。

### 命名规则

`**The [Name] Rule.** [简短教条]` — 这些是可记忆、可引用的，对 AI 消费者比项目符号列表粘性更强。目标每节 1-3 条。
