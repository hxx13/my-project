**Goal:** 豁免权的产生与消失只在**状态变更点**（`TwinCardMappingService`）统一记账到 `twin_automation_log`，消灭"各渠道各自写记录"的分叉；补齐"删除已批申请不收回豁免"空档；清理 `exempt_at_exit` 死列；Web + 小程序提供按人反查"豁免轨迹"。

**Architecture:** 引入 `ExemptChangeContext`（来源渠道/触发类型/操作人/关联单号），所有豁免写方法强制携带该上下文（删除无上下文的公开重载，编译期强制未来调用方声明来源）；`TwinCardMappingService` 内唯一私有记账方法 `writeExemptLedger` 负责写 `twin_automation_log`；四条纯 SQL 批量收回路径改"先查快照后更新"以支持逐人记账；惰性过期不记账（读路径不写库），60 秒定时收回是"消失"的正式记录点。

**Tech Stack:** Spring Boot 3.5 + MyBatis + MySQL 8（后端）；React + TS + react-query + Bento 令牌（Web）；原生小程序（aroapp）。

## 事件词汇表（新数据的统一契约）

写入 `twin_automation_log`，列约定：`automation_type=EXEMPTION`，`user_id`=aroUserId，`target_id`=cardNo，`created_by=exempt-ledger`（对齐既有 `writeScheduledExemptRevokeLog` :869-888 的列用法）。

| event_key | 含义 |
|---|---|
| `EXEMPT_GRANTED`（新增常量 `EVENT_EXEMPT_GRANTED`） | 豁免产生（含覆盖旧豁免，detail 注明原到期） |
| `EXEMPT_REVOKED`（沿用 :32） | 豁免消失 |

| trigger_reason（渠道码） | trigger_type | 场景 |
|---|---|---|
| `MANUAL_ADMIN` | USER | 管理员手动设置/取消（detail 带 client=web/miniapp/room-audit-web/room-audit-miniapp 与操作人） |
| `SCAN_DELAY_APPROVED` | USER | 延迟申请人工/自动审核通过（自动批走同一 reviewRequest，操作人=规则 owner） |
| `SCAN_DELAY_DIRECT` | USER | 延迟申请免审直批 |
| `KEEP_CARD_GRANT` | USER | 扫码登记勾选长期保管卡 |
| `SCAN_EXIT_REVOKE` | USER | 扫码离开联动收回 |
| `EXEMPT_EXPIRE_TIMER` | TIMER | 60 秒定时到期收回 |
| `EXEMPT_COUNT_EXHAUSTED` | USER/TIMER | 次数耗尽（即时/兜底两处） |
| `DAILY_EXEMPT_RESET_FALLBACK`（沿用 :33） | TIMER | 每日兜底回收（行为不变，实现归一） |
| `FIRST_FREEZE_FINISHED_CLEAR_ALL_EXEMPT`（复用已有展示标签） | TIMER | 首冻后清空（新增逐人记账；AroSyncTask 汇总行保留） |
| `EXEMPT_RECONCILE_REVOKE` | SYSTEM | 事件溯源纠偏收回 |
| `STARTUP_EXEMPT_RESET` | SYSTEM | 开机洗刷过期豁免 |
| `MAPPING_DELETED_REVOKE` | USER | 解绑卡映射随行收回 |
| `SCAN_DELAY_REQUEST_DELETED` | USER | 删除已批申请撤回豁免（Task 3 新行为） |

历史码 `SCAN_DELAY_GRANTED` 停写但保留展示映射（旧数据仍要能渲染）。

**detail 模板**（对齐 :872-877 风格）：`姓名=…，卡号=…，模式=…，时长/到期=…，房间=…，操作人=…，关联单号=…[，覆盖旧豁免(原到期=…)]`。
