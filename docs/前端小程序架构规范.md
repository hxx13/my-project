## 三、核心架构：API 请求链路

### 3.1 请求链路图

```
小程序页面
  └→ springAuth.springRequest({ url, method, data })
    └→ callSpringProxy({ path, method, data, authorization })
      └→ wx.cloud.callFunction({ name: "springProxy", data: {...} })
        └→ 云函数 springProxy/index.js
          └→ axios({ method, url: SPRING_BASE_URL + path, headers, data, timeout: 28000 })
            └→ Spring Boot 后端 (ECS)
              └→ 返回 Result<T> JSON
```

### 3.2 云函数 springProxy 详解

**文件**：`cloudfunctions/springProxy/index.js`

**核心职责**：
- 路径白名单校验（`ALLOWED_API_PREFIXES` 环境变量）
- 转发 HTTP 方法、请求头（Authorization, X-Proxy-Secret）、请求体
- multipart 文件上传处理（`__uploadFile` 魔术字段 → base64 解码 → `multipart/form-data`）
- arraybuffer 响应编码为 base64（Excel 导出场景）
- 统一返回 `{ ok, statusCode, body }`

**环境变量**：

| 变量 | 必填 | 说明 |
|------|------|------|
| `SPRING_BASE_URL` | 是 | Spring Boot 后端地址，如 `http://47.101.61.184:8080` |
| `PROXY_SHARED_SECRET` | 否 | 与后端 `app.mp.proxy.secret` 一致，启用后所有请求携带 `X-Proxy-Secret` |
| `ALLOWED_API_PREFIXES` | 否 | 逗号分隔的路径白名单，默认覆盖常用前缀 |

**默认白名单前缀**：
```
/api/auth,/api/me,/api/mp,/api/admin,/api/notifications,/api/repair,
/api/purchase,/api/supplies,/api/upload,/api/public,/api/chat,/api/v1
```

### 3.3 springAuth.js 核心 API

**文件**：`miniprogram/utils/springAuth.js`

| 导出函数 | 用途 |
|----------|------|
| `springRequest(options)` | **最常用** — 发起鉴权请求，自动带 `Authorization: Bearer <token>` |
| `callSpringProxy(payload)` | 底层函数 — 直接调云函数，60s 超时 |
| `loginWechat(jsCode)` | 微信静默登录 → `POST /api/auth/login/wechat` |
| `bindWechat({...})` | 绑定校园账号 → `POST /api/auth/bind/wechat` |
| `refreshWechatSession()` | 刷新会话：优先 Bearer 刷新，失败回退 `wx.login` |
| `uploadSpringFile(tempFilePath)` | 上传图片到 Spring |
| `uploadCloudMediaFile(tempFilePath)` | 上传图片到微信云存储（返回 `cloud://` URL） |
| `persistSpringSession(authData)` | 将登录响应写入 storage |
| `clearSpringSession()` | 清除所有登录态 |
| `toAbsoluteMediaUrl(url)` | 相对路径 → 绝对 HTTPS URL |
| `toAbsoluteApiUrl(url)` | 相对 API 路径 → 完整可访问 URL |

### 3.4 强制规则

| 规则 | 说明 |
|------|------|
| 所有后端请求走 `springAuth.springRequest()` | 不走 `wx.request` 直连后端 |
| 图片上传用 `springAuth.uploadSpringFile()` | 不走 `wx.uploadFile` 直传后端 |
| 云存储上传用 `springAuth.uploadCloudMediaFile()` | 返回 `cloud://` URL，不存 base64 |
| 新增 API 前缀需加入云函数白名单 | 在 `ENV_CONSOLE.txt` 记录，云端同步更新 |
| 不在页面中直接 `wx.cloud.callFunction` | 所有云函数调用封装在 `springAuth.js` 中 |

## 四、认证体系（双轨制）

### 4.1 两套 Token

| Token | 存储键 | 用途 | 来源 |
|-------|--------|------|------|
| JTU Token | `token` | 直连校园网 JTU API | `app.js autoLogin()` 硬编码账号密码登录 |
| Spring Token | `springToken` | 调用自有后端 | `springAuth.loginWechat()` → `wx.login` → 云函数 → Spring |

两套 Token 独立管理，互不干扰。JTU Token 仅用于 `utils/request.js` 直连 JTU 的场景（如新闻回退）；Spring Token 用于所有业务 API。

### 4.2 登录流程

```
应用启动 (app.js onLaunch)
  ├── 云开发初始化 (wx.cloud.init)
  ├── JTU 校园网登录 (autoLogin) —— 直连 aro.shsmu.edu.cn
  └── Spring 静默登录 (runWechatSilentLoginOnLaunch)
        └── wx.login → 获取 jsCode
          └── springAuth.loginWechat(jsCode)
            └── 云函数 springProxy
              └── POST /api/auth/login/wechat
                └── 返回 { token, role, userInfo }
                  └── persistSpringSession() → 写入 storage
```

### 4.3 强制规则

| 规则 | 说明 |
|------|------|
| JTU Token 仅供 `request.js` 使用 | 业务 API 不认 JTU Token |
| Spring Token 始终通过 `springAuth` 获取 | 不手动写入 `springToken` storage 键 |
| 启动时自动执行静默登录 | 页面不重复调 `loginWechat` |
| 会话过期由 `refreshWechatSession` 处理 | 页面捕获 401 后调 refresh 再重试 |

## 五、页面开发规范

### 5.1 页面四件套

```
pages/xxx/
├── index.js      ← Page({ data, onLoad, onShow, methods })
├── index.json    ← { navigationBarTitleText, usingComponents }
├── index.wxml    ← 模板
└── index.wxss    ← 样式
```

### 5.2 生命周期标准模式

```javascript
const springAuth = require('../../utils/springAuth.js');
const pagePermission = require('../../utils/pagePermission.js');

Page({
  data: {
    loading: true,
    list: [],
    error: null,
  },

  onLoad() {
    // 首次加载：从 storage 恢复角色等静态数据
    this.setData({
      role: wx.getStorageSync(springAuth.KEYS.ROLE) || '',
    });
  },

  onShow() {
    // 每次显示：权限门控 + 刷新数据 + 刷新 TabBar 角标
    if (!pagePermission.guardPageOnShow(this, '/pages/xxx/index', this.data.role, 'STUDENT')) {
      return;
    }
    this.loadData();
    if (this.getTabBar()) {
      this.getTabBar().refreshTabs();
    }
  },

  async onPullDownRefresh() {
    await this.loadData();
    wx.stopPullDownRefresh();
  },

  async loadData() {
    this.setData({ loading: true, error: null });
    try {
      const res = await springAuth.springRequest({
        url: '/api/v1/xxx/list',
        method: 'GET',
      });
      const parsed = this.parseResponse(res);
      if (parsed.ok) {
        this.setData({ list: parsed.data, loading: false });
      } else {
        this.setData({ error: parsed.message, loading: false });
      }
    } catch (e) {
      this.setData({ error: e.message || '请求失败', loading: false });
    }
  },

  parseResponse(res) {
    const body = (res && res.data) ? res.data : null;
    if (!body || body.success !== true) {
      return { ok: false, message: (body && body.message) || '请求失败' };
    }
    return { ok: true, data: body.data };
  },
});
```

### 5.3 JSON 配置模式

```json
{
  "navigationBarTitleText": "页面标题",
  "enablePullDownRefresh": true,
  "backgroundTextStyle": "dark",
  "usingComponents": {
    "van-icon": "@vant/weapp/icon/index",
    "van-cell": "@vant/weapp/cell/index"
  }
}
```

### 5.4 WXML 模板模式

```xml
<view class="page-container">
  <!-- 加载态 -->
  <view wx:if="{{ loading }}" class="state-loading">加载中...</view>

  <!-- 错误态 -->
  <view wx:elif="{{ error }}" class="state-error">
    <text>{{ error }}</text>
    <button bindtap="loadData">重试</button>
  </view>

  <!-- 空态 -->
  <view wx:elif="{{ list.length === 0 }}" class="state-empty">暂无数据</view>

  <!-- 正常态 -->
  <block wx:else>
    <view wx:for="{{ list }}" wx:key="id" class="card-item">
      <text>{{ item.name }}</text>
    </view>
  </block>
</view>
```

### 5.5 强制规则

| 规则 | 说明 |
|------|------|
| 必须覆盖四种状态 | loading / error / empty / normal |
| `onShow` 中必须调权限门控 | `pagePermission.guardPageOnShow(this, path, role, minRole)` |
| 解析响应用统一的 `parseResponse` | 检查 `body.success === true` |
| `wx:key` 必须指定 | 不用 `wx:key="*this"`（除非列表是字符串数组） |
| WXSS 尺寸用 `rpx` | 适配不同屏幕宽度 |
| 底部预留 TabBar 安全区 | `padding-bottom: calc(30rpx + 50px + env(safe-area-inset-bottom))` |

## 六、权限控制体系

### 6.1 三层权限

| 层级 | 实现 | 作用 |
|------|------|------|
| 云函数白名单 | `ALLOWED_API_PREFIXES` | 控制哪些 API 路径可被小程序访问 |
| 页面访问 | `pagePermission.guardPageOnShow()` | 无权限页面弹出 toast 并返回 |
| 入口可见 | `pagePermission.canShowMiniEntry()` | 控制 TabBar、首页快捷入口是否显示 |

### 6.2 角色层级映射

```javascript
// utils/roleAccess.js
const ROLE_LEVEL_MAP = {
  STUDENT: 1, STAFF: 2, SENIOR: 3,
  ADMIN: 4, SUPER_ADMIN: 5, PLATFORM_OWNER: 6,
};

function hasMinRole(currentRole, minRole) {
  return getRoleLevel(currentRole) >= getRoleLevel(minRole);
}
```

### 6.3 TabBar 动态构建

```javascript
// utils/tabBarHelper.js
function buildTabList() {
  const role = wx.getStorageSync(springAuth.KEYS.ROLE) || '';
  const tabs = [
    { path: '/pages/index/index', text: '首页', icon: 'wap-home', minRole: 'STUDENT' },
    { path: '/pages/room/index', text: '房间', icon: 'location', minRole: 'STUDENT' },
    { path: '/pages/overview/index', text: '概览', icon: 'chart-trending-o', minRole: 'ADMIN' },
    { path: '/pages/telemetry/index', text: '温湿度', icon: 'notes-o', minRole: 'ADMIN' },
  ];
  // 过滤无权限的 Tab
  return tabs.filter(tab =>
    pagePermission.canShowMiniEntry('tabbar', tab.path, role, tab.minRole || 'STUDENT')
  );
}
```

### 6.4 强制规则

| 规则 | 说明 |
|------|------|
| 角色信息从 `springAuth.KEYS.ROLE` 读取 | 不从 `wx.getStorageSync('role')` 硬编码键名 |
| 页面显示时必须调 `guardPageOnShow` | 不跳过权限检查 |
| 入口可见性用 `canShowMiniEntry` | 不在 WXML 里写 `wx:if="{{ role === 'ADMIN' }}"` |
| 新增页面必须登记 | 在管理端「页面权限」中注册，小程序端自动同步 |

## 七、待办角标系统

### 7.1 数据流

```
后端 GET /api/me/pending-badges
  → pendingBadgeCounts.js（合并并发请求）
    → badgeSnapshotStore.js（全局单例 + 订阅者模式）
      → custom-tab-bar（渲染角标数字）
      → 各页面（按需订阅特定业务域角标）
```

### 7.2 核心文件

| 文件 | 职责 |
|------|------|
| `pendingBadgeCounts.js` | 发起请求、去重并发（`inflightPromise`）、错误时保留上次快照 |
| `badgeSnapshotStore.js` | 全局单例、发布订阅、按 key 分发 |

### 7.3 强制规则

| 规则 | 说明 |
|------|------|
| 角标数据从后端获取 | 不在前端计算未读数 |
| 网络错误保留上次成功快照 | 不因一次失败清空角标 |
| 并发请求自动合并 | `pendingBadgeCounts` 内置去重，调用方无需关心 |

## 十、与元规范的对齐

小程序端受限于原生框架，以下原则需适配应用：

| 元规范章节 | 小程序端适配 |
|-----------|------------|
| §3.1 融入而非替代 | 复用 `springAuth`、`pagePermission`、`badgeSnapshotStore`，新页面不重写请求/权限逻辑 |
| §3.4 常量集中管理 | 角色层级放 `roleAccess.js`，API 路径白名单在云函数 `ALLOWED_API_PREFIXES` 集中管理 |
| §3.5 显式状态机 | 小程序用 `data.step` 字段模拟状态机，Page 中一个 `step` 字段替代散落的布尔标志 |
| §3.6 接口契约文档化 | `springAuth.js` 暴露的函数签名即接口契约，调用方不触碰底层 `wx.cloud.callFunction` |
| §4.2 只有 Happy Path | 每个列表页必须覆盖 loading / error / empty / normal 四态（本文档 §5.5 已覆盖） |
| §二 Spec 章节模板 | 小程序新功能设计文档必须覆盖 API 对接清单、权限模型、分包策略 |

### 10.1 小程序端状态管理模式

受限于原生框架无 `useReducer`，用 `data.step` 字段模拟：

```javascript
// ✅ 正确：用 step 字段控制页面状态
Page({
  data: {
    step: 'input',  // 'input' | 'verifying' | 'locked' | 'success'
    pin: '',
    errorMsg: '',
    lockCountdown: 0,
  },

  onPinInput(e) {
    if (this.data.step !== 'input') return;  // 状态守卫
    this.setData({ pin: e.detail.value });
  },
  // ... 状态转换全部通过 setData({ step: 'xxx' })
});
```

## 十二、禁止事项

1. **禁止 `wx.request` 直连后端** — 所有请求走云函数 springProxy。
2. **禁止 `wx.uploadFile` 直传后端** — 上传走 `springAuth.uploadSpringFile()` 或 `uploadCloudMediaFile()`。
3. **禁止在页面中硬编码角色判断** — 页面可见性走 `pagePermission`，入口可见性走 `canShowMiniEntry`。
4. **禁止在 WXML 中写业务逻辑** — 数据处理在 JS 中完成，WXML 只负责渲染。
5. **禁止手动操作 `wx.setStorageSync('springToken', ...)`** — Token 管理走 `springAuth.persistSpringSession/clearSpringSession`。
6. **禁止新增云函数** — 当前仅 `springProxy` 一个云函数，所有后端通信通过它。如需新能力，扩展 `springProxy` 或在后端新增 REST 端点。
7. **禁止分包页面被主包直接引用** — 分包工具模块放 `package-feature/utils/`。
8. **禁止忽略四种 UI 状态** — 每个列表页面必须有 loading / error / empty / normal 四态的渲染分支。
9. **禁止 `wx:key="*this"`** — 列表渲染必须指定唯一标识字段。
10. **禁止散落的布尔标志管理页面状态** — ≥3 个互斥状态时使用 `data.step` 字段模拟状态机，避免 `isLoading && isError` 同时为 true。
