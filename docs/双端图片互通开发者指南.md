# 双端图片互通 · 开发者指南

> 新增任何带图片列的功能时，按此清单操作即可自动打通 Web ↔ 小程序双向图片加载。

---

## 自动机制（无需手动干预）

| 机制 | 说明 |
|------|------|
| `<AutoImage>` 组件 | Web 端替代 `<img>`，自动解析 `cloud://` / 相对路径 / HTTP URL |
| `toAbsoluteMediaUrl()` | 小程序端 URL 解析，相对路径 → 绝对 HTTP / `cloud://` 直通 CDN |
| `ImageRecordAutoRepair` | 应用启动时扫描所有图片列，磁盘文件存在但缺 `upload_file_record` → 自动创建 |
| `bootstrap-fix-relative-urls.sql` | 启动时自动将相对路径 `/api/upload/files/...` 转为完整公网 URL |
| `syncToWechat` 云函数 | 轮询待同步记录 → 上传微信云存储 → 回填 `cloud://` fileID |
| `cloud-mappings` API | 批量解析 HTTP URL → `cloud://` fileID，供小程序 CDN 优先加载 |
| `triggerCloudSync()` | 小程序检测到未命中 CDN 的图片时，自动触发 `syncToWechat` |

## 新增图片列 · 操作清单

假设新增表 `lab_report`，图片列 `screenshot_url`（非 JSON）。

### ① 后端自动修复扫描

**文件**：`src/main/java/com/example/demo/modules/upload/config/ImageRecordAutoRepair.java`

在 `SCAN_TARGETS` 列表末尾加一行：

```java
// 新增表：lab_report.screenshot_url
new ScanTarget("lab_report", "screenshot_url", false),
```

> 如果是 JSON 数组列（如 `["url1","url2"]`），第三个参数改为 `true`。

### ② 云端 URL 迁移覆盖

**文件**：`src/main/java/com/example/demo/modules/upload/controller/UploadController.java`

搜索 `scanCloudUrls`、`autoReplaceCloudUrls`、`replaceCloudUrls`、`fixRelativeUrls` 四个方法，在各自的 `ScanTarget` 列表末尾各加一行：

```java
new ScanTarget("lab_report", "screenshot_url", "id", false),
```

> JSON 数组列的第三个参数同样改为 `true`。

### ③ 相对路径修复

**文件**：`src/main/resources/db/bootstrap-fix-relative-urls.sql`

非 JSON 列：
```sql
UPDATE lab_report SET screenshot_url = CONCAT('http://47.101.61.184:8080', screenshot_url)
WHERE screenshot_url LIKE '/api/upload/files/%' AND screenshot_url NOT LIKE 'http%';
```

JSON 数组列（如 `["/api/upload/files/...", ...]`）：
```sql
UPDATE lab_report SET screenshot_url = REPLACE(screenshot_url, '"/api/upload/files/', '"http://47.101.61.184:8080/api/upload/files/')
WHERE screenshot_url LIKE '%"/api/upload/files/%';
```

### ④ Web 端页面

**文件**：`frontend/src/pages/AdminLabReportPage.tsx`（示例）

```tsx
import { AutoImage } from "@/components/ui/AutoImage";

// 替代 <img> —— 自动处理所有 URL 格式
<AutoImage src={row.screenshotUrl} className="w-full object-cover" />
```

### ⑤ 小程序端页面

**文件**：`aroapp/miniprogram/.../labReport/index.js`（示例）

```js
// 在 decorate / render 函数中
coverUrl: springAuth.toAbsoluteMediaUrl(row.screenshotUrl),
```

WXML 中正常使用：
```html
<image src="{{ item.coverUrl }}" mode="aspectFill" lazy-load />
```

## 图片上传规范

| 端 | 上传方式 | 存储 URL 格式 |
|----|---------|-------------|
| **小程序** | `wx.cloud.uploadFile()` → 拿到 `cloud://` fileID | **存 HTTP `publicUrl`**（`syncToBackend` 返回的），不是 `cloud://` |
| **Web** | `POST /api/upload` → 拿到 `publicUrl` | 直接存 `publicUrl` |

> 小程序创建/修改记录时，先 `await syncToBackend` 拿到 `publicUrl`，再把 `publicUrl` 存入业务表。
> 不要直接存 `cloud://` —— Web 端无法直接渲染。

## 架构图

```
┌── 小程序 ──────────────────────────────────────┐
│  upload → wx.cloud.uploadFile → cloud:// ID      │
│  syncToBackend (await) → 后端存盘 + 创建 record   │
│  业务表存 publicUrl                               │
│  显示: toAbsoluteMediaUrl(url) → <image>          │
│       cloud:// 优先 (CDN) / HTTP 回退             │
└──────────────────────────────────────────────────┘
                    ↕
┌── 后端 ────────────────────────────────────────┐
│  upload → 存盘 → upload_file_record              │
│  ImageRecordAutoRepair: 启动时扫描补缺           │
│  cloud-mappings: HTTP → cloud:// 反查            │
│  bootstrap-fix: 相对路径 → 绝对 URL              │
└──────────────────────────────────────────────────┘
                    ↕
┌── Web ─────────────────────────────────────────┐
│  <AutoImage src={url} />                         │
│    cloud:// → proxy-image → 磁盘文件             │
│    相对路径 → 拼接 origin                        │
│    HTTP → 直连                                   │
└──────────────────────────────────────────────────┘
```
