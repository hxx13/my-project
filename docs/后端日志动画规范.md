# 后端日志动画规范

> 生效日期：2026-06-30 | 强制执行

## 核心原则

**任何耗时超过 200ms 的后端操作，控制台必须有可见的进度反馈。不允许没有任何反应的"静默等待"。**

## 三种动画类型

| 场景 | 工具 | 何时使用 |
|------|------|---------|
| **旋转指示器** | `LoadingSpinner.run()` / `supply()` | 不可预知总量，只知"正在做" |
| **进度条** | `LoadingSpinner.progress()` | 可计数场景（N 条记录、M 个批次） |
| **启动阶段** | `@StartupPhase` + `StartupRunner` | 启动时的一次性初始化（已由框架自动动画） |

## 一、旋转指示器（Spinner）

### 何时使用

- 加载模型文件（"加载人脸模型"）
- 请求外部 API Token（"获取 ARO Token"）
- 初始化缓存（"初始化卡片映射缓存"）
- 数据库迁移脚本执行（"执行遥测 DDL"）
- 任何无法预知总量的操作

### API

```java
import static com.example.demo.common.logging.banner.LoadingSpinner.*;

// 无返回值
run("加载人脸模型", () -> faceDetectService.init());

// 有返回值
String token = supply("获取 ARO Token", () -> aroService.login());

// 自定义输出流
LoadingSpinner.on(someStream).run("导出报表", () -> export());
```

### 效果

```
  ⠋ 加载人脸模型 …
  ✓ 加载人脸模型 (3.8s)
```

### 禁止的写法

```java
// ❌ 禁止：没有任何进度反馈
log.info("[FaceModel] 开始加载…");
faceService.init();
log.info("[FaceModel] 加载完成");

// ✅ 正确：用 LoadingSpinner 包裹
LoadingSpinner.run("加载人脸模型", () -> faceService.init());
```

## 二、进度条（ProgressBar）

### 何时使用

- 分批拉取数据（WinCC 680 点分 5 批）
- 逐页同步人员数据（"ARO 同步第 3/12 页"）
- 批量处理记录

### API

```java
LoadingSpinner.progress("WinCC测量", 680, tick -> {
    for (int i = 0; i < 5; i++) {
        List<Point> batch = fetchBatch(i);
        tick.accept(batch.size()); // 报告本批数量
    }
});
```

### 效果

```
  ⠋ WinCC测量 [████████████░░░░░░] 60% (408/680)
  ✓ WinCC测量 (2.1s)
```

## 三、启动阶段（@StartupPhase）

已有框架自动处理，无需手动调用 LoadingSpinner。详见 `docs/superpowers/specs/2026-06-30-logging-system-design.md`。

```java
@StartupPhase(name = "数据库迁移", order = 2, subtasks = true)
@Component
public class MyBootstrap implements StartupRunner {
    public StartupResult run(StartupContext ctx) {
        ctx.subtask("login-branding", () -> runScript("db/bootstrap-xxx.sql"));
        ctx.subtask("admin-template", () -> runScript("db/bootstrap-yyy.sql"));
        return StartupResult.success("28/28 就绪");
    }
}
```

## 四、日志级别速查

| 级别 | 目标 | 控制台可见？ | RingBuffer 可见？ |
|------|------|------------|-----------------|
| ERROR | 需要立即处理的问题 | ✅ 是 | ✅ 是 |
| WARN | 潜在问题、降级行为 | ✅ 是 | ✅ 是 |
| INFO | 重要业务事件 | ❌ 否（被 ThresholdFilter 拦截） | ✅ 是 |
| DEBUG | 调试细节 | ❌ 否 | ✅ 是 |

**INFO 级别不再打印到控制台**。如需查看 INFO/DEBUG，访问：
```
GET /api/admin/logging/recent?count=200&minLevel=INFO
```

## 五、检查清单

在提交代码前，自查以下项目：

- [ ] 所有 `log.info("正在…")` + `doSomething()` + `log.info("完成")` 模式已替换为 `LoadingSpinner`
- [ ] 所有可计数的批量操作使用 `LoadingSpinner.progress()`
- [ ] 新增启动初始化逻辑使用 `@StartupPhase` 而非 `@PostConstruct` 手写日志
- [ ] 无 `System.out.println` 直接输出（用 LoadingSpinner 或 slf4j）
- [ ] 无硬编码 `log.info` 打印"已就绪""已完成"（成功静默，失败才说话）
