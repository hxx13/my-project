## 二、启动类配置

**文件**：`TwinSystemApplication.java`

```java
@SpringBootApplication
@MapperScan({
    "com.example.demo.modules.*.mapper",
    "com.example.demo.modules.twin.*.mapper",
    "com.example.demo.modules.accessfusion.mapper"
})
@EnableScheduling
@EnableAsync
public class TwinSystemApplication {
    public static void main(String[] args) {
        SpringApplicationBuilder builder = new SpringApplicationBuilder(TwinSystemApplication.class);
        builder.headless(false);
        builder.run(args);
    }

    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
```

**关键点**：
- 使用 `SpringApplicationBuilder` 而非 `SpringApplication.run()`，设置了 `headless(false)`
- `@MapperScan` 分三组路径：`modules.*.mapper` 通配大部分，`modules.twin.*.mapper` 覆盖 `twin` 模块的多级子包，`modules.accessfusion.mapper` 为特殊路径单独声明
- `@EnableScheduling` 开启定时任务，`@EnableAsync` 开启异步方法

## 五、模块内部结构

每个模块遵循统一的分层：

```
modules/{module}/
├── controller/          ← @RestController
├── service/             ← @Service（业务逻辑）
├── mapper/              ← @Mapper 接口（MyBatis）
├── entity/              ← @Data POJO（数据库行映射）
└── dto/                 ← 请求/响应 DTO
```

**特殊结构**：`twin` 模块包含多级子包（`scan/`、`dashboard/`、`card/`、`dahua/`、`order/`、`audit/`、`sync/`、`common/`），每个子包内部仍遵循 controller/service/mapper/entity/dto 结构。

## 六、Controller 层（当前实际模式）

**类级注解模板**：
```java
@RestController
@RequestMapping("/api/{module}")       // 全小写、短横线分隔
@CrossOrigin("*")
@Tag(name = "{模块中文名}")
public class XxxController {
    private final XxxService xxxService;
    private final AuthContextService authContextService;
    // 构造函数注入（不使用 @Autowired 字段注入）
}
```

**方法级模式**：
- `@GetMapping("/{id}")` + `@Operation(summary = "...")` → 返回 `Result<XxxView>`
- `@PostMapping` + `@RequestBody @Valid` → 返回 `Result<?>`
- `@GetMapping("/list")` + `@RequestParam(defaultValue = "1") int page` → 返回 `Result<PageResult<XxxView>>`
- 获取当前用户：`authContextService.resolveUserFromBearer(request.getHeader("Authorization"))`
- `/api/v1/twin/` 前缀用于扫码引擎专用接口

## 七、Service 层（当前实际模式）

```java
@Service
public class XxxService {
    private final XxxMapper xxxMapper;
    private final OtherModuleService otherService;  // 跨模块依赖

    public XxxService(XxxMapper xxxMapper, OtherModuleService otherService) {
        this.xxxMapper = xxxMapper;
        this.otherService = otherService;
    }

    @Transactional  // 仅写操作加事务
    public void create(CreateXxxRequest req, User operator) { ... }

    public XxxView findById(String id) {  // 读操作不加 @Transactional
        XxxEntity entity = xxxMapper.findById(id);
        if (entity == null) {
            throw TwinBusinessException.of(ErrorCodeConstants.NOT_FOUND, "记录不存在");
        }
        return toView(entity);
    }
}
```

**实际遵循的规则**（从代码中观察到）：
- 构造函数注入，不使用 `@Autowired` 字段注入
- `@Transactional` 仅用于多表写入场景，读方法不加
- 业务异常统一用 `TwinBusinessException.of(code, msg)`
- 跨模块通知走 `NotificationService.publish()`
- 写操作返回 void/int，不返回 entity

## 八、Mapper 层（当前实际模式）

```java
@Mapper
public interface XxxMapper {
    XxxEntity findById(@Param("id") String id);
    List<XxxEntity> listByCondition(@Param("status") String status,
                                     @Param("offset") int offset,
                                     @Param("limit") int limit);
    int insert(XxxEntity entity);
    int update(XxxEntity entity);
}
```

**XML 模板要点**：
- `<resultMap>` 显式映射蛇形/驼峰字段
- `<sql id="Base_Column_List">` 复用列名
- 单行查询加 `LIMIT 1`
- 动态条件用 `<if>` 标签
- 每个 UPDATE 必含 `update_time = NOW()`

## 九、Entity（当前实际模式）

- 注解：`@Data`（Lombok）
- 无 JPA 注解（项目不使用 Hibernate）
- 时间类型：`LocalDateTime`
- 主键：业务单据用 `String id`（UUID），系统表用 `Long id`（自增）
- 软删除字段：`deleted` + `deletedTime` + `purgeAfterTime`

## 十、统一响应体 Result\<T\>

```json
{ "code": 200, "success": true, "message": "操作成功", "data": { ... } }
```

- `Result.success()` / `Result.success(data)` / `Result.success(data, msg)`
- `Result.fail(code, msg)` — 业务失败，带错误码
- `Result.error(msg)` — 通用 500
- 前端判断：`response.data.code === 200` 或 `response.data.success === true`
- 错误码从 `ErrorCodeConstants` 引用，不手写数字

---

## 十一、异常处理

```
RuntimeException
└── TwinBusinessException (int code + String message)
```

全局处理器（`@RestControllerAdvice`）：
- `TwinBusinessException` → `ex.getCode()`
- `MethodArgumentNotValidException` / `BindException` → 400
- `NoResourceFoundException` → 404
- `Exception`（兜底）→ 500，不暴露堆栈

Controller 不 try-catch 业务异常，交给全局处理器统一处理。

---

## 十二、认证与授权

**Token 机制**：当前使用模拟 JWT（格式 `jwt_mock_token_{userId}`），由 `JwtTokenService` 签发。`AuthContextService` 从 `Authorization: Bearer <token>` 中提取 userId → 查 User 表 → 返回 User 对象。

**鉴权层级**：
- `AdminAuthInterceptor`：拦截 `/api/admin/**`，要求 `role.level >= STAFF(2)`
- `ApiAuthInterceptor`：业务操作级鉴权
- `AuthEndpointRateLimitFilter`：认证接口频率限制

**角色层级**：`STUDENT(1) < STAFF(2) < SENIOR(3) < ADMIN(4) < SUPER_ADMIN(5) < PLATFORM_OWNER(6)`

---

## 十三、定时任务与异步

- 定时任务：`@Scheduled` + `@Component`，主线程池 8 线程，WinCC 遥测有独立线程池
- 异步任务：`@Async("coreTaskExecutor")` (4-10 线程) 和 `@Async("heavyCalcExecutor")` (2-4 线程)

---

## 十四、数据库约定

**表命名**：`sys_` 系统表，业务表无前缀，`access_` 门禁清洗，`telemetry_` 遥测，`twin_` 孪生核心

**DDL 管理**：
```
schema.sql                  ← 权威建表语句
db/bootstrap-*.sql          ← 启动时自动执行
scripts/*.ddl.sql           ← 增量变更（手动执行）
*SchemaMigrator.java        ← 模块级 Java 迁移器（启动时检测并 ALTER）
```

**字段约定**：单列主键 `id`，时间戳 `create_time` / `update_time` DATETIME，软删除 `deleted INT DEFAULT 0`，编码 `utf8mb4`
