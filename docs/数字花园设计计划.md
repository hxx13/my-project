## 二、仓库策略

### 决策：单仓库（不新建独立库）

| 维度 | 单仓库 | 独立库 |
|------|--------|--------|
| 文档引用源码 | ✅ 直接引用 | ❌ 跨库链接断裂 |
| 版本同步 | ✅ 代码和文档原子 commit | ❌ 需手动对齐 |
| 导图工具 | ✅ `npm run mindmap` 直接扫 | ❌ 需跨库配置 |
| Agent 操作 | ✅ 一次 clone | ❌ 需管理两个仓库 |
| 复杂度 | ✅ 低 | ❌ 高 |

**结论**：所有内容留在 `hxx13/my-project`。管理后台新增 `/admin/docs` 路由模块。文档原始数据放 `src/main/resources/docs/` 或 MySQL 表。

### 4.3 技术选型

| 组件 | 选型 | 原因 |
|------|------|------|
| 文档渲染 | React 组件 + DOMPurify | 安全渲染 HTML，防止 XSS |
| 代码高亮 | Prism.js 或 highlight.js | 轻量，支持 Java/XML/SQL |
| Markdown 编辑 | @uiw/react-md-editor | 国产，支持预览，GitHub 风格 |
| 表格渲染 | 原生 HTML table | 保留原始格式 |
| 图片处理 | 保留 base64 或提取为静态文件 | 见 4.4 |

### 4.4 图片处理

原始 HTML 中的图片是 base64（`data:image/png;base64,...`），两种处理方式：

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 保留 base64 | 零处理，内容完整 | 页面体积大（~500KB/页），加载慢 |
| B. 提取为文件 | 加载快，可缓存 | 需预处理，存储管理 |
| **C. 懒加载 + 占位** | 兼顾体验和性能 | 实现稍复杂 |

**推荐方案 A（保留 base64）**：内网/本地使用，加载速度可接受。后续可渐进优化为 B。

## 五、编辑功能与元数据

### 5.1 文档元数据 Schema

每个文档页面的数据结构（对应 MySQL 表 `doc_pages`）：

```sql
CREATE TABLE doc_pages (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    category    VARCHAR(100)  NOT NULL,        -- 分类：后端手册、AI大模型 等
    slug        VARCHAR(200)  NOT NULL,        -- URL 标识：module-new
    title       VARCHAR(200)  NOT NULL,        -- 标题：新建模块
    content     MEDIUMTEXT    NOT NULL,        -- HTML 正文内容
    source      VARCHAR(20)   DEFAULT 'manual',-- 来源：imported / agent / manual
    version     INT           DEFAULT 1,       -- 版本号（每次保存 +1）
    author      VARCHAR(100)  DEFAULT 'system',-- 作者：用户名 或 agent-id
    created_at  DATETIME      DEFAULT NOW(),   -- 创建时间
    updated_at  DATETIME      DEFAULT NOW(),   -- 最后修改时间
    INDEX idx_category (category),
    INDEX idx_slug (category, slug)
);
```

### 5.2 修改历史表

```sql
CREATE TABLE doc_history (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    page_id     BIGINT        NOT NULL,        -- 关联 doc_pages.id
    version     INT           NOT NULL,        -- 版本号
    content     MEDIUMTEXT    NOT NULL,        -- 该版本的完整内容快照
    author      VARCHAR(100)  NOT NULL,        -- 修改人
    summary     VARCHAR(500),                  -- 修改摘要
    created_at  DATETIME      DEFAULT NOW(),   -- 修改时间
    FOREIGN KEY (page_id) REFERENCES doc_pages(id)
);
```

### 5.3 自动时间戳规则

当文档被创建或修改时，系统自动处理：

| 操作 | created_at | updated_at | version | 历史记录 |
|------|-----------|-----------|---------|---------|
| 新建文档 | 当前时间 | = created_at | 1 | 插入 v1 |
| 编辑保存 | 不变 | 当前时间 | +1 | 插入新版本 |
| Agent 导入 | 当前时间 | = created_at | 1 | 插入 v1，标记 author=agent-id |
| 回滚到历史版本 | 不变 | 当前时间 | +1 | 插入新版本（内容=旧版本） |

**前端渲染时间戳**：文档底部显示：

```
创建于 2026-06-09 14:30 · 最后修改 2026-06-10 09:15 · 版本 v3 · 作者 Claude
```

## 六、Agent 集成

### 6.1 Agent 导入 .md 文件

**API 端点**：`POST /api/docs/import`

```json
{
  "category": "后端手册",
  "title": "新建模块",
  "content": "# 新建模块\n\n本章节将介绍...",
  "format": "markdown",
  "author": "claude-agent",
  "source": "agent"
}
```

**后端处理**：
1. 将 Markdown 转为 HTML（使用 `commonmark-java` 或 `flexmark`）
2. 写入 `doc_pages` 表，自动生成 `created_at`、`updated_at`、`version = 1`
3. 写入 `doc_history` 表，记录 v1 快照
4. 返回创建的文档 ID 和 URL

**Agent 使用示例**（Agent 视角）：

```bash
# Agent 生成文档后，通过 API 导入
curl -X POST https://xxx.com/api/docs/import \
  -H "Content-Type: application/json" \
  -d '{
    "category": "后端手册",
    "title": "自定义序列化器",
    "content": "# 自定义序列化器\n\n## 背景\n...",
    "format": "markdown",
    "author": "claude-opus-4"
  }'
```

### 6.2 Agent 批量导入

`POST /api/docs/import-batch`

```json
{
  "author": "claude-agent",
  "documents": [
    { "category": "后端手册", "title": "文档A", "content": "..." },
    { "category": "AI大模型", "title": "文档B", "content": "..." }
  ]
}
```

### 6.3 Agent 导出

`GET /api/docs/export/:pageId?format=md`

返回原始 Markdown（如果内容是 Markdown 转换来的）或 HTML→MD 转换结果，方便 Agent 读取和二次编辑。

## 八、关键注意事项

### 给下一个 Agent 的提醒

1. **HTML 内容源**：文件在 `D:\codex\YUDAO\ruoyi-vue-pro\`，23 个分类目录，326 个文件。每个 HTML 包含完整的内联 CSS 和 base64 图片。

2. **安全检测层**：原始 HTML 的 `<body>` 内有 `<div id="yudao_9f6bd39458">文档安全环境检测中...</div>` 和 `<div id="yudao_26c55123a9" style="opacity:0.001; filter:blur(20px)">`，导入前必须移除。

3. **不要转为 Markdown**：之前的尝试（turndown）丢失了表格格式和图片，且 326 个文件全量转换质量不可控。HTML 原文渲染是最可靠的方式。

4. **文件命名**：原始 HTML 文件名格式为 `标题 _ ruoyi-vue-pro 开发指南 (日期).html`，提取标题时需去掉后缀部分。

5. **侧边栏链接**：原始 HTML 内包含完整的 doc.iocoder.cn 链接（约 340 个），导入后应替换为本地路由 `/admin/docs/:category/:slug`。

6. **base64 图片**：部分文件有 10+ 张 base64 截图，单文件可达 1MB+。前端渲染时需考虑性能（懒加载）。

7. **时间戳格式**：统一使用 ISO 8601 格式存储（`2026-06-09T14:30:00+08:00`），前端展示时格式化为中文格式（`2026年6月9日 14:30`）。

8. **Agent 作者标识**：不同 Agent 导入文档时，author 字段格式建议为 `agent:{agent-name}:{version}`，例如 `agent:claude:opus-4`。
