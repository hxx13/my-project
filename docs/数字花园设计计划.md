> **目标**：在 TwinSystem 管理后台中新建独立的知识库模块，统一管理所有开发文档——YUDAO 导入的 326 份 HTML 参考手册、Agent 生成的技术文档、人工编写的操作指南和架构设计文档。
>
> **交付对象**：下一个 Agent（AI 开发者），本文档是完整的设计规格。
>
> **设计日期**：2026-06-09
>
> **版本**：v2（全面重构，对齐项目标准化架构）

## 二、数据库设计

### 2.1 knowledge_categories（分类）

```sql
CREATE TABLE knowledge_categories (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(100)  NOT NULL,               -- 分类名称：后端手册、AI大模型 等
    slug        VARCHAR(100)  NOT NULL UNIQUE,        -- URL 标识：backend-manual
    sort_order  INT           DEFAULT 0,              -- 排序（拖拽调整）
    icon        VARCHAR(50)   DEFAULT 'BookOpen',      -- Lucide 图标名
    description VARCHAR(300),                         -- 分类描述
    created_at  DATETIME      DEFAULT NOW(),
    updated_at  DATETIME      DEFAULT NOW()
);
```

**初始数据**：YUDAO 导入时自动扫描 23 个目录名，创建对应分类记录。文件名格式 `标题 _ ruoyi-vue-pro 开发指南 (日期).html`，从中提取分类名。

### 2.2 knowledge_pages（文档）

```sql
CREATE TABLE knowledge_pages (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    category_id   BIGINT        NOT NULL,              -- 关联分类
    slug          VARCHAR(200)  NOT NULL,              -- URL 标识：module-new
    title         VARCHAR(300)  NOT NULL,              -- 文档标题
    content_html  MEDIUMTEXT    NOT NULL,              -- HTML 内容（渲染用）
    content_md    MEDIUMTEXT,                          -- Markdown 内容（编辑用，可为空）
    source        VARCHAR(20)   DEFAULT 'manual',      -- 来源：imported / agent / manual
    version       INT           DEFAULT 1,             -- 版本号（每次保存 +1）
    author        VARCHAR(100)  DEFAULT 'system',      -- 作者：用户名 或 agent-id
    is_published  TINYINT(1)    DEFAULT 1,             -- 是否发布
    created_at    DATETIME      DEFAULT NOW(),
    updated_at    DATETIME      DEFAULT NOW(),
    UNIQUE INDEX idx_category_slug (category_id, slug),
    INDEX idx_category (category_id),
    INDEX idx_updated (updated_at),
    FOREIGN KEY (category_id) REFERENCES knowledge_categories(id)
);
```

**双格式存储策略**：
- `content_html` 始终非空——用于渲染
- `content_md` 可选——Markdown 编辑者的编辑源。新建 MD 文档时通过 flexmark 生成 HTML；HTML 导入时 `content_md` 为 NULL
- 编辑时：有 MD 则在 MD 编辑器打开，否则在 HTML 编辑器打开

### 2.3 knowledge_history（版本历史）

```sql
CREATE TABLE knowledge_history (
    id           BIGINT AUTO_INCREMENT PRIMARY KEY,
    page_id      BIGINT        NOT NULL,
    version      INT           NOT NULL,
    content_html MEDIUMTEXT    NOT NULL,              -- 该版本的完整 HTML 快照
    content_md   MEDIUMTEXT,                          -- 该版本的 MD 快照
    author       VARCHAR(100)  NOT NULL,
    summary      VARCHAR(500),                        -- 修改摘要
    created_at   DATETIME      DEFAULT NOW(),
    FOREIGN KEY (page_id) REFERENCES knowledge_pages(id)
);
```

### 2.4 自动时间戳规则

| 操作 | created_at | updated_at | version | 历史记录 |
|------|-----------|-----------|---------|---------|
| 新建文档 | 当前时间 | = created_at | 1 | 插入 v1 |
| 编辑保存 | 不变 | 当前时间 | +1 | 插入新版本 |
| Agent 导入 | 当前时间 | = created_at | 1 | 插入 v1，author=agent-id |
| 回滚到历史版本 | 不变 | 当前时间 | +1 | 插入新版本（内容=历史快照） |

### 3.4 Service 层核心逻辑

**KnowledgePageService.saveOrUpdate()**：
1. 若 `content_md` 非空 → 用 flexmark 将 MD 转为 HTML → 写入 `content_html`
2. 若仅有 `content_html` → 保留原样，`content_md` 置空
3. 服务端 jsoup 清洗 HTML（见安全设计），再写入数据库
4. `version + 1`，更新 `updated_at`
5. 向 `knowledge_history` 插入快照

**KnowledgePageService.rollback()**：
1. 读取 `knowledge_history` 中指定版本的快照
2. 将快照内容覆盖当前页面
3. `version + 1`（回滚是新版本）
4. 向 `knowledge_history` 插入新记录

**KnowledgeImportService**（见第五章）。

### 4.6 TanStack Query Hooks 设计

遵循项目现有模式，每个查询 Hook 封装一个 API 调用：

| Hook | Query Key | Stale Time | 说明 |
|------|-----------|-----------|------|
| `useKnowledgeTree()` | `['knowledge', 'tree']` | 5 min | 分类树 + 文档列表 |
| `useKnowledgePage(id)` | `['knowledge', 'page', id]` | 5 min | 单页内容 |
| `useKnowledgePageBySlug(catId, slug)` | `['knowledge', 'page', catId, slug]` | 5 min | 按 slug 获取 |
| `useKnowledgeHistory(pageId)` | `['knowledge', 'history', pageId]` | 2 min | 版本历史 |
| `useKnowledgeSearch(params)` | `['knowledge', 'search', params]` | 0（始终新鲜） | 搜索结果 |
| `useKnowledgeCategoryManager()` | `['knowledge', 'categories']` | 10 min | 分类管理 |

Mutation Hooks（成功后自动 invalidate 相关 queries）：

| Hook | 成功后 invalidate |
|------|-----------------|
| `useKnowledgeSave(pageId?)` | `tree`, `page/${id}`, `history/${id}` |
| `useKnowledgeImport()` | `tree` |
| `useKnowledgeRollback(pageId)` | `page/${id}`, `history/${id}` |

### 4.7 内容渲染组件（`KnowledgePageRenderer`）

双模渲染逻辑：
- 若 `contentHtml` 非空 → DOMPurify 清洗 → `dangerouslySetInnerHTML`
- 若 `contentMd` 非空且无 HTML → 用 `components/markdown/` 已有组件渲染
- 代码高亮：复用项目中已有的 highlight.js / Prism.js（与 markdown 组件一致）
- 图片懒加载：`loading="lazy"` + Intersection Observer 渐进加载

## 五、内容导入设计

### 5.1 YUDAO HTML 批量导入

**数据源**：`D:\codex\YUDAO\ruoyi-vue-pro\` — 23 个目录，326 个 HTML 文件。

**处理流程**（`KnowledgeImportService.importYudaoHtml()`）：

1. 遍历 23 个目录，每个目录名 → 新建/匹配 `knowledge_categories` 记录
2. 每个 HTML 文件：
   - 解析文件名提取标题（去掉 `_ ruoyi-vue-pro 开发指南 (日期)` 后缀）
   - jsoup 读取 `<body>` 内容
   - 移除安全检测层：`<div id="yudao_9f6bd39458">` 和 `<div id="yudao_26c55123a9">`
   - 替换 doc.iocoder.cn 外链为本地路由 `/admin/knowledge/page/{id}`
   - 清洗 HTML（白名单标签）
   - 写入 `knowledge_pages`：`source='imported'`, `version=1`
   - 写入 `knowledge_history` 快照
3. 统计并返回导入结果（成功数 / 跳过数 / 错误列表）

**调用方式**：Phase 2 启动脚本直接调用 `KnowledgeImportService`，或通过 `POST /api/admin/knowledge/pages/import-batch` 触发。

### 5.2 Agent 导入（单篇/批量）

**API 端点**：`POST /api/admin/knowledge/pages/import`

请求体：
```json
{
  "categoryId": 1,
  "title": "自定义序列化器",
  "content": "# 自定义序列化器\n\n## 背景\n...",
  "format": "markdown",
  "author": "agent:claude:opus-4"
}
```

**服务端处理**：
1. 若 `format = "markdown"` → flexmark 转为 HTML → 写入 `content_html`，`content_md` 保留原始 MD
2. 若 `format = "html"` → jsoup 清洗 → 写入 `content_html`
3. 生成 `slug`（从标题自动推导）
4. 写入 `knowledge_pages`：`source='agent'`, `version=1`
5. 写入 `knowledge_history` v1 快照
6. 返回创建的文档 ID

**批量导入**：`POST /api/admin/knowledge/pages/import-batch`，数组格式，单次最多 50 篇。

**Agent 作者标识格式**：`agent:{name}:{version}`，例如 `agent:claude:opus-4`。

### 5.3 导出

`GET /api/admin/knowledge/pages/{id}/export?format=md`

- 若有 `content_md` → 直接返回原始 MD
- 若仅有 `content_html` → jsoup 提取纯文本 → 返回 TXT（不做 HTML→MD 转换，之前 turndown 丢失格式的教训）

### 5.4 旧 MD 文件清理

此前用 turndown 从 YUDAO HTML 转换出的 Markdown 文件可以删除。新流程走 HTML 原文导入 + 双格式存储，不再需要这些转换产物。

## 六、安全设计

### 6.1 认证

所有 `/api/admin/knowledge/**` 端点由现有 `AdminAuthInterceptor` 直接覆盖，解析 JWT Token 后注入 `User` 到 Request Attribute。无需额外拦截器。

### 6.2 鉴权（角色→操作映射）

| 操作 | SUPER_ADMIN | ADMIN | STAFF | STUDENT |
|------|:---:|:---:|:---:|:---:|
| 查看文档 | ✅ | ✅ | ✅ | ❌ |
| 新建/编辑文档 | ✅ | ✅ | ❌ | ❌ |
| 删除文档 | ✅ | ❌ | ❌ | ❌ |
| 管理分类 | ✅ | ❌ | ❌ | ❌ |
| 批量导入 | ✅ | ❌ | ❌ | ❌ |
| 回滚 | ✅ | ✅ | ❌ | ❌ |

Controller 方法级使用 `requireRole()` 或 `@RoleEnum` 注解（与现有 Controller 模式一致）。

### 6.3 XSS 防护

**服务端（写入前）**：jsoup HTML 清洗，白名单策略：
- 允许标签：`h1-h6, p, a, img, table, thead, tbody, tr, th, td, ul, ol, li, code, pre, blockquote, strong, em, hr, br, div, span, details, summary`
- 允许属性：`href, src, alt, class, id, width, height, colspan, rowspan, target`
- 禁止：`script, style, iframe, object, embed` 及所有 `on*` 事件属性
- base64 图片放行：`src` 中以 `data:image/` 开头

**前端（渲染时）**：DOMPurify 二次清洗后 `dangerouslySetInnerHTML`：
```typescript
const cleanHtml = DOMPurify.sanitize(contentHtml, {
  ALLOW_DATA_ATTR: false,
  ALLOWED_TAGS: [...],  // 与后端白名单一致
});
```

### 6.4 速率限制

复用已有 `AuthEndpointRateLimitFilter`。导入端点额外限制：`POST /import-batch` 每分钟最多 5 次。

### 6.5 CSRF

项目使用 JWT Bearer Token 认证方式，无 Cookie-based session，CSRF 风险天然可控。无需额外配置。

## 十三、边缘情况与错误处理

| 场景 | 处理方式 |
|------|---------|
| 分类下无文档 | 左侧树展开后显示"暂无文档"空状态 |
| 文档内容为空 | 渲染时显示"该文档暂无内容"空状态 |
| 重复 slug（同一分类下） | 返回 409，前端提示"该分类下已存在相同标识的文档" |
| 同时编辑冲突 | MVP 不做乐观锁，最后保存者胜出。后续可加 version 校验（409 冲突） |
| 删除含文档的分类 | 返回 400，"该分类下有 N 篇文档，请先移动或删除" |
| 导入格式不支持 | 返回 400，"支持的导入格式：markdown, html" |
| YUDAO HTML 无标题可提取 | 使用文件名作为 title |
| YUDAO HTML 无正文 | 跳过，计入 error 列表 |
| base64 图片过大（>1MB） | 服务端不限制，前端 Intersection Observer 懒加载 |
| 搜索无结果 | 显示 EmptyState + 建议修改查询词 |
| 网络断开 | ErrorRetry 组件 + 手动重试按钮 |
| 导出无 MD 内容 | 返回 HTML 纯文本提取 |
| 并发导入（同一分类+slug） | 数据库 UNIQUE 约束拦截，返回 409 提示重复 |

## 十七、约束与原则

1. **不转为纯 Markdown**：之前 turndown 转换丢失了表格格式和图片。HTML 原文渲染 + 双格式存储替代。
2. **不新建仓库**：单仓库，知识库与项目代码原子 commit。
3. **不重复造轮子**：复用 `components/markdown/`、`components/ui/*`、`adminHttp`、已有的工具函数。
4. **不动已有 API**：现有 `AdminDocsController`（API 发现工具）保持不动，知识库使用独立的前缀 `/api/admin/knowledge/`。
5. **自动建表**：遵循 `[[feedback_auto_create_tables]]` 规范，`KnowledgeSchemaMigrator` 在启动时自动执行 DDL。
6. **Hash 路由**：`createHashRouter`，维持项目现有路由模式。
7. **adminHttp 实例**：所有知识库 API 调用使用现有 `adminHttp`，不创建新 Axios 实例。
8. **Agent 作者标识**：格式 `agent:{name}:{version}`，例如 `agent:claude:opus-4`。
9. **时间格式**：数据库存 ISO 8601，前端用 `formatDateTimeAsiaShanghai` 转中文展示。
10. **旧 MD 文件**：此前 turndown 转换出的 MD 产物可以删除。
