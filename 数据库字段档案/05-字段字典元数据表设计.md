# 05-字段字典元数据表设计（CRF/EDC 结构层）

> 状态：**设计态（待建）**。本文件定义 NHP 业务「字段字典元数据化」的 11 张表结构、冻结状态机、与四步走的对接规则。**在建表前必读**。
>
> 定位：字段字典从「markdown 文档」升级为「数据库元数据表」，字段新增 = 插一行数据，冻结后才实体化为物理列。
>
> 锚定标准：CDISC ODM（Operational Data Model，IND 申报认的临床数据交换标准）的实体模型。

## 一、三个前瞻性洞见

1. **字段定义 ≠ 字段引用**。`donor_id` 在 D1 是主键、在 D3/D10 是外键、在 D9 是关联字段——同一字段多域复用，角色不同。故拆「字段定义（ItemDef）」与「表单内字段引用（ItemRef）」两层。
2. **字段 ≠ 字段版本**。CRF V1.0 冻结后 V1.1 要加肾脏模块、可能改字段单位/码表。冻结后不可改但可演进 → 版本 + 冻结状态机。
3. **码表 ≠ 静态下拉**。码表本身要版本化、冻结、可追溯（04 已规定「码表变更走版本流程」）。

## 二、表结构总览（11 张，分两层）

```
核心层（先建）
  crf_study           研究项目/方案（多研究隔离）
  crf_center          中心/机构（SJ/SH/RJ/XH/HS 跨中心扩展）
  crf_form            表单 = 数据域 D1~D10（含版本）
  crf_section         子模块 D1.01 个体档案
  crf_field           字段定义（ItemDef，含版本+冻结）
  crf_form_field      表单-字段引用（ItemRef，位置/必填/角色）
  crf_codelist        码表（含版本+冻结）
  crf_codelist_item   码表项

机制层（结构预留，二期建）
  crf_visit           访视/时点（TP-01~TP-12，事件驱动）
  crf_validation_rule 校验/分支规则（范围/正则/跨字段/跳题）
  crf_dict_change_log 字段字典变更审计（ALCOA+）
```

## 三、逐表定义（接口契约，非 DDL）

### 3.1 crf_field — 字段定义（核心，ItemDef）

| 列 | 说明 |
|---|---|
| id | BIGINT PK |
| field_code | VARCHAR(32) UNIQUE，`D1.02.003`（字典追溯码，人读） |
| name_en | VARCHAR(64) UNIQUE，DB 列名 snake_case（`donor_id`） |
| name_cn | VARCHAR(128)，中文名 |
| data_type | VARCHAR(32)，标准化枚举（见第四节） |
| unit | VARCHAR(32) NULL，单位（`mg/kg`） |
| precision | INT NULL，数值精度 p,s（前瞻：DECIMAL 需要） |
| required | VARCHAR(8)，`YES / NO / CONDITIONAL`（条件必填） |
| codelist_id | BIGINT NULL FK → crf_codelist（枚举字段） |
| description | TEXT，说明（含「条件必填」触发条件） |
| status | VARCHAR(20)，`DRAFT / PENDING_REVIEW / FROZEN / RETIRED` |
| version | INT，版本号，随冻结递增 |
| frozen_at / frozen_by | 冻结留痕 |
| active / created_at / updated_at | 软删 + 时间戳 |

### 3.2 crf_form_field — 字段引用（ItemRef，前瞻核心）

同一 `donor_id` 在不同域的角色：

| 列 | 说明 |
|---|---|
| form_id | 所在表单（D1/D3/D10） |
| field_id | 引用的字段定义 |
| role | `PK / FK / VALUE / DERIVED`（主键/外键/采集值/派生） |
| position | 表单内顺序 |
| required_override | 覆盖该表单内必填（NULL=沿用字段默认） |
| logic_ref | 分支/显隐逻辑引用 |

### 3.3 crf_codelist + crf_codelist_item — 码表版本化

| crf_codelist | 说明 |
|---|---|
| code | `BREED / EDIT / FARM` |
| name | 码表名 |
| version | 版本 |
| status | 冻结状态 |

| crf_codelist_item | 说明 |
|---|---|
| codelist_id | 归属码表 |
| item_code | 稳定码（`SH` / `GTKO`） |
| item_label | 显示名 |
| sort_order | 排序 |
| active | 软删 |

> 关键：采集记录存 `codelist_item_id`（或 item_code + version），**不存 label**——码表改 label 不改 code，历史记录仍可追溯。

### 3.4 支撑表

- `crf_form`：`study_id` + `code(D1..D10)` + `form_type(DOMAIN/MODULE/公共层)` + `version` + `status`。器官模块（D9/D10）作为独立 form 挂 study 下；V1.1 肾脏模块 = 新增一个 form 记录，复用主干字段引用。
- `crf_section`：`form_id` + `code(D1.01)` + `name`，承载「域内子模块」分组。
- `crf_study`：`code(NHP-XENO)` + `protocol_version`，多研究/多方案隔离。
- `crf_center`：`code(SJ/SH/RJ/XH/HS)` + `name`，对应 04 编码规则的跨中心扩展。

### 3.5 机制层三表

- `crf_visit`：`code(TP-01..TP-12)` + `seq` + `repeating`（随访=重复事件）+ `planned_days`（术后相对天数）。事件驱动随访（「事件触发随访挂 TP10」）靠它表达。
- `crf_validation_rule`：`field_id` + `rule_type(RANGE/REGEX/CROSS_FIELD/SKIP)` + `expression`（结构化 JSON）。承接「条件必填」与 AUP 条件联动。
- `crf_dict_change_log`：`entity(field/codelist/form)` + `entity_id` + `change_type` + `before/after(JSON)` + `operator` + `created_at`。ALCOA+ 审计落点，也是《变更日志.md》的数据库镜像。

## 四、data_type 标准化枚举（锚定 CDISC ODM）

| code | 说明 | 落库 |
|---|---|---|
| STRING | 短字符/编号 | VARCHAR |
| TEXT | 长文本 | TEXT |
| INTEGER | 整数 | INT |
| DECIMAL | 数值带精度 | DECIMAL(p,s) |
| DATE / DATETIME | 日期/时间 | DATE / DATETIME |
| BOOLEAN | 开关 | TINYINT |
| ENUM | 单选枚举 | VARCHAR + codelist FK |
| ENUM_MULTI | 多选枚举 | 关联表 |
| CALC | 计算/派生字段 | 不落库 |
| FILE | 附件/影像 | 文件表引用 |

## 五、冻结 → 物理列（状态机）

```
DRAFT ──PI校对──▶ PENDING_REVIEW ──冻结──▶ FROZEN ──▶ 生成真实列(四步走)
   │                                              │
   └──────────────── RETIRED ◀────────────────────┘（升级到新版本）
```

- `DRAFT`：数据走 JSON 扩展列，随便改，只动 `crf_field` 一行。
- `FROZEN`：触发受控建列——从 `crf_field` 读定义，走《01》双 SQL 四步走生成真列。
- 改已冻结字段：不直接改，`version+1` 生成新版本行 + 写 `crf_dict_change_log`，老版本 RETIRED 但保留（历史数据仍指向老版本）。

## 六、与现有体系的关系

- **复用 ref_data 哲学，不复用其表**：`crf_*` 全强类型 + 版本 + 冻结；ref_data 的 JSON 思路只留给「草稿数据层」。
- **环境变量**：只碰种子（身份标签 code、开关），字段字典一律进 `crf_field`。
- **`03` 变人读镜像**：`crf_field` 是权威，03 的 markdown 是可读副本，靠「动表必留痕」铁律同步。
