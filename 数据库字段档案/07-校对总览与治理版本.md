## 二、数据治理与合规要点

> Demo 版治理框架：权属、用途、去标识化、质控、版本与扩展

| 主题 | 规则 | 说明 |
|---|---|---|
| 数据权属 | 原始数据产权归属产生数据的机构（基地/动物中心/医院），平台依据合作协议获得去标识化数据的处理与算法训练权 | 协议须在首例数据采集前签署 |
| 用途边界 | 本平台 Demo 定位为科研查询层：队列检索、统计分析、文献与公共案例查询 | 不输出面向个体诊疗决策的建议；临床决策支持层须另行评估 SaMD 注册路径 |
| 去标识化 | 平台层不含受试者可识别信息；NHP 阶段绑定伦理批件号，临床阶段叠加人遗合规与知情同意编号 | 人类遗传资源相关事项在临床阶段启动前完成审批/备案架构设计 |
| 样本-数据绑定 | 每个检测结果的 SAMPLE_ID 可全程回溯至采集、交接、存储、委托、回传链路（CoC） | 链路断裂视为数据质量事件 |
| 数据质量 | 双人复核、异常值复测、TAT 监控、时点偏差自动标记 | 质控指标进入平台月报 |
| 版本管理 | 数据字典、panel、放行标准、研究方案全部版本化；历史数据保留与旧版本的映射 | 禁止覆盖式修改 |
| 扩展原则 | 新增中心/体系只增码不改结构；数据字典设计已预留临床阶段字段扩展位 | 支撑跨体系标准输出 |
| EDC 与审计追踪 | 数据采集进入 REDCap 本地实例后执行全字段级修改留痕（修改人/时间/原值/新值/原因），对齐 ALCOA+；双轨期纸版与 Excel 兜底数据须与 EDC 回溯录入一致性核查 | 首例数据回溯录入作为 EDC UAT 真实测试集；正式上线后电子采集为主 |
