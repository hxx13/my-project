# 09-业务流转与码表使用分析

> 状态：**分析定稿**。本文件从源文档（两份 Word + 数据字典 Excel）严谨还原 NHP 业务的**真实流转**、**时点使用**、**码表使用**，纠正此前前端设计「凭猜测画流程」的错误。
>
> 来源：《交医-NHP项目CRF及EDC建设方案 V0.1》《异种移植NHP-EDC最低建设标准》+ 数据字典 v0.3 的编码规则/码表/采集时点三张 sheet。

## 一、核心链路（不是「填写→复核→冻结」）

真实业务是围绕**移植事件 TX** 的一条链，六段：

```
供体链   供体猪建档(D1) → 基因编辑/病原监测(季度) → 术前复查 → 放行判定
                       └──────────────┐
                                     ↓  交叉配型 XM（供体-受体对）
受体链   受体猴入组(D2,TP01) → 预筛/抗猪抗体基线 → 配型(D3)
                                     ↓
手术链   移植手术 TX(D3,TP03) ← 麻醉监护(D7) + 心脏/肝灌注模块(D9/D10)
                                     ↓  再灌注即刻样本 SMP
样本链   样本采集(D4,各时点) → 委托检测 TST → 结果回传 RS
                                     ↓
随访链   免疫用药(D6 REG/MED/LVL) + 随访(D5 FU) + 病理活检(D8 PATH)
                                     ↓
结局链   终点/剖检(D5,TP11) → 数据锁定(TP12)
```

**关键：移植事件 TX 是枢纽**——样本(SMP)、检测(TST/RS)、随访(FU)、用药(MED)、病理(PATH)、麻醉(ANES)、心脏模块(HX) 全部挂接 TX 编号。一条 TX 记录 = 一例移植的完整数据入口。

## 二、TP 时点时间轴（12 时点，定义「什么字段什么时候用」）

| 时点 | 阶段 | 时间锚点 | 采集内容 / 使用字段 |
|---|---|---|---|
| TP01 | 术前筛查期 | -28d ~ -7d | 受体预筛、抗猪抗体基线、交叉配型(XM)、供体放行判定 |
| TP02 | 术前基线 | -1d ~ 0d | 免疫/凝血/炎症基线、微生物组基线、样本预存 |
| TP03 | 术中 | 0d | 再灌注即刻样本、手术事件(TX)、麻醉(ANES)、心脏/肝灌注(D9/D10) |
| TP04 | 术后早期 | 1d-7d | 每日：血常规/凝血/生化/猪源cfDNA/PERV；排斥高发窗 |
| TP05 | 术后亚急性 | 8d-28d | 每周2次：全套监测 panel；首次活检窗(PATH) |
| TP06 | 术后中期 | 29d-90d | 每周1次；免疫方案调整(REG) |
| TP07 | 术后稳定期 | 91d-180d | 每2周1次 |
| TP08 | 长期随访 | 181d-365d | 每月1次；病原潜伏监测 |
| TP09 | 超长期 | ≥366d | 每季度；终身病原学随访 |
| TP10 | 事件触发 | 随时 | 疑似排斥/感染/血栓事件加采(AE)，不受时点表限制 |
| TP11 | 终点/剖检 | 终点 | 安乐死/死亡剖检，全器官病理 + 组织库留存 |
| TP12 | 数据锁定 | 终点+30d | 单例数据清理完成、锁定归档 |

## 三、四级 ID 关联体系（16 类，均挂 TX）

| ID | 格式 | 挂接关系 |
|---|---|---|
| 供体猪 ID | DON-{基地}{年}-{序号4} | 终身唯一 |
| 受体猴 ID | RCP-{中心}{年}-{序号3} | 入组即赋码，预筛猴进配对库 |
| 配型记录 ID | XM-{DONOR}-{RECIP}-{序号} | 供-受体对，可多条 |
| **移植事件 ID** | **TX-{中心}{年}-{序号3}** | **核心枢纽，样本/检测/随访/用药/病理均挂此** |
| 随访记录 ID | FU-{TX}-{时点} | 挂 TX |
| 不良事件 ID | AE-{TX}-{日期}-{序号2} | 事件触发即赋码 |
| 免疫方案 ID | REG-{TX}-{序号2} | 挂 TX，一例多方案 |
| 用药记录 ID | MED-{REG}-{序号4} | 挂 REG，每次给药一条 |
| 血药浓度 ID | LVL-{TX}-{日期}-{序号2} | 挂 TX，采血时间记谷/峰 |
| 麻醉记录 ID | ANES-{TX} | 挂 TX |
| 病理记录 ID | PATH-{TX}-{时点}-{序号2} | 挂 TX，一次取材一条 |
| 心脏模块 ID | HX-{TX} | 挂 TX |
| 灌注记录 ID | PERF-{DON}-{日期} | 挂供体（体外肝灌注） |
| 样本 ID | SMP-{TX}-{时点}-{样本类型}-{分管2} | 挂 TX，采血即赋码，CoC 监管链 |
| 检测委托单 ID | TST-{实验室}{年月}-{序号4} | 与样本 ID 多对多 |
| 检测结果 ID | RS-{TEST_ID}-{项目码} | 挂委托单，行级唯一 |

## 四、码表使用（各域 × 码表 × 采集时点/采集方）

码表不是「静态下拉」，是**特定时点、特定采集方下的取值约束**：

| 域 | 引用的码表 | 主要采集时点 | 主要采集方 |
|---|---|---|---|
| D1 供体猪域 | FARM 基地 / BREED 品种 / EDIT 编辑组合 / PATHOGEN 病原 / ORG 器官 | 入档、季度、术前 | 基地、分子平台、受托实验室 |
| D2 受体NHP域 | CENTER 中心 / NHP_PATH 猴病原 | TP01、入组、TP02 | 受托实验室、动物中心 |
| D3 配型与手术 | IMMU 免疫方案 / ORG 器官 / PROC 术式 | TP03、TP01 | 外科团队、受托实验室 |
| D4 样本与检测 | SAMPLE 样本类型 / LAB 实验室 / ASSAY 检测项目 | 各时点、委托时、TP04-06 回传 | 平台、受托实验室、采样方 |
| D5 随访与事件 | AE 不良事件 / ENDPOINT 终点 / CAUSE 死因 | 事件触发、各时点、终点 TP11/TP12 | PI团队、病理平台、兽医团队 |
| D6 免疫抑制用药 | DRUG_IS 免疫抑制药 / IMMU 方案 / DOSE_ADJ 剂量调整 / ROUTE 给药途径 | 每次给药、方案启动、监测时点 | PI团队、护理/执行人 |
| D7 麻醉术中监护 | DRUG_ANES 麻醉药 | 术中连续、麻醉开始、术毕 | 麻醉团队 |
| D8 病理诊断 | ORG 器官 / REJ_GRADE 排斥分级 | 取材、阅片、报告签发 | 病理平台、病理医师 |
| D9 心脏移植模块 | GRAFT_H 心脏移植物 / PRESV 保存液 / ECG_RHY 心电节律 | TP03、获取、按血检频率、TP05/TP11 | 受托实验室、外科、超声、麻醉 |
| D10 体外肝灌注 | PERF 灌注方式 / LIVER_APP 肝外观 | 每3h、每15-30min、灌注启动/结束 | 受托实验室、灌注团队 |

## 五、对前端设计的修正（08 需改）

1. **记录管理页的「流程管道」错了**：不是「填写→复核→冻结→完成」，而是**以 TX 移植事件为主卡，显示供体/受体关联 + 当前 TP 时点进度 + 挂接的子记录数（样本/检测/随访/用药/病理）**。
2. **字段管理页要突出「采集时点 + 采集方 + 码表」**：这三列决定「字段什么时候、由谁、按什么取值用」，不能只当普通元数据列。
3. **码表管理要带「被哪些域/字段引用」反向视角**：码表是取值约束，要能反查「FARM 被 D1 哪些字段用、在哪个时点用」。
