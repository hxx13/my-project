# 10-EDC 通用功能架构与缺口

> 状态：**参考/缺口清单**。本文件抽象掉 NHP 具体字段，还原 REDCap / 商业 EDC（太美/易迪希/Veeva/Medidata）的**通用业务流与功能模块**，并对照现有设计（05/06/09）标出缺口。用于「基础架构打好」时的功能补全清单。

## 一、EDC 通用业务流（四阶段）

```
阶段0 研究设计(Build)    数据字典 + eCRF表单设计器 + 逻辑规则 + 码表 + 版本冻结
阶段1 站点与权限(Setup)   中心/站点 + 用户 + 角色分级 + 按数据域授权
阶段2 受试者与录入(Run)   受试者注册/随机化 + 访视计划 + 表单填写(各种控件) + 双录入
阶段3 核查与质控(Clean)   逻辑核查(edit check) + 数据质疑(query) + SDV + 医学审核
阶段4 签名锁定交付(Lock)  电子签名 + 病例锁定 + 审计追踪 + CDISC导出 + 数据库锁定
```

## 二、字段控件类型全集

| 控件类型 | 说明 | 现有设计 |
|---|---|---|
| 文本 | 单行/多行 | ✅ value_string / value_text |
| 数值 | 带单位/精度 | ✅ value_decimal |
| 日期/时间 | 日历控件 | ✅ value_date / value_datetime |
| 下拉单选 | 来自码表 | ⚠️ 码表有，无控件渲染 |
| 下拉多选 | 码表多选 | ⚠️ record_value_item 有，无控件 |
| 单选按钮/复选 | 少选项 | ❌ |
| 计算字段 | 自动算(BMI等) | ❌ CALC 提了未实现 |
| 附件/图片上传 | 图片/PDF/报告 | ⚠️ value_file_id 有，无上传控件 |
| 重复组/表格 | 一行多字段可增删行 | ❌（D6用药/D10灌注每3h都是此类） |
| 电子签名 | 手写/勾选 | ⚠️ signature 表有，无控件 |

## 三、角色/权限模型（Word 文档 5.2 已定）

> 按角色分级：**录入员 / 数据管理员 / PI / 监查 / 只读**，按数据域授权。

对应现有 06：`crf_form_role`（角色×表单×capability）+ `crf_dag`（数据访问组）+ person_identity_tag（研究身份）。

## 四、对照现有设计的缺口清单

| # | 缺口 | 说明 | 关联 |
|---|---|---|---|
| 1 | eCRF 表单设计器 | 把字段组成表单的设计器 UI | 05 crf_form/form_field |

## 五、补全顺序建议

1. **先补「字段控件层 + 表单设计器」**（#1/#2/#5）——没有它，填写页做不出来，业务转不起来。
2. **再补「逻辑规则 + 访视计划引擎」**（#3/#4）——数据质量靠它们。
3. **最后补「导出 + 报表 + SDV」**（#7/#8/#9）——IND 申报和监管需求。
4. 附件存储（#10）可随填写页一起，复用现有 upload_file_record。
