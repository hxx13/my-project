# 13-代码架构设计（NHP 表单编辑模块）

> 状态：**架构约束**。本文件定义 NHP 前端「表单编辑」模块的代码架构。**只取 AUP 的架构模式，不照搬其 2396 行巨石文件**；按标准代码架构分层设计。

## 一、从 AUP 取与不取

**取（模式）**：
- `schema/` 层分离：formTemplate（类型）/ typeRegistry（题型注册）/ fieldTemplates（复合模板）都是纯类型/纯数据
- 题目渲染组件 FormField 独立

**不取（改造）**：
- AupTemplateEditor.tsx 2396 行单文件巨石（混状态 + UI + 业务逻辑）
- AUP 专用 picker 题型（cagePicker/animalPicker/personPicker/departmentPicker）—— 目前与我们信息无关联，不保留
- AUP 审批骨架 stageFlow、AUP 段码 A/B/C、AUP 专属复合模板（G/H/I/J/K/L 板块、A8 板块触发）

## 二、NHP 代码架构

```
features/nhp/
├── schema/                  # 领域层：纯类型 + 注册表（无 UI、无状态）
│   ├── formTemplate.ts        # FormField/Section/SubSection 类型
│   ├── typeRegistry.ts        # 题型注册表（去 picker）
│   ├── fieldTemplates.ts      # NHP 复合模板（供体-受体关联/随访序列/用药记录/重复块）
│   └── crfTemplate.ts         # CRF 模板 ↔ 字段字典(05) 对接类型
├── store/                   # 状态层：纯 reducer + hook（可单测）
│   ├── templateReducer.ts     # addSection/removeField/moveField/updateField/insertTemplate/undo
│   └── useTemplateEditor.ts   # 包 reducer 的 hook，编辑器唯一状态入口
├── editor/                  # 编辑器 UI：薄组件，各司其职
│   ├── NhpTemplateEditor.tsx  # 页面壳（只组合，不写逻辑）
│   ├── SectionTree.tsx        # 板块/字段树（左）
│   ├── FieldEditorPanel.tsx   # 字段编辑面板（右）
│   ├── TypeMenu.tsx           # 题型菜单
│   ├── OptionsEditor.tsx      # 选项编辑（手动/字典）
│   ├── ShowWhenEditor.tsx     # 条件连锁编辑
│   └── TemplateInsertMenu.tsx # 复合模板插入
├── components/              # 填写渲染层（运行时）
│   └── NhpFormField.tsx       # 题目渲染（按 type 分发）
├── pages/  hooks/  api/     # 页面、数据 hook、接口
```

## 三、代码设计原则（硬约束）

1. **单一职责**：每个文件只做一件事，单文件控制在 ~300 行内。
2. **分层隔离**：schema 不知道 UI，store 不知道 UI，只通过 hook 接口暴露。
3. **纯函数可测试**：reducer、fieldTemplates.build 都是纯函数，可单测。
4. **组合优于继承**：页面壳 = 组合子组件，不堆 if-else。
5. **禁止巨石文件**：编辑器整体拆成 `store + 6 个 editor 子组件 + 渲染组件`。

## 四、与业务流的关系

- 表单模板的「阶段骨架」不再用 AUP 的 stageFlow（填写→组长→格式→专家→通过）。
- 改用 NHP 业务流转（见 09）：供体建档 → 受体入组 → 交叉配型 → 移植手术 → 术后随访 → 终点剖检 → 数据锁定，作为表单的**采集阶段导航**。
- 复合模板换为 NHP 专属：供体-受体关联、随访纵向序列、用药记录、重复块（每3h灌注）。
