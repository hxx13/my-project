# 02-权限管理体系

> 权限是「账号级角色 + 能力点 + 身份标识」三层的统一体系。NHP 业务新增账号一律**进现有人员库（personnel）**，不另建账号体系。

## 一、账号级角色（RoleEnum，人级唯一权威）

`personnel.role` 存 RoleEnum.code，**人级唯一、不分视角、不取最高**。六档：

| code | 中文 | level |
|---|---|---|
| MEMBER | 学生 | 1 |
| STAFF | 普通员工 | 2 |
| SENIOR | 高级员工 | 3 |
| ADMIN | 管理员 | 4 |
| SUPER_ADMIN | 超级管理员 | 5 |
| PLATFORM_OWNER | 平台所有者 | 6 |

## 二、能力点（capability，两层权限）

在角色之上，还有 capability 能力点做细粒度授权（角色 + 能力点两层）。具体能力点随模块定义；NHP 业务新增能力点须与既有 capability 命名一致并登记。

## 三、身份标识（person_identity，人级多选标签）

人员身份用「标签字典 + 多选映射」表达，已收敛为**人级唯一、统一一套、不分视角**，key = `personnel.id`。

- `person_identity_tag`：标签字典。内置 组长 / 秘书 / 专家 三个默认标签（code 稳定、环境变量可配），其余管理员配置。
- `person_identity`：人员 → 标签多选映射，`UNIQUE(user_id, tag_id)`，user_id 即 personnel.id。

## 四、统一人员表（personnel）

账号注册一律进 `personnel`（统一人员库）。关键身份字段已统一：

| 字段 | 语义 |
|---|---|
| `staff_id` | 教职工侧 sys_user.id |
| `job_number` | 工号 = 学号 |
| `user_id` | 认证 id |
| `role` | RoleEnum.code（人级唯一权威角色） |
| 身份标签 | person_identity_tag（多选，人级唯一） |

## 五、NHP 研究侧角色如何落地（新增身份标识字段的方案）

NHP 业务涉及 PI、兽医、数据管理员、实验员、组长等研究角色。落地原则：**不另起账号体系，也不另开并列身份字段**，而是在现有身份标识上扩展。

方案（推荐）：在 `person_identity_tag` 增加研究侧标签（如 PI、兽医、数据管理员、实验员），由管理员配置；或新增一张「研究项目角色表」，personnel.id → 研究角色，随项目 / 协议（AUP）绑定。
