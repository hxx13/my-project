## 一、核心存储决策

**EAV 为权威（canonical），物化宽表为查询投影（rebuildable）。**

- **写入只进 EAV**（`crf_record_value`），字段新增 = 插 `crf_field` 一行，零 DDL。
- **冻结时**：走四步走生成**物化宽表**（每域一张，如 `crf_d1_donor`），列 = 冻结字段（name_en → 列、data_type → SQL 类型）。宽表**只读、可重建**，从 EAV 用确定性构建任务生成。
- **为什么这样**：EAV 权威 → 加字段不改代码、血缘/审计天然落点；宽表投影 → 满足「直接查库」+ IND 导出，且可重建 = 冻结迁移无「回填失败」风险（#5 顺带解决）。

> 取舍：宽表非实时（需重建），导出/查库前触发重建即可。实时性要求高再讨论双写。

## 三、数据血缘（#3）

- 每条 `crf_record_value` 存 `field_version_id` + `codelist_item_id`（**存 item 不存 label**），采集时锁定的字段/码表版本即可追溯。
- 冻结后字段 `version+1`，旧记录仍指向旧 `field_version_id`，历史定义不丢。
- 码表改 label 不改 code，历史值可回溯到当时的 item。

### 双录入（已确认：一期支持 + 配置开关，2026-08-20）

- 双录入完整流程（录入→二录→比对→差异处理）一期建成，由系统配置开关 `crf.double-entry.enabled` 控制（默认关）。
- 开关关：单录入 + query 兜底（首例 T0 时效路径）；开关开：同一 `crf_record` 需两次独立录入并比对。
- 开关遵循项目既有系统配置开关模式（`sys_system_config`，同 `scan.data_source`）。

## 五、物化查询层（冻结生成）

- 冻结一个 form（域）→ 四步走生成宽表 `crf_{form_code}`（如 `crf_d1_donor`），列 = 冻结字段。
- 宽表**只读、可重建**：构建任务从 EAV 按 subject+visit 透视生成。
- D9/D10 器官模块：作为独立 form，物化时**合并进父域宽表**（加前缀列）或独立宽表——见待确认项。

## 八、冻结修正（#5）

- **冻结粒度 = 表单级**。`crf_form.status = FREEZING` 时该表单只读（录入锁定），物化完成置 `FROZEN`。
- 字段级 status（DRAFT/PENDING_REVIEW）只用于**冻结前**的校对进度；表单冻结前，其全部字段须非 DRAFT。
- 物化是**可重建投影**，冻结窗口 = 一次构建，无「回填失败/类型不符」风险（与 05 状态机相比的修正点）。

## 九、ENUM_MULTI / CALC / FILE 落地（#7）

- **ENUM_MULTI** → `crf_record_value_item`（见二）。
- **CALC** → 不落库；表达式存 `crf_field.calc_expression`（版本化），读取/导出时计算，保证可复现。
- **FILE** → `crf_record_value.value_file_id` 复用现有 `upload_file_record`。

## 十、已确认决策（2026-08-20）

| # | 决策点 | 决定 |
