## 0. 核心诊断（已确认）

一句话：**架构是对的，seed 和内置模板错在「粒度」与「丢信息」。**

自由配置流水线五层，其中三层机制现成、两处断信号：

```
① 字典层   ② 原子层      ③ 组合层        ④ 调度层       ⑤ 数据层
定义字段 → 切成原子   → 自由组装成模板 → 决定何时/几次填 → 落到真实数据
(填什么)  (一个单位)    (怎么摆)        (什么时候用)    (填的结果)
```

| 层 | 现状 | 判定 |
|---|---|---|
| ① 字典 | `crf_field_dictionary` + `crf_field`，249 字段已灌 | ✅ 对；`role` 已就位（缺 DERIVED 应用），timepoint 需归一化 |
| ② 原子 | `crf_form`(DOMAIN/MODULE)，按**域**切（D1=29 字段） | ❌ 粒度错（应按子模块×重复频率） |
| ③ 组合 | `crf_form`(TEMPLATE)+`crf_composite_atom` | ✅ 机制已对 |
| ④ 调度 | `crf_visit`+`crf_visit_instance` 表在 | ❌ 未接进链路 |
| ⑤ 数据 | `crf_record`+`crf_record_value`(EAV) | ⚠️ 能存；role 已正确填充，缺实体层 + 调度层 |

## 2. 改造方案（五层，按依赖排序）

### ① 字典层
- **`role` 不加列**：已在 `crf_form_field`，且 JSON 已正确填充（222V/15PK/12FK），seed 已读。缺口是 DERIVED=0 的应用（标上 pairing_score 等派生字段）。
- `role` 决定填表时答案从哪来：
  - `PK` → 调取号器自动生成
  - `FK` → 实体选择器（选一行真实数据）
  - `VALUE` → 码表选择或按类型直填
  - `DERIVED` → 表达式计算，不存值
- **`timepoint` 不落 `crf_field`**：时点是访视/原子属性（D2 决策）。字段可多时点复用。

### ② 原子层
- 原子单位：`域 → 子模块 × 重复频率`
- 示例（D1 从 1 个原子变 6 个）：
  ```
  D1.01 入档  → A（7 字段，一次性）
  D1.02 入档  → B（7 字段，一次性）
  D1.03 季度  → C（7 字段，重复·季度）
  D1.03 年度  → D（1 字段，重复·年度）
  D1.03 TP02  → E（1 字段，挂访视 TP02）
  D1.04 术前  → F（6 字段，一次性·逐器官）
  ```
- `crf_form` 加 schedule（`visit_id` + `repeat`）

### ③ 组合层
- 机制不动，只加规则：组合默认只钉同一节奏原子，或组合自己声明覆盖的节奏。

### ④ 调度层（前置：timepoint 归一化，见 §4m）
- **先做时点本体归一化**：65 离散值 → `TP 码 × 频次 × 事件` 三元组（清掉"同上/0h/结束/术前1月每2-3d；术后每2周"等残留）。
- 归一化后 → `crf_visit` 映射（TP 码 + repeat + 事件锚点）。
- 受试者 → 按组合模板展开 `crf_visit_instance`（哪些时点、各几条）→ 每实例对应一个 `crf_record`。

### ⑤ 数据层
- `crf_record` 加 `atom_id`（版本无关的逻辑原子标识，区别于 form_id+form_version_id 的血缘）+ `transplant_id`（决策 D1）。**`visit_instance_id` 已存在，不加**。
- 填表时 role 生效：PK 取号 / FK 存真实外键 / DERIVED 不算值。

### 改表 vs 重灌 seed 清单

| 改动 | 类别 |
|---|---|
| ~~`crf_field` 加 role/timepoint~~（role 已在 crf_form_field；timepoint 落访视/原子层） | 不改 |
| `crf_form` 加 schedule 两列（event_anchor+frequency，见 22 号计划 §6.1） | 改表 |
| `crf_record` 加 atom_id（澄清语义）+ transplant_id | 改表 |
| 新建 `crf_transplant`（+ `crf_crossmatch` 等 §4k 实体清单） | 建表 |
| 编码规则/role 补 DERIVED/timepoint 归一化/原子重切 | 重灌 seed + 改生成逻辑 |

## 3. 编码规则 sheet 对照复盘（16 类 ID）

### 生成能力盘点
- `buildCode` 现只支持 `{center}/{year}/{seq[:n]}` → 仅 **DON/RCP/TX 3 类可用**。
- 其余 13 类会静默返回含花括号字面量（应改为抛异常）。
- 根因：`crf_sequence` 唯一键 `(id_type, center_code, year)` 只覆盖"机构+年"作用域，无法表达 AE(当日)/MED(方案)/SMP(TX+时点+类型)/PATH(TX+时点) 的嵌套作用域。
- 改法：`crf_sequence` 键泛化为 `(id_type, scope_key)`；`buildCode` 收 context map。

### 字典侧 5 处结构缺陷
| # | 缺陷 | 处理 |
|---|---|---|
| 1 | FU-{TX}-{时点} 撞车（TP04 每日/TP05 每周2次/TP10 随时，规则却写"一时点一条"） | 已定：改 `FU-{TX}-{TP}-{seq:2}` |
| 2 | TP 码两套（TP-01 vs TP01），seed 用了带横线，拼 ID 会 4 段歧义 | 已定：统一 `TP01` 无横线（涉及 crf_visit 存量迁移） |
| 3 | XM-{DONOR}-{RECIP} 缺序号（规则说明有 -01/-02，格式列漏写） | 已定：补 `-{seq:2}` |
| 4 | PERF-{DON}-{日期} 同日二次灌注撞车 | 待 PI 确认约束 |
| 5 | ORG-{1位} 与 Lu=肺 2 位矛盾（L=肝/Lu=肺 定长解析歧义） | 待 PI 确认 |

### 其他结论
- 派生键 ANES-{TX}/HX-{TX}/RS-{TEST_ID}-{项目码} 不应走取号器 → `crf_id_rule` 加 `derived` 标记。
- `crf_sequence.center_code` 语义：DON=基地码 SH(FARM)、RCP/TX=中心码 SJ(CENTER)，与总览表 FARM_ID/CENTER_ID 外键一致，仅列名偏窄。
- 三个 `{year}` 语义不同：DON=出生年 / RCP=入组年 / TX=手术年，调用方须传对。

## 4b. D2 受体NHP域分析

### 结构：17 字段 / 2 子模块（无新子实体）
| 子模块 | 字段数 | 内容 | 时点分布 |
|---|---|---|---|
| D2.01 受体档案 | 7 | 身份 + weight + 病原 | 入组 + TP01 混着 |
| D2.02 术前基线 | 10 | 抗猪抗体/补体/凝血/免疫/肾功/微生物组 + 入选结论 | TP01 / TP01·02 / TP02 |

### 关键发现
1. **条件必填跨域引用**：ab_neu5gc_titer（CMAH 未敲除）/ ab_sda_titer（B4GALNT2 未敲除）/ renal_baseline（肾移植方案）——填表引擎运行时需读 D1 供体基因编辑 / 方案 / 器官数据来求值。`required=CONDITIONAL` 已有，但触发条件目前只能写死文本，缺「跨域引用求值」执行机制。
2. **无新子表**：D2.01 几乎全落 `crf_subject` 12 身份列；D2.02 是纵向监测序列的起点（TP01/TP02=D5 随访起点），走 EAV。印证「不是每个域都要建子表，看有没有重复子实体」。
3. **中心编码缺口**：center_id 无对应列（D1 有 farm_code），需加。

### 修正原子切分规则（决策 D2 精修）
- 原规则：子模块 × 时点组。
- **精修**：切分看「重复语义」非「时点」——
  - 不重复的逻辑单元即使跨时点（D2.02 跨 TP01→TP02）→ **不切**，一个原子，schedule=时点范围；
  - 混不同重复频率（D1.03 季度/年度/TP02）→ **切**，按频率拆。
- 新表述：**「反复填 vs 一次填」是切分开关；时点只定原子的 schedule 范围。**

### 待决问题
- ~~基线字段（D2.02）是否与 D5 随访指标复用同一份字段定义？~~ **已决定：复用**（2026-08-21 会话 2）。同一指标（肌酐/CH50/抗猪抗体滴度）只建一份 `crf_field` 定义，基线/随访都引用它，保证单位一致、可连成连续曲线。

### 决策影响（复用字段定义带来的设计修正）
- 字段定义**不带单一 `timepoint`**：一个指标出现在多个访视时点（TP01/02 基线 + TP04~09 随访），`timepoint` 不能是 `crf_field` 的单一列。
- **时点是「访视/原子」的属性，不是「字段」的属性**——通过 `crf_visit` 定义 + 原子挂 visit 来表达"这个字段在这个访视时点被采集"。
- 原 §2 改造方案里的「`crf_field` 加 `timepoint` 列」需改为：`timepoint` 落在**访视-字段关联**层（如 `crf_form_field` 或 visit×field 映射），而非字段定义本身。

## 4c. D3 配型与手术域分析

### 结构：18 字段 / 2 子模块 = 2 个实体
| 子模块 | 实体 | 主键 | 采集时点 | 基数 |
|---|---|---|---|---|
| D3.01 交叉配型 | 配型记录 | `xm_id` | TP01 | 每供受对多条（-01/-02） |
| D3.02 移植手术 | 移植事件 | `tx_id` | TP03 | 每例一条，二次移植另赋码 |

### 关键结论
1. **role 分类已标注**（PK/FK 准确：xm_id/tx_id=PK、donor_recip_pair=FK），但 **DERIVED=0**：`pairing_score` 说明写"平台配对算法输出 V1 规则引擎"，JSON 里 role 却是 VALUE——派生字段未启用，需补标 DERIVED 并挂计算引擎。
2. **两个实体都要落表**：`crf_crossmatch`（配型，多对多供受对 + 评分 + 决策）+ `crf_transplant`（手术，单向引用采用的 xm_id）。修正决策 D1 的"TX 是 D3 域一堆 EAV 值"——D3 含 XM 和 TX 两个实体。
3. **crf_transplant 列定稿**（见下）。
4. **intraop_samples = FK 列表**：确认 D4 样本与 TX 的 1:N，手术即刻（TP03）产生第一批样本。
5. **免疫方案分工边界**：D3.02.008/009 只存方案编码（IMMU 码表），剂量/途径明细在 D6。TX 引用方案编码，不存明细。
6. **tx_date 是 day0 锚点**：`crf_visit.planned_days` 全从这天算，访视引擎以 tx_date 为原点展开。

### crf_transplant 表列（D3 定稿）
`tx_id`(PK, 取号) · `donor_subject_id`(FK→subject) · `recipient_subject_id`(FK→subject) · `xm_id`(FK→crossmatch) · `tx_organ`(ORG) · `procedure_type`(PROC) · `tx_date`(DATE, day0) · `cold_ischemia_min`/`warm_ischemia_min`(DECIMAL) · `reperfusion_time`(TIME) · `induction_regimen`/`maintenance_regimen`(IMMU) · `parent_tx_id`(自引用, 二次移植)

## 4d. D4 样本与检测域分析

### 结构：22 字段 / 3 子模块 = 3 实体
| 子模块 | 实体 | 主键 | 时点 |
|---|---|---|---|
| D4.01 样本台账 | 样本 SMP | `sample_id` | 各时点 + 入库 |
| D4.02 检测委托单 | 委托单 TST | `test_id` | 委托时 |
| D4.03 结果回传 | 结果 RS | `RS-{TEST_ID}-{项目码}` | TP04-08 不等 |

### 关键问题
1. **总览表漏了 RS_ID**：数据域总览 D4 只列 SAMPLE_ID/TEST_ID，编码规则却有 RS。D4 实体三层：样本→委托单→结果。
2. **tx_id 必填是错的**：术前样本（TP02 微生物组、D1.04 器官出厂）无 TX。样本归属改「多态来源」：术后挂 tx_id，术前挂 donor_id/recipient_id。SMP 编码规则放宽：有 TX 用 `SMP-{TX}-...`，术前用 `SMP-{DON/RCP}-...`。
3. **coc_log 不该是 TEXT**：是 1:N 交接事件表（人/时间/温度），建 `crf_sample_coc_event`。
4. **qc_status 是状态机**（已复核/待复核/复测），挂在结果 RS 上。
5. **collect_datetime 是质量指标**：偏差自动计算（protocol deviation）+ TDM 谷/峰判定前提。

### 数据模型
```
样本 SMP ──(1:N)── CoC 交接事件
   ├─ 归属多态：tx_id OR donor_id/recipient_id
   ├─ timepoint_code → 访视实例
   └─ collect_datetime → 偏差 + TDM
委托单 TST ── 多对多 样本
   ├─ panel_version → D12 版本域
   └─ test_items → ASSAY 码表
结果 RS ── 关联 TST + 项目码(ASSAY)
   └─ qc_status 状态机
```

### 跨域依赖
- panel_version → D12 标准与版本域（Excel 说明里写"D7版本域"，与封面 D12 编号漂移，待对齐）
- test_items → ASSAY 码表

## 4e. D5 随访与事件域分析

### 结构：17 字段 / 3 子模块 = 3 实体 + 3 种 schedule
| 子模块 | 实体 | 主键 | 时点 | 基数 |
|---|---|---|---|---|
| D5.01 随访序列 | 随访 FU | `fu_id` | 各时点 | 每 TX 多条 |
| D5.02 不良事件 | 事件 AE | `ae_id` | 事件触发 | 每 TX 多条 |
| D5.03 终点结局 | 结局 Outcome | （无独立主键，挂 tx_id） | 终点/TP11/TP12 | 每 TX 一条 |

### 关键结论
1. **FU 撞车实锤**：`timepoint_code` 说明"各时点"，TP04 每日 7 次 → `FU-{TX}-{TP}-{seq:2}` 修正必须落。
2. **graft_function 反模式**：把多器官多指标压成"指标:值"TEXT，废掉单独查询/画曲线。应细拆成独立指标字段，与 D2.02 基线 / D4.03 检测结果**对齐复用**（肌酐只定义一次）。
3. **跨域引用再证**：rejection_dx→D8 病理、biopsy_sample_id→D4 样本。跨域求值是普遍需求。
4. **FU 两类**：计划访视（TP01-09，schedule 展开）+ 事件触发（TP10，事件创建）。
5. **结局 1:1 实体**未进总览表（总览只列 FU_ID/AE_ID），实际为 `crf_outcome`（主键=tx_id）。

### 数据模型

## 4f. D6 免疫抑制用药域分析

### 结构：18 字段 / 3 子模块 = 3 实体（清晰三层）
| 子模块 | 实体 | 主键 | 基数 |
|---|---|---|---|

### 关键结论
1. **方案库 vs 方案实例**：`immu_code`（方案库版本化，含剂量/调整规则）+ `target_range`（随方案版本变化）指向一个版本化标准库；`regimen_id` 是实例。拆两张表：`crf_regimen_library`（版本化）+ `crf_regimen`（实例，引用库版本）。"版本化标准库+实例引用"在 D4(panel)/D6(方案) 已两次出现，是通用结构。
2. **序列作用域实锤**：REG/MED/LVL 三个 ID 全是父 ID 作用域，`(center,year)` 键对不上，坐实 scope_key 泛化，且给了 scope_key 拼法实例。
3. **dose 单位 ALCOA+**：dose 拆 `dose_value`+`dose_unit`（录入锁定）；dose_time 同步记录。
4. **剂量调整事件跨域重复**：D6.01.006 regimen_change_reason 与 D5.01.006 regimen_change 是同一业务事件，需去重（D6 主记录，D5 引用）。
5. **LVL 可能是 RS 特例**：血药浓度本质是检验+TDM 谷峰语义，可复用 RS 结构而非平行建两套检验体系。
6. **域标题自曝**：D6 "v0.2 初稿，医学内容待 PI 评审"（D9/D10 同为此类低可信度域）。

## 4l. 架构级风险与修正（评审后补）

> 定位：**范围不收缩**——前瞻性与可扩展性优先，全量架构设计（含 D6/D9/D10 低可信度域、协议层、DERIVED 引擎、CoC 等）。但以下三件事是**数据质量/正确性前提**，与"前瞻 vs 收缩"无关，必须先落地。

### 风险 1：timepoint 归一化（最前置，真正的瓶颈）
实测 249 字段 timepoint = **65 个离散值**，三种语义混排：
- TP 码：TP01(18)/TP03(16)/TP02(6)/TP05-TP11(5)/TP04-06(3)…
- 频次：每3h(20)/每15-30min(7)/每1-3h(6)/每次给药(7)/每2周(4)…
- 自然语言事件：入档(14)/各时点(11)/取材(6)/阅片(6)/灌注启动(6)/灌注结束(4)/麻醉开始(3)…
- 残留占位：**同上(4)/0h/结束(1)/术前1月每2-3d；术后每2周(1)**…

处理：归一化为 `TP 码 × 频次 × 事件锚点` 三元组，产出「时点本体」映射表，清掉残留。这是 crf_visit 展开引擎的唯一输入，不做它调度层没素材。

### 风险 2：EAV vs 实体表边界判据（三条）
| 判据 | 落点 | 例子 |
|---|---|---|
| 稳定主键 + 被多域引用 | 实体表 | subject/transplant/crossmatch/sample/regimen |
| 身份属性（一实体一条） | 身份列 | crf_subject 身份列 |
| 测量序列（时间+指标+值，高频重复） | EAV + 原子标序列频率 | 监护/随访/检测结果 |
| 标准/方案（版本化） | 标准库表 + 实例引用 | panel/方案/协议 |

### 风险 3：字段复用 vs field_code 唯一键冲突
「肌酐只定义一份、基线/随访复用」撞上 `crf_field.field_code` 唯一键（`D域.子模块.序号` 命名）：肌酐在 D2.02 与 D5.01 是两行不同 field_code。
处理：引入**「概念/指标库」层（类 LOINC）**——`concept_code` 是跨域唯一指标标识，`crf_field` 是某域对概念的一次实例化（N:1）。复用 = 多 crf_field 指向同一 concept。

### 风险 4：DERIVED=0 空档
role 四值里 DERIVED 声明了但 0 个使用；pairing_score 应标 DERIVED 却标 VALUE。
处理：补标 DERIVED；计算引擎可后置，结构先预留。

### 风险 5：低可信度域先建表的锁策略（「范围不收缩」的配套）
全量前瞻 + D6/D9/D10（115 字段，占 47%）待 PI 评审先建表，必须配套「未校对域结构不锁死」策略，否则前瞻性变大规模返工：
- 三域表结构先建，但字段挂 `status=DRAFT` 不进 FROZEN；`crf_form` 原子/组合同样 DRAFT 不发布。
- PI 校对签署后才允许字段 FROZEN + 表结构迁移（增删改列走版本迁移，不改已冻结列）。
- 语义：**「建结构」≠「锁结构」**；低可信度域只建 DRAFT 骨架，冻结权交给校对流。
