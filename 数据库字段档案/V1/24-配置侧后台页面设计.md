# 24-NHP 配置侧后台页面设计

> 状态：**深设计进行中**。与 `23-事件流工作台前端设计.md`（采集侧）成对，本文管配置侧（管理端 `/content-manager`）。
> 核心原则：**配置侧定义「每个事件类型有哪些字段 / role / 编码 / 规则」，采集侧只做「记录发生了什么」**。现有页面按此重构（合并 / 删除 / 改造）。

---

## 1. 现有页面盘点与决策（合并 / 删除 / 改造）

现有 11 个 `/content-manager` 路由，按表单范式组织。事件流范式下重新分流：

| 现有 route | 页面 | 决策 | 新归属 | 理由 |
|---|---|---|---|---|
| `nhp-hub` | 流程前门（4 步引导） | **删除** | — | 「配置模板→登记→开填」是表单范式引导，事件流下无意义；配置侧首页改为简单总览 |
| `nhp-template` / `edit` | 模板列表 / 编辑器 | **改造** | 配置侧「事件类型」 | 域/组合/原子 → 事件类型（=原子），加 capture_form / schedule / 主键规则 / 下游规则 |
| `nhp-field` / `:dictKey` | 字段字典列表 / 编辑器 | **保留 + 加概念库** | 配置侧 | 加 `concept_code`（概念/指标库），仍是字段权威 |
| `nhp-field-review` | 字段校对 | **保留** | 配置侧 | PI 校对流程（verdict 四态） |
| `nhp-codelist` | 码表 | **保留** | 配置侧 | 码表 + 整表版本 |
| `nhp-subjects` | 动物管理 | **移出** | 采集侧（=对象列表） | 采集侧首页就是对象列表，配置侧不再放 |
| `nhp-records` | 实例管理 | **移出** | 采集侧运维 | 实例/访视审阅、删除 |
| `nhp-entry` | 采集入口（admin preview） | **移出** | 采集侧 | admin 代填/审阅走采集侧工作台 |

## 3. 核心页面设计

### 3.1 事件类型定义页（改造自模板，配置侧核心）

**列表列**：事件类型 code · 名称 · `capture_form`（推导）· 实体表 · 主键编码规则 · schedule（event_anchor/frequency）· 状态（DRAFT/FROZEN）。

**详情/编辑**分四区：
1. **基本信息**：实体表（`crf_sample` 等）、主键编码规则（`SMP-{TX}-{TP}-{类型}-{分管2}`）、归属多态（tx_id OR donor/recipient）。
2. **采集形态**（`capture_form`）：SERIES / LEDGER / PANEL，**推导结果只读展示**，覆盖需记 `crf_dict_change_log`。
3. **schedule**：event_anchor（ENROLL/PRE_TX/DAY0/POST_TX/…）+ frequency（ONCE/Q3H/QUARTERLY/…）。
4. **字段集**（role 标注）：每字段标 PK/FK/VALUE/DERIVED + 码表/来源，与 §14.1 的「事件类型=原子」一致。
5. **下游规则**：引用 `crf_event_rule`（本事件触发什么下游动作）。

### 3.2 访视/时点页（新增）

- `crf_visit` 列表：TP01~TP12，每行 event_anchor + frequency + planned_days + early/late 窗口 + end_days。
- `crf_timepoint_map`：65 原始值 → 三元组（事件锚点 × 频次 × TP 码）映射，seed 灌入，残留（同上/0h结束）已拆解标注。

### 3.3 事件规则页（新增）

- `crf_event_rule` 列表：源事件类型 · 触发时机（CREATED/STATUS_CHANGED）· 触发条件 · 动作（EXPAND_SCHEDULE/GENERATE_TODO/CREATE_EVENT/ADVANCE_STATE）· 动作参数（JSON）。
- 每条可展开看 action_spec 参数。

### 3.4 编码规则页（新增）

- `crf_id_rule` 16 类 ID：pattern（全占位符）+ derived 标记（ANES/HX/RS=1 不走取号器）+ scope_key 拼法展示。
- `crf_sequence` 键泛化后，展示各 ID 类型的 scope_key 拼法（DON={base}|{year}、SMP={tx}|{tp}|{type}…）。

### 3.5 标准库页（新增）

- 三类版本化标准：方案库（`crf_regimen_library`）、panel/放行标准（`crf_standard_version`）、协议（`crf_protocol`）。
- 统一「版本化标准库」模式：禁止覆盖式修改，变更走版本 + 软删。

### 3.6 字段审核页（PI 校对，改造 `nhp-field-review` 薄页）

对应 Excel「校对总览」+ 各域 L/M 校对列（见 07）。当前 `nhp-field-review` 仅 20 行，需补全为真校对页：

1. **校对总览表**（顶部）：各域字段数 / 待校对 / 确认 / 需修改 / 有疑问 / 完成率——对应 Excel 校对总览 sheet，自动统计。
2. **字段校对区**（选中域后）：逐字段 verdict 四态（**确认 / 需修改 / 建议删除 / 有疑问**）+ 意见框。
3. **签署区**：心脏 PI / 肝脏 PI / 平台 DM 三签署（字段级校对签署 ≠ 记录级 `crf_signature`）。
4. **缺口**：`crf_field.status` 是生命周期态（DRAFT/PENDING_REVIEW/FROZEN/RETIRED），**缺 verdict 维度**——需加 `verdict VARCHAR(16)` + `verdict_note TEXT`（或落 `crf_dict_change_log`），见 22 §9 待补。

### 3.7 码表审核页（item 级 + 版本）

1. 码表列表（版本化，`crf_codelist` 整表版本）。
2. 选中码表的 item 列表：item_code / item_label / 审核态（确认/需修改/建议删除）+ 意见。
3. 版本 + 冻结：`crf_codelist.status` DRAFT→FROZEN，冻结后取值禁止直接改，变更走新版本。

### 3.8 快照管理页（`crf_record_snapshot` 独立成页）

当前快照是填写工作台里的抽屉（NhpSnapshotDrawer）。独立成页后：

1. **快照列表**：按 record / subject / 时间筛选，列 = 记录 # / 版本号 / 阶段（stage）/ 业务阶段（biz_stage）/ 创建人 / 时间。
2. **对比**：选中两个版本 → 字段级 diff（fieldCode→before/after）。
3. **回滚**：回滚到某版本（恢复 values + 记录状态，落审计）。

### 3.9 审计留痕页（两个 tab）

当前审计是填写工作台里的面板（NhpTracePanel）。独立成页后分两 tab：

1. **数据变更审计**（`crf_data_audit_log`）：字段 / 变更类型（INSERT/UPDATE/DELETE）/ 前值 / 后值 / 操作人 / 变更原因 / 时间。筛选按 record / field / 操作人 / 时间。
2. **字典变更审计**（`crf_dict_change_log`）：实体（field/codelist/form）/ 变更类型（CREATE/UPDATE/FREEZE/RETIRE）/ 前 JSON / 后 JSON / 操作人。这是配置侧 ALCOA+ 全留痕。

## 4. 与采集侧的边界（防越界）

- 配置侧**不出现**「对象时间线 / 记录事件 / 序列网格 / 台账」这些采集侧概念。
- 采集侧**不出现**「域 / 原子 / 字段字典 / 码表」这些配置侧概念（事件面板由事件类型定义驱动，采集者无感）。
- 唯一交集：事件类型定义页的「下游规则」引用事件规则页的规则；采集侧待办由规则引擎 + 调度引擎驱动，采集者只看到待办结果。

1. **改造**：模板 → 事件类型（先接 capture_form 推导 + schedule 两列 + 字段集 role 展示）。

3. **新增**：访视/时点 → 编码规则 → 事件规则 → 标准库（按后端 V20260821025/27/35/33 顺序）。
4. **移出**：subjects/records/entry 三个路由从配置侧导航摘除，落到采集侧。
5. **删除**：hub 路由下线，配置侧首页用简单总览替代。
