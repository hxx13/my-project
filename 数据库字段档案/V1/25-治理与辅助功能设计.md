| # | 功能块 | Excel 来源 | 一句话 |
|---|---|---|---|
| A | 数据质量中心 | 治理与合规·数据质量 | 双人复核/异常值复测/TAT/时点偏差/CoC 断裂 → 质控月报 |
| B | 版本管理中心 | 版本管理 + 版本记录 | 字典/码表/panel/方案版本化 + 状态机 + 旧版本映射 |
| C | 团队与权限 | 校对总览·分工 + 权限体系 | 研究团队 + 身份标识 + 角色×capability + DAG |
| D | 迭代审核系统 | 校对总览 | 校对→汇总→第二轮商议→复审→签署→冻结 |

## A. 数据质量中心（质控）

### Excel 原文
> 双人复核、异常值复测、TAT 监控、时点偏差自动标记 → 质控指标进入平台月报。样本-数据绑定：链路断裂视为数据质量事件。

### 设计（一个「质控看板」+ 三类事件队列）

**1. 质控看板（首页）**：质控指标卡 + 趋势。指标 = 双人复核完成率、异常值复测闭环率、TAT 达标率、时点偏差率、CoC 断裂数。

**2. 数据质量事件队列（统一收口）**——四类事件自动标记，DM 逐条核查：

| 事件类型 | 触发规则 | 来源 |
|---|---|---|
| 异常值复测 | 值超出 `crf_reference_range`（种属/性别/年龄分层） | 序列网格录入时自动 ▲▼ |
| 时点偏差 | collect_datetime 偏离计划时点（`early_days`/`late_days` 窗口外） | DERIVED 偏差引擎 |
| TAT 超时 | 送检委托 `tat_hours` 超时未回传 | `crf_test_order.tat_hours` |
| CoC 链路断裂 | 样本 → 委托 → 结果 三环节任一缺失 | 样本台账下钻 |

**3. 双人复核**：采集侧工作台已有「一录/二录」开关。此处收口为「待复核队列」——关键事件（手术/终点/排斥分级）必复核，其余抽查。复核通过 → 记录级 `crf_signature`（复核人）。

**4. 质控月报**：指标聚合导出，对应 Excel「质控指标进入平台月报」。

### 后端
`crf_reference_range`（已有）+ `crf_validation_rule`（已有）+ 新增 `crf_quality_event`（事件队列，含 type/status/ref_id/复核人）。CoC 断裂判定走 `crf_event_rule`（ADVANCE_STATE → 生成质量事件）。

## B. 版本管理中心（版本总结）

### Excel 原文
> 数据字典、panel、放行标准、研究方案全部版本化；历史数据保留与旧版本的映射；禁止覆盖式修改。

### 设计（一个「版本总结」页 + 四类版本对象）

**版本对象**：字典（`crf_field`）/ 码表（`crf_codelist`）/ panel+放行标准（`crf_standard_version`）/ 方案（`crf_regimen_library` + `crf_protocol`）。

**页面三区**：
1. **版本历史**：每个对象一行一个版本（版本号 + 日期 + 变更内容 + 变更类型 + 状态）。
2. **状态机**：`DRAFT → PENDING_REVIEW → FROZEN → ARCHIVED/RETIRED`，冻结后禁止改，变更走新版本。
3. **旧版本映射**：历史数据（已采集的 record_value）保留 `field_version_id`/`form_version_id` 血缘，导出时按版本还原。

**版本总结**：一个总览页，聚合「当前冻结版本 + 各对象版本历史 + 变更摘要」，对应 Excel「版本记录」sheet（v0.1/v0.2/v0.3 逐条）。

### 后端
`crf_field.version/status`、`crf_codelist.version/status`（已有）；`crf_standard_version`（22 §3.7）；`crf_dict_change_log`（变更留痕，已有）；记录级 `field_version_id`/`form_version_id`（已有，血缘关键）。

## C. 团队与权限（身份标识系统）

### Excel 原文
> 校对分工：心脏PI 主校对 D9 + 复核 D3/D5/D6/D7 中心脏内容；肝脏PI 主校对 D10 + 复核 D4 肝功能 panel；平台DM 复核汇总。

### 设计（研究团队页 + 授权矩阵 + DAG）

**1. 研究团队页**：研究侧角色清单——心脏PI / 肝脏PI / 平台DM / 兽医 / 外科团队 / 麻醉团队 / 病理平台 / 受托实验室。每个角色挂「身份标识」（`person_identity_tag`，已有权限体系），不是账号。

**2. 授权矩阵**（`crf_form_role` 已有表）：角色 × 表单（事件类型）× capability（crf:entry 录入 / crf:verify 复核 / crf:freeze 冻结 / crf:query 查询 / crf:export 导出）。矩阵里体现「谁记什么事件」——麻醉记体征、护理记给药、实验室回传结果、PI 复核。

**3. DAG 数据访问组**（`crf_dag`/`crf_dag_user` 已有表）：多中心隔离，基地码/中心码分 DAG，跨中心查询走授权。

### 后端
已有 `crf_form_role` + `crf_dag`/`crf_dag_user`（V20260820002）+ 既有 RoleEnum/capability 权限体系。缺的是「研究团队角色」这一层命名（映射到身份标识），属配置非建表。

## D. 迭代审核系统（校对工作流）

### Excel 原文
> 校对列 L/M：确认/需修改/建议删除/有疑问 + 意见。需修改/建议删除/有疑问行由平台DM汇总，提交第二轮商议逐条处理。签署：心脏PI/肝脏PI/平台DM。

### 设计（状态机 + 工作流）

```
第一轮校对（各 PI 逐字段 verdict 四态）
   → 平台DM 汇总「需修改/建议删除/有疑问」行
   → 第二轮商议（逐条处理：改 / 删 / 保留）
   → 复审（PI 复核修改结果）
   → 三签署（心脏PI / 肝脏PI / 平台DM）
   → 冻结（CRF V1.0 FROZEN，T0-3 周前）
```

**页面**：字段审核页（v7 已画）+ 新增「待确认项清单」（汇总需修改/建议删除/有疑问行，附处理状态）+「签署区」（三签署）。`crf_field.status` 补 `verdict`/`verdict_note` 维度（v7 已记缺口）。

## E. 研究治理设置（权属/去标识化/用途）

### Excel 原文
> 数据权属协议须在首例数据采集前签署；NHP 阶段绑定伦理批件号；平台定位为科研查询层，不输出诊疗建议。

### 设计（一个「研究治理」配置页，静态声明 + 附件）
- **权属协议**：协议上传 + 签署状态（首例采集前强制）。
- **伦理批件号**：绑定 NHP 阶段伦理批件号（`crf_study` 挂）。
- **用途边界声明**：勾选「科研查询层」定位，禁用诊疗决策输出。
- 纯配置，不建表（挂 `crf_study` 或系统配置）。

## F. 双轨采集与导入

### Excel 原文
> 双轨期纸版与 Excel 兜底数据须与 EDC 回溯录入一致性核查；首例数据回溯录入作为 EDC UAT 真实测试集；正式上线后电子采集为主。

### 设计（导入批次 + 一致性核查）
- **回溯录入**：采集时间 ≠ 录入时间（`collected_at` vs `created_at` 分离，已有）。
- **导入批次**（`crf_import_batch` 已有）：纸版/Excel 数据导入，按批次留痕 + `source_ref`。
- **一致性核查**：导入数据 vs EDC 双轨比对，差异标红，DM 逐条核。
- 对应已有 `16-数据导入层设计.md`，此处只补「一致性核查」这个治理动作。
