# 26-NHP 旧版改造与迁移方案

> 状态：**改造方案（可执行）**。现有代码是「表单范式」的完整实现（前端 ~9300 行 + 后端 32 entity/10 service/9 controller）。新范式 = 事件流。改造本质：**把「form/域」概念换成「事件类型/原子」**，不是推倒重来。
> 关键洞察：旧版已埋了新范式的种子——`fieldTemplates.ts` 的「随访序列/用药记录/灌注监测」复合模板，本质就是未来的「事件类型」，只是被当成了「可展开的字段块」。

## 2. 种子 / 导入机制改造

### 2.1 种子源 `nhp-field-dict.json`（249 字段）

**现状**：字段含 `fieldCode/nameCn/nameEn/dataType/unit/required/codelist/timepoint/desc/role/domain/sub/pos`。`role` 已正确（222V/15PK/12FK，0 DERIVED）；`timepoint` 是 65 个自然语言散值。

**改造**（不改 JSON 结构，加字段 + 归一化）：
1. 字段加 `conceptCode`（概念/指标库，22 §2.2）、`eventAnchor` + `frequency`（timepoint 归一化三元组，22 §2.1）。
2. `role` 补 DERIVED（pairing_score 等算法输出字段，22 §2.3）。
3. `timepoint` 65 原始值 → 落 `crf_timepoint_map`（65→43 三元组映射），不再直接落字段。

### 2.2 seed 逻辑 `NhpSeedService`

**现状**：`seedFields()` 落 crf_field（不落 timepoint）；`seedTemplate()` 按 `dcode`（域）切原子；`role` 已从 JSON 读。

**改造**：
1. 原子切分从「按域」→「按子模块 × 重复频率」（22 §6.1），原子 = 事件类型。
2. `crf_form` 落 schedule 两列（event_anchor/frequency）+ **capture_form 推导列**（SERIES/LEDGER/PANEL，按 22 §6.1 规则算，不人工选）。
3. `crf_field` 落 concept_code；`crf_form_field` 落 role（含 DERIVED 补标）。
4. 新增 seed：`crf_event_rule`（5 条驱动链）、`crf_timepoint_map`（65→43）、`crf_standard_version`（方案/panel/协议版本）。

### 2.3 内置种子清单（bootstrap SQL + JSON）

**保留纪律**：幂等 + 软删 + 版本，`EmbeddedTwinSystemCoreDdlBootstrap` 注册。

| 种子 | 现状 | 改造 |
|---|---|---|
| `nhp-field-dict.json` | 249 字段源 | 加 conceptCode/eventAnchor/frequency/DERIVED |
| `bootstrap-nhp-data.sql` | 码表/编码规则 seed | 加 crf_event_rule + crf_timepoint_map + standard_version seed |
| `bootstrap-nhp-meta.sql` | 元数据 DDL | 加 capture_form/schedule/concept_code 列 |
| 10 个 bootstrap-nhp-*.sql | DDL + seed | 增补新表 DDL |

### 2.4 导入 `NhpImportService`

**现状**：`createBatch(formId + fileFormat + mappingJson)` → `validate` → `execute`（execute 二期返回 501）。

**改造**：
1. `formId` → **事件类型（atom）**：导入不再对着「域表单」，对着「事件类型」。
2. `execute` 落库：事件面板类 → 实体表（crf_sample 等）；序列类 → EAV；台账类 → 子表——不再只写 `crf_record_value`。
3. 补「一致性核查」：导入数据 vs EDC 双轨比对（25 §F）。

## 3. 前端编辑器改造

### 3.1 模板编辑器 `NhpTemplateEditor` → 事件类型编辑器

**现状**：基于 `typeRegistry`（20 题型）+ `SectionTree` 组表单。

**改造**：
1. `typeRegistry` 的 20 题型 **收敛**：装饰类（divider/description/richText）保留给「事件面板里的说明块」；结构化类（table/group/repeatGroup）**被 capture_form 取代**（台账=repeatGroup 的自然形态，序列=SERIES 网格）。
2. 编辑器四区（对应 v6 事件类型详情）：基本信息 / capture_form（推导只读）/ schedule / 字段集（role 标注）+ 下游规则。
3. `TypeMenu` 从「题型网格」→「role + 形态」选择；`FieldEditorPanel` 加 role 标注。

### 3.2 字段编辑器 `NhpFieldPage` → 字段字典 + 概念库

**保留**，加两处：
1. 字段加 `concept_code`（挂概念库，跨域复用肌酐/凝血等）。
2. 字段加 `verdict` + `verdict_note`（校对四态，v7 缺口）。

### 3.3 复合题型模板 `fieldTemplates.ts` → 事件类型种子（升格）

**关键改造**：8 个 `FIELD_TEMPLATES` 里，4 个本质是事件类型：

| 旧复合模板 | 升格为 |
|---|---|
| `followUpSeq` 随访序列 | 随访访视（容器） |
| `medicationRecord` 用药记录 | 给药台账 |
| `perfusionMonitor` 灌注监测 | 灌注序列（SERIES） |
| `donorRecipient` 供受关联 | 供受对（FK 选择器） |

其余（yesNoExpand/dropdownSelect/detailTable/declarationList）保留为「事件面板内的字段组模板」。**即：复合模板从「塞进域表单的字段块」升格为「一等事件类型」**。

### 3.4 连锁关系 `crfTemplate.ts` → role 推导

**现状**：`dictFieldToFormField` 做码表→dictKey、外键→cascade、条件必填→showWhen。

**改造**：改为 `dictFieldToEventTypeField`——加 role 推导（PK 字段→取号器、FK 字段→实体选择器、DERIVED 字段→计算器、其余→VALUE 码表/直填），capture_form 由 frequency/基数/判别列推导。

### 3.5 schema `formTemplate.ts` → 事件类型 schema

**改造**：`FormField` 加 `role`（PK/FK/VALUE/DERIVED）+ `captureForm` + `schedule`；`FormTemplate` 的「sections（域）」降级为「事件类型的字段分组」，不再作为采集侧导航。

## 4. 填写侧改造（NhpFillWorkbench → 时间线工作台）

对应 v3/v5 设计稿，逐组件：
1. `NhpFillWorkbench`：顶栏加「时点/访视选择」，主体三形态分流（序列网格/台账/事件面板），右侧留痕保留。
2. `NhpFillEntryGate`：建实例时加「时点」维度（术前锚/术后 day0 锚）。
3. `NhpFormField`：按 `role` 分发（PK→取号器灰锁、FK→实体选择器、DERIVED→计算只读、VALUE→按 data_type 渲染）。这是**最小、最关键的一刀**——改这一个组件，role 自动化就落地了。

## 5. 实施顺序（改造，非新建）

1. **后端先行**（22 号计划 6 步）：P0 数据质量 → P2 编码 → P1 实体 → 调度 → 事件规则 → P3 去重。
2. **前端第 1 刀**（最小闭环）：`NhpFormField` role 化 + `nhp-field-dict.json` 加 concept/eventAnchor/frequency + `NhpSeedService` 原子重切。验收：填写页里 PK/FK/DERIVED 控件生效。
3. **前端第 2 刀**（配置侧）：`NhpTemplateEditor` → 事件类型编辑器（capture_form/schedule/role）+ 新增 4 配置页。
4. **前端第 3 刀**（采集侧）：`NhpFillWorkbench` → 时间线工作台（三形态 + 时点）。
5. **前端第 4 刀**（治理组）：快照/审计独立成页 + 字段审核 verdict + 数据质量中心。
6. **收尾**：删 hub/StageStepper，移出 subjects/records/entry，路由重排。

> 每刀独立可验收，不推倒重来；旧版「字段字典/码表/编码规则/导入/权限」这些对的部分**全部保留复用**。
