# V2 前端改造实施计划（REDCap 事件模型）

> 状态：实施计划 · 2026-08-22
> 范围：前端重设计 + 最小后端接线（用户已确认）
> 依据：V2-架构总纲.md（五层正交 · 三×三事件模型）

## 一、诊断结论

**后端表/实体/mapper 已建 80%，但接线断裂：**
- 已建：`crf_visit`（事件）/ `crf_visit_plan`（指派矩阵）/ `crf_todo`（待办）/ `crf_event_rule`（规则）/ `crf_subject.lifecycle_stage+arm_code`（状态机）
- 断裂：无 `crf_visit_plan` REST 端点、无待办完成/取消端点、生命周期/arm 无 API 可设置、事件引擎 `onEvent` 未被调用

**前端四处错误设计：**
1. 表单携带调度（`NhpTemplateEditor` 的「采集形态·schedule」面板 `:482-527`）
2. 采集侧客户端启发式 `nhpFillableForms.ts`（event_anchor×frequency 手写映射）
3. SERIES/LEDGER/PANEL 三形态孤儿化（`NhpSeriesGrid`/`NhpLedger` 零引用）
4. 无「表单-事件指派矩阵」UI

## 二、分阶段实施

### Phase 0：拆 V1 调度（纯前端）
- `schema/formTemplate.ts`：删 `CaptureForm` 类型 + `FormTemplate` 的 `eventAnchor`/`frequency`/`captureForm`
- `api/nhpTemplate.api.ts`：删 `NhpTemplateListItem` 的这三列
- `pages/admin/NhpTemplateEditor.tsx`：删 schedule 面板 + 相关 state + 保存 payload
- `components/NhpFillWorkbench.tsx`：删 `templateMeta.captureForm`

### Phase 1：事件定义 + 指派矩阵（配置侧 + 后端）
- 后端：新增 `NhpVisitPlanController`（GET/PUT/DELETE `crf_visit_plan` by visit）+ `NhpVisitService` 补写方法
- 前端：`NhpVisitPage` → 事件定义页（schedule 类型 + 节奏/窗口 + 数据形状）
- 前端：新增 `NhpEventAssignmentPage`（表单-事件指派矩阵，按 arm 分组）
- 路由 + 导航注册

### Phase 2：采集侧事件驱动（前端）
- 删 `nhpFillableForms.ts`
- `NhpFillEntryGate`/`NhpSurgeryFormLauncher`：改读 `listTodoBySubject` + 指派矩阵
- `NhpFillWorkbench`：事件驱动 + 按数据形状派发（PANEL→长表单 / LEDGER→NhpLedger / SERIES→NhpSeriesGrid）
- `NhpSeriesGrid`/`NhpLedger`：补编辑能力 + 接线

### Phase 3：状态机 + 待办闭环（后端引擎）
- subject `lifecycle_stage`/`arm_code` 可设置端点
- `createRecord` 触发展开（接 `NhpEventEngine.onEvent`）
- todo 完成/取消端点 + 采集侧「标记完成」
